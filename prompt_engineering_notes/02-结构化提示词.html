Zero-Shot vs Few-Shot：概念全景

在提示词工程的核心技术谱系中，Zero-Shot（零样本）和Few-Shot（少样本）是两个最基础也最重要的范式。 它们的区别看似简单——「给不给示例」——但背后涉及的是模型如何利用预训练知识 vs 如何从示例中归纳模式这一根本性问题。 理清这个区别，是选择正确提示策略的第一步。

核心定义与对比

维度 Zero-Shot 零样本 Few-Shot 少样本
定义 不提供任何示例，仅靠自然语言指令引导模型完成任务 在指令中提供 1~5 个输入-输出示例对，让模型模仿模式
知识来源 完全依赖模型预训练阶段学到的知识 结合预训练知识 + 从示例中上下文学习（In-Context Learning）
Token 成本 低 — 只有指令本身 较高 — 指令 + 所有示例的 token
输出稳定性 中等 — 依赖指令质量，容易产生格式偏差 高 — 示例约束了输出格式和风格
适用场景 通用任务、常识推理、简单分类、翻译/摘要 特定格式输出、领域分类、复杂推理、风格迁移
典型用法 "将以下中文翻译成英文：{text}" "参考以下示例完成翻译...\n例1: 你好→Hello\n例2: ..."

何时用 Zero-Shot？何时升级到 Few-Shot？

✅ 优先使用 Zero-Shot
文本翻译 · 摘要生成 · 常识问答 · 简单情感分类 · 格式转换 · 通用写作辅助
⚡ 考虑 Few-Shot
特定领域分类 · 非标准 JSON 输出 · 风格化改写 · 复杂多步推理 · 边界情况处理
🔬 进阶：CoT + Few-Shot
数学推理 · 逻辑推演 · 多条件决策 · 需要展示推理链路的场景
💡 经验法则
先试 Zero-Shot → 效果不够再叠加 Few-Shot → 还不够加 CoT
关键认知：In-Context Learning 不是「训练」
Few-Shot 中的示例并不会改变模型的权重参数。它的工作机制是：示例作为额外的上下文信息，帮助模型在当前对话中定位到正确的输出模式。 这就好比考试时给你看了几道例题——你并没有因此变得更聪明，但你更清楚老师期望的答题格式和深度。 因此 Few-Shot 示例的质量和代表性远比数量重要。
02

Zero-Shot Prompting：原理与实战

Zero-Shot 提示的本质是利用大语言模型在预训练阶段习得的广泛知识来完成新任务。 当你给出一个清晰的指令时，模型会在其参数空间中检索与该任务相关的知识模式， 并据此生成输出。这个过程不需要任何针对特定任务的微调或示例演示。

工作原理：从预训练到零样本推理

大语言模型（如 GPT 系列、Claude、Qwen、DeepSeek 等）在海量文本数据上进行自监督预训练。 这些数据天然包含了各种任务的隐式模式：

  • 翻译模式：「Hello」经常与「你好」共现 → 学会双语映射
  • 摘要模式：长文章后常跟着简短总结 → 学会信息压缩
  • 分类模式：「太棒了！」常被标记为正面 → 学会情感判断
  • 问答模式：问题后紧跟答案 → 学会问题-答案关联

实战：用 OpenAI 兼容 API 调用 Zero-Shot

下面是一个可直接运行的完整代码示例，使用 Qwen 或 DeepSeek 的 API：

Python — Zero-Shot 完整调用示例 
from openai import OpenAI

# 初始化客户端（兼容 OpenAI API 格式的服务均可）
# 支持：Qwen / DeepSeek / OpenAI / 本地 Ollama 等
client = OpenAI(
    api_key="your-api-key",
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1"  # Qwen
)

# ===== Zero-Shot Prompt 定义 =====
zero_shot_prompt = """请判断以下用户评价的情感倾向。

评价文本：
"{review_text}"

请从以下三个选项中选择最匹配的一个：
A. 正面（Positive）
B. 负面（Negative）
C. 中性（Neutral）

只输出选项字母和对应标签，不要额外解释。"""

# ===== 调用 API =====
response = client.chat.completions.create(
    model="qwen-plus",          # 或 "deepseek-chat", "gpt-4o-mini" 等
    messages=[
        {"role": "system", "content": "你是一个专业的情感分析助手。"},
        {"role": "user",   "content": zero_shot_prompt.format(
            review_text="这个产品太棒了！物流很快，包装也很用心，完全超出我的预期！"
        )}
    ],
    temperature=0.3,              # 低温度 = 更确定性的输出
    max_tokens=100
)

# 解析结果
result = response.choices[0].message.content
print(f"模型输出: {result}")
# 典型输出: A. 正面（Positive）

Zero-Shot 的关键优化技巧

技巧清单：提升 Zero-Shot 成功率的 6 个要点
  • 明确选项范围：不要说「判断情感」，而是列出具体选项（正面/负面/中性），减少自由发挥空间
  • 约束输出格式：「只输出 A/B/C 和标签」比「请分析」能得到更稳定、可解析的结果
  • 设定 System Role：system message 设定角色（如"你是专业分析师"）能激活特定领域的知识子空间
  • 控制 Temperature：分类任务用 0~0.3，创意写作用 0.7~1.0，根据任务类型调整
  • 使用结构化标记：用 ## 标题、### 子标题、- 列表等 Markdown 结构组织 prompt，提升模型理解力
  • 添加负面约束：「不要输出解释」「不要编造信息」比只说正面要求更有效

步骤 优化动作 解决的问题 效果提升

优化的本质
提示词优化的本质就是持续减少模型的「自由发挥空间」。 差的 prompt 让模型自己决定一切：输出什么格式？包含哪些字段？用什么语气？ 好的 prompt 把这些决策权全部收回——你告诉模型 exactly 要什么， 模型只需要专注于「如何最好地完成这个明确的任务」。每增加一个有效约束，就减少一个不确定性来源。 但注意：过度约束也会限制模型的能力，需要在灵活性和可控性之间找到平衡点。

提示词模板基础：Python 原生方案

当你的提示词需要在多个场景下复用时，模板化（Templating）就变得至关重要。 模板的核心思想是将提示词中的固定部分与可变部分分离—— 固定部分（指令、约束、格式定义）写一次，可变部分（用户输入、动态参数）运行时填入。 这是提示词工程从「一次性对话」进化到「生产级应用」的关键一步。

为什么需要模板化？

🔄 复用性
同一套逻辑适配不同输入，避免重复编写相似 prompt
📦 可维护性
修改模板一处即可全局生效，无需逐个调整
⚡ 一致性
所有调用共享相同指令结构和约束条件
🔧 可组合性
子模板可拼接成复杂 Pipeline，支持模块化管理

方案一：str.format() —— 最基础的模板方式

Python — str.format() 模板 
# ========== 定义模板（使用 {variable} 占位符）==========
review_template = """
## 角色
你是一名{role}，擅长{expertise_domain}。

## 任务
对以下产品评价进行情感分析和关键信息提取。

## 待分析文本
"{review_text}"

## 输出要求
请严格按照 JSON 格式返回，包含以下字段：
sentiment, confidence, positive_factors, negative_factors,
neutral_factors, purchase_intent, one_line_summary

只输出 JSON，不要其他内容。
"""

# ========== 使用时填充变量 ==========
prompt_1 = review_template.format(
    role="电商数据分析师",
    expertise_domain="用户行为分析与情感计算",
    review_text="太棒了！物流超快，包装精美，五星好评！"
)

prompt_2 = review_template.format(
    role="电商数据分析师",
    expertise_domain="用户行为分析与情感计算",
    review_text="质量太差了，用了两天就坏，退款！"
)

print(prompt_1)
# → 两份 prompt 共享相同的指令结构和约束，只有 review_text 不同

方案二：Partial 预填充 —— 减少运行时变量

当模板中有大量变量，但其中很多是固定不变的（如角色、格式要求等）， 可以先用 format() 填充固定变量，生成一个「半成品」模板， 后续每次只需传入真正变化的变量。

Python — Partial 预填充模式 
# ========== 第一步：定义全量模板 ==========
full_template = """
## 角色
你是一名{role}，擅长{expertise_domain}。

## 任务
对以下{content_type}进行{task_type}。

## 待处理内容
{content}

## 输出要求
- 语言：{language}
- 格式：{output_format}
- 长度限制：{max_length}
"""

# ========== 第二步：预填充固定变量（生成半成品模板）==========
# 角色和格式是固定的，只有 content 是每次调用都不同的
analyst_template = full_template.format(
    role="金融分析师",
    expertise_domain="市场分析、财务建模、风险评估",
    content_type="财经新闻文本",
    task_type="多维度分类标注",
    language="中文",
    output_format="JSON",
    max_length="不超过200字",
    content="{content}"     # ← 保留占位符，稍后填入
)

# ========== 第三步：运行时只需传入变化的部分 ==========
news_1 = analyst_template.format(content="央行今日宣布降准0.5个百分点，释放长期资金约1万亿元")
news_2 = analyst_template.format(content="某科技巨头Q3营收同比增长35%，超市场预期")

# 优势：业务代码只需关心 content 参数，其余配置集中管理
Partial 模式的价值
Partial 预填充实现了「配置与数据的分离」。 固定不变的配置（角色、格式、约束）在系统初始化时一次性填入， 变化的数据（用户输入、待处理文本）在每次请求时动态注入。 这种模式在批量处理场景下尤为强大——比如你需要分析 1000 条评论， 只需构造一次半成品模板，然后循环填入不同评论即可。
05

LangChain 模板体系：PromptTemplate & ChatPromptTemplate

当项目规模增长到需要管理大量提示词时，纯 Python 字符串模板就开始显得力不从心了。 LangChain 提供了一套成熟的提示词模板体系——PromptTemplate 用于单轮补全式提示， ChatPromptTemplate 用于多轮对话式提示。它们不仅支持变量管理， 还提供了三种变量注入方式、partial_variables 动态绑定、 以及与 LLM Chain 的无缝集成能力。

5.1 PromptTemplate：单轮补全式模板

PromptTemplate 是最基础的模板类，适用于将整个 prompt 作为一个整体发送给模型的场景（类似 GPT-3 的 text completion 接口）：

LangChain — PromptTemplate 基础用法 
from langchain_core.prompts import PromptTemplate

# ========== 方式一：from_template（推荐）==========
template = """
请对以下产品评价进行情感分析：

评价内容：{review_text}

请判断情感倾向（正面/负面/中性），并给出置信度。
只输出结果，不要解释。
"""

prompt_template = PromptTemplate.from_template(template)

# 查看模板中的变量名
print(prompt_template.input_variables)
# 输出: ['review_text']

# ========== 方式二：format 注入（最常用）==========
prompt = prompt_template.format(review_text="这个产品太棒了，超出预期！")
print(prompt)
# → 生成的完整 prompt 文本

# ========== 方式三：partial 预填充（返回新模板对象）==========
# 预填充部分变量，得到一个只需要剩余变量的新模板
partial_tmpl = prompt_template.partial(review_text="默认评论文本")
# partial_tmpl 现在是一个不需要任何变量的「已完成」模板

5.2 ChatPromptTemplate：多轮对话式模板

现代 LLM API（OpenAI Chat Completions、Qwen、DeepSeek 等）都是基于消息列表的多轮对话接口。 ChatPromptTemplate 专为这种场景设计，它管理一组 System / User / Assistant 消息模板， 每条消息都可以包含独立的变量。

LangChain — ChatPromptTemplate.from_messages 
from langchain_core.prompts import ChatPromptTemplate

# ========== 定义多轮对话模板 ==========
chat_template = ChatPromptTemplate.from_messages([
    ("system", "你是一名{role}，擅长{expertise}。请始终以专业的态度回答问题。"),
    ("user",  "请分析以下评价：\n{review_text}"),
])

# ========== format_messages：生成消息列表（直接传给 API）==========
messages = chat_template.format_messages(
    role="电商数据分析师",
    expertise="用户情感分析与行为洞察",
    review_text="物流很快，但产品质量一般般"
)

# messages 是一个 [SystemMessage, UserMessage] 列表
print(messages[0].content)
# → "你是一名电商数据分析师，擅长用户情感分析与行为洞察。请始终以专业的态度回答问题。"

print(messages[1].content)  
# → "请分析以下评价：\n物流很快，但产品质量一般般"

# ========== 直接传给 LLM（无缝集成）==========

5.3 三种变量注入方式对比

LangChain 模板体系提供了三种变量注入机制，各有适用场景：

方式 方法名 返回值 适用场景 特点
format .format(**kwargs) str (字符串) 需要获取完整 prompt 文本 最常用，一次性填入所有变量
format_messages .format_messages(**kwargs) List[Message] 直接传给 ChatModel ChatPromptTemplate 专用，返回消息对象列表
partial / partial_variables .partial() / 构造参数 新 Template 对象 预填充固定变量 返回新模板，剩余变量延后填入

5.4 partial_variables：动态变量的高级用法

partial_variables 是 partial() 的进阶版——它允许你传入一个可调用对象（函数）， 每次格式化时动态执行该函数来获取变量值。这在需要动态生成时间戳、加载外部配置等场景下非常有用。

LangChain — partial_variables 动态绑定 
from datetime import datetime
from langchain_core.prompts import PromptTemplate, ChatPromptTemplate

# ========== 定义动态变量函数 ==========
def get_current_time():
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

def load_system_config():
    # 可从数据库、配置文件、环境变量等动态加载
    return {
        "version": "v2.1",
        "rules": "严格遵循JSON格式，不输出markdown标记"
    }

# ========== PromptTemplate + partial_variables ==========
template = PromptTemplate.from_template(
    """
当前时间：{current_time}
系统配置：{system_config}

请分析以下内容：{content}
"""
)

# 绑定动态变量（函数会在每次 format 时自动调用）
partial_tmpl = template.partial(
    current_time=get_current_time,      # 传入函数引用
    system_config=load_system_config     # 传入函数引用
)

# 每次 format 时，动态函数会重新执行
prompt_1 = partial_tmpl.format(content="第一条评论")   # 时间: 2026-05-15 10:30:00
import time; time.sleep(2)
prompt_2 = partial_tmpl.format(content="第二条评论")   # 时间: 2026-05-15 10:30:02（自动更新！）

# ========== ChatPromptTemplate + partial_variables ==========
chat_tmpl = ChatPromptTemplate.from_messages([
    ("system", "分析时间：{current_time}\n规则：{rules}"),
    ("user", "请分析：{content}"),
])

# 通过构造参数绑定 partial_variables
chat_with_partial = chat_tmpl.partial(
    current_time=get_current_time,
    rules=lambda: load_system_config()["rules"]
)

messages = chat_with_partial.format_messages(content="测试评论")
# SystemMessage 中自动包含最新的时间和规则
选择建议：什么时候用什么？
  • 简单脚本 / 快速原型：直接用 Python f-string 或 str.format()，零依赖，足够用
  • 单轮补全场景：用 PromptTemplate.from_template() + .format()
  • 多轮对话 / Chat API 场景：用 ChatPromptTemplate.from_messages() + .format_messages()
  • 批量处理 / Pipeline：用 .partial() 或 partial_variables 预填充固定配置
  • 需要动态变量（时间、外部配置）：用 partial_variables 绑定函数，实现懒求值

本集小结 & 实践 Checklist

核心知识地图

Zero-Shot 核心
不提供示例，仅靠自然语言指令引导模型完成任务，依赖预训练知识
vs Few-Shot
Few-Shot 利用 In-Context Learning 从示例中归纳模式，输出更稳定但 Token 成本更高
优化方法论
角色设定 → 明确任务 → 格式约束 → 负面约束 → 验证迭代（五步法）
模板化三要素
固定/可变分离 · Partial 预填充 · 变量注入（format/partial/partial_variables）
LangChain 模板栈
PromptTemplate（单轮）· ChatPromptTemplate（多轮）· from_template / from_messages
优化本质
每增加一个有效约束 = 减少一个不确定性来源 = 提升输出稳定性

实践 Checklist

Zero-Shot + 模板化 自检清单
  • [ ]  Zero-Shot 检查：指令是否列出了明确的选项范围？（而非开放式提问）
  • [ ]  格式约束检查：输出是否有明确格式要求？（JSON Schema / 表格 / 固定字段）
  • [ ]  负面约束检查：是否使用了「不要...」类型的约束来消除不想要的输出？
  • [ ]  A/B 测试验证：是否对比过 Bad vs Good prompt 的实际输出差异？
  • [ ]  模板化检查：重复使用的 prompt 是否已模板化？（使用 {variable} 占位符）
  • [ ]  Partial 使用：固定配置是否通过 Partial 预填充来减少运行时变量数量？
  • [ ]  LangChain 选型：是否根据场景正确选择了 PromptTemplate 还是 ChatPromptTemplate？
