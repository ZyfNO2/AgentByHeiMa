语义匹配：从关键词到语义理解

在传统的文本搜索中，我们依赖关键词匹配（Keyword Matching）—— 用户输入「苹果」，系统查找包含「苹果」的文档。但这种方式有致命缺陷： 「苹果公司」和「吃苹果」在关键词层面高度重叠，语义上却天差地别。

语义匹配（Semantic Matching）的核心思想是：将文本映射到一个 高维向量空间（Embedding Space）中，使得语义相近的文本在空间中距离更近。 这不是魔法——它是基于深度学习的分布式表示理论（Distributed Representation）， 由 Hinton 等人在 1986 年提出、Word2Vec（2013）首次大规模验证、Transformer（2017） 将其推向新高度的技术范式转移。

语义匹配的核心 Pipeline

  • 文本编码（Text → Embedding）：通过 Embedding 模型将变长文本转换为固定维度的稠密向量（通常 384/768/1024/1536 维）
  • 相似度计算（Vector Similarity）：使用余弦相似度（Cosine Similarity）、欧氏距离或点积度量两个向量的接近程度
  • 排序与检索（Ranking & Retrieval）：按相似度降序排列候选集，返回 Top-K 最相关结果
  • 后处理过滤（Post-filtering）：结合业务规则对结果进行二次筛选和重排

为什么余弦相似度？

在 Embedding 空间中衡量两个向量的相似性，余弦相似度（Cosine Similarity） 是最广泛采用的度量方式。其数学定义为两个向量夹角的余弦值：

Math / 余弦相似度定义 
/* 余弦相似度公式 */
              A · B          Σ(Aᵢ × Bᵢ)
cos(A, B) = ────── = ─────────────────
           ‖A‖ × ‖B‖   √ΣAᵢ² × √ΣBᵢ²

/* 取值范围: [-1, 1] */
/*  1  = 完全同向 (语义相同)
 *  0  = 正交无关 (语义无关)
 * -1  = 完全反向 (语义相反) */
为什么不用欧氏距离？
欧氏距离衡量的是向量的绝对位置差异，而余弦相似度关注的是方向一致性。 在 NLP 场景中，两段文本的 Embedding 向量长度可能因文本长度不同而差异很大， 但它们描述同一件事时方向应当一致。余弦相似度天然归一化了向量长度的影响， 因此更适合语义匹配场景。当然，如果 Embedding 模型已经做了 L2 归一化， 余弦相似度就等价于点积（Dot Product），计算效率更高。

Python 实现：从零手写余弦相似度

Python / 余弦相似度三种实现方式对比 
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity
import torch
import torch.nn.functional as F

# ═══ 方式一：纯 NumPy 手写实现 ═══
def cosine_sim_numpy(vec_a: np.ndarray, vec_b: np.ndarray) -> float:
    """手动计算余弦相似度，适合理解原理"""
    dot_product = np.dot(vec_a, vec_b)
    norm_a = np.linalg.norm(vec_a)
    norm_b = np.linalg.norm(vec_b)
    return dot_product / (norm_a * norm_b)

# ═══ 方式二：scikit-learn（推荐用于小规模数据）═══
def cosine_sim_sklearn(matrix_a: np.ndarray, matrix_b: np.ndarray) -> np.ndarray:
    """批量计算两矩阵间所有向量对的余弦相似度"""
    return cosine_similarity(matrix_a, matrix_b)

# ═══ 方式三：PyTorch（推荐用于 GPU 加速的大规模场景）═══
def cosine_sim_pytorch(vec_a: torch.Tensor, vec_b: torch.Tensor) -> torch.Tensor:
    """GPU 加速的余弦相似度，支持 batch 运算"""
    return F.cosine_similarity(vec_a.unsqueeze(0), vec_b.unsqueeze(0))

# ─── 使用示例 ───
vec1 = np.array([0.3, 0.5, 0.2, 0.8, 0.1])
vec2 = np.array([0.28, 0.52, 0.22, 0.78, 0.12])

print(f"余弦相似度: {cosine_sim_numpy(vec1, vec2):.4f}")
# 输出: 余弦相似度: 0.9987 （非常接近，说明语义高度一致）

BGE（Beijing Academy of Artificial Intelligence General Embedding） 是由北京智源人工智能研究院（BAAI）开发的系列 Embedding 模型， 其中 BGE-Large-Zh-v1.5 在 C-MTEB（Chinese Massive Text Embedding Benchmark） 中文榜单上长期霸榜第一。它有几个关键特性使其成为中文场景的首选：

🎯 Instruction-Aware
支持指令前缀，可为不同任务定制编码行为
⚡ Matryoshka Representation
支持动态截断维度，灵活平衡精度与存储成本
📥 完全开源
Apache 2.0 协议，可本地部署无 API 费用
📈 1024 维输出
在精度和效率之间取得良好平衡

# ══════════════════════════════════════════════
# 方式一：OpenAI text-embedding-3-large (API)
# ══════════════════════════════════════════════
from openai import OpenAI

client = OpenAI()

def embed_openai(text: str) -> list[float]:
    """调用 OpenAI Embedding API，返回 3072 维向量"""
    response = client.embeddings.create(
        model="text-embedding-3-large",
        input=text,
        dimensions=1024  # 可选：缩短维度以节省存储
    )
    return response.data[0].embedding


# ══════════════════════════════════════════════
# 方式二：BGE-Large-Zh-v1.5 (本地部署，推荐！)
# ══════════════════════════════════════════════
from sentence_transformers import SentenceTransformer

# 首次运行会自动下载模型 (~1.2GB)
bge_model = SentenceTransformer("BAAI/bge-large-zh-v1.5")

def embed_bge(texts: list[str]) -> np.ndarray:
    """
    BGE 编码函数，支持批量输入
    关键特性：Instruction-aware 前缀
    """
    instruction = "为这个句子生成表示以用于检索相关文章："
    texts_with_instruction = [instruction + text for text in texts]
    embeddings = bge_model.encode(
        texts_with_instruction,
        normalize_embeddings=True  # L2归一化，后续可用点积代替余弦
    )
    return embeddings

端到端实现：从查询到结果

Python / 金融文本语义匹配完整实现 
import numpy as np
from typing import list, TypedDict
from dataclasses import dataclass
from sentence_transformers import SentenceTransformer

# ════════════════════════════════════════
# Step 1: 加载 Embedding 模型
# ════════════════════════════════════════
model = SentenceTransformer("BAAI/bge-large-zh-v1.5")


@dataclass
class MatchResult:
    """匹配结果的数据结构"""
    doc_id: str
    title: str
    score: float       # 相似度分数 [0, 1]
    content_preview: str


class FinancialSemanticMatcher:
    """
    金融文本语义匹配引擎
    
    核心能力:
    - 文本向量化 (BGE Embedding)
    - 余弦相似度批量计算
    - Top-K 检索与排序
    - 结果后处理与格式化
    """
    
    def __init__(self, model_name: str = "BAAI/bge-large-zh-v1.5"):
        self.model = SentenceTransformer(model_name)
        self.doc_embeddings = None   # 文档向量矩阵
        self.doc_metadata = []      # 文档元数据
    
    def build_index(self, documents: list[dict]):
        """
        构建文档索引（离线阶段）
        
        Args:
            documents: [{"id": str, "title": str, "content": str}, ...]
        """
        texts = [doc["content"] for doc in documents]
        self.doc_metadata = documents
        
        # 批量编码所有文档
        self.doc_embeddings = self.model.encode(
            texts,
            normalize_embeddings=True,
            show_progress_bar=True,
            batch_size=32
        )
        print(f"[索引构建完成] 共 {len(documents)} 篇文档，"
              f"向量维度: {self.doc_embeddings.shape[1]}")
    
    def search(self, query: str, top_k: int = 5,
               threshold: float = 0.5) -> list[MatchResult]:
        """
        语义搜索主方法
        
        Args:
            query: 用户查询文本
            top_k: 返回前 K 条结果
            threshold: 最低相似度阈值（低于此值的结果被过滤）
        
        Returns:
            按相似度降序排列的 MatchResult 列表
        """
        # 1. 编码查询
        query_embedding = self.model.encode(
            ["为这个句子生成表示以用于检索相关文章：" + query],
            normalize_embeddings=True
        )[0]
        
        # 2. 计算与所有文档的相似度（矩阵运算，极快）
        scores = np.dot(self.doc_embeddings, query_embedding)
        
        # 3. Top-K 排序
        top_indices = np.argsort(scores)[::-1][:top_k]
        
        // 4. 组装结果
        results = []
        for idx in top_indices:
            if scores[idx] >= threshold:
                doc = self.doc_metadata[idx]
                results.append(MatchResult(
                    doc_id=doc["id"],
                    title=doc["title"],
                    score=float(scores[idx]),
                    content_preview=doc["content"][:100] + "..."
                ))
        
        return results


# ════════════════════════════════════════
# 实际使用示例
# ════════════════════════════════════════
matcher = FinancialSemanticMatcher()

# 模拟金融文档库
fin_docs = [
    {"id": "doc_001", "title": "贵州茅台2024Q1营收387.56亿，同比增长18%",
     "content": "贵州茅台发布2024年一季报，实现营业收入387.56亿元..."},
    {"id": "doc_002", "title": "央行宣布下调存款准备金率0.5个百分点",
     "content": "中国人民银行决定于2024年X月X日下调金融机构..."},
    {"id": "doc_003", "title": "宁德时代发布神行超充电池，充电10分钟续航400公里",
     "content": "宁德时代正式发布全新一代磷酸铁锂电池产品..."},
    {"id": "doc_004", "title": "茅台一季度收入创历史新高，直销渠道占比近46%",
     "content": "贵州茅台2024年第一季度财报显示，直销渠道销售收入..."},
]

# 构建索引
matcher.build_index(fin_docs)

# 执行搜索
results = matcher.search(
    query="茅台今年第一季度的业绩怎么样？",
    top_k=3
)

# 输出结果
for r in results:
    print(f"[{r.score:.3f}] {r.title}")
# 输出示例:
# [0.892] 贵州茅台2024Q1营收387.56亿，同比增长18%
# [0.876] 茅台一季度收入创历史新高，直销渠道占比近46%

FAISS：Facebook 的高性能向量检索引擎

当文档数量从几十篇增长到十万、百万甚至亿级时， 前面的「暴力穷举法」（计算查询向量与每个文档向量的相似度）将变得不可接受—— O(N) 的线性扫描时间复杂度意味着 100 万篇文档需要进行 100 万次点积运算。

FAISS（Facebook AI Similarity Search） 是 Meta（原 Facebook） 开源的向量相似度搜索库，它通过近似最近邻（ANN, Approximate Nearest Neighbor） 算法将检索复杂度从 O(N) 降低到 O(log N)，同时保持极高的召回率（通常 > 95%）。 它是目前工业界使用最广泛的向量检索引擎之一，也是 LangChain 的默认向量存储后端之一。

FAISS 核心概念速览

概念 说明 类比
Index（索引） 组织向量数据的结构，决定了检索算法 数据库中的 B-tree 索引
IndexFlatL2 暴力搜索（精确），基准测试用 没有索引的全表扫描
IndexIVFFlat 基于聚类的倒排索引，速度/精度平衡的首选 先按区域缩小范围再精确搜索
nprobe IVF 索引的探测聚类数，越大越准但越慢 搜索时检查多少个「候选桶」
nlist IVF 索引的聚类数量，影响索引构建质量 把数据分成多少个「桶」

FAISS 实战：从零搭建向量数据库

Python / FAISS 向量检索完整流程 
import faiss
import numpy as np
import pickle
from sentence_transformers import SentenceTransformer

# ══════════════════════════════════════════════
# Phase 1: 准备数据 & 编码
# ══════════════════════════════════════════════
model = SentenceTransformer("BAAI/bge-large-zh-v1.5")

documents = [
    {"id": 1, "text": "贵州茅台2024年一季度营收387.56亿元"},
    {"id": 2, "text": "央行下调存款准备金率释放长期资金约1万亿元"},
    {"id": 3, "text": "比亚迪海豹车型月销量突破3万辆"},
    # ... 更多文档
]

# 批量编码为向量矩阵 shape=(N, 1024)
texts = [d["text"] for d in documents]
embeddings = model.encode(texts, normalize_embeddings=True)
embeddings = embeddings.astype(np.float32)


# ══════════════════════════════════════════════
# Phase 2: 构建 FAISS 索引
# ══════════════════════════════════════════════
dimension = embeddings.shape[1]  # 1024 for BGE-Large-Zh
n_total = embeddings.shape[0]     # 文档总数

# === 选择合适的索引类型 ===

# 方案A: IndexFlatL2 (暴力搜索，< 1万条文档时够用)
# index = faiss.IndexFlatL2(dimension)

# 方案B: IndexIVFFlat (推荐！适合 1万~1000万条文档)
nlist = int(np.sqrt(n_total))  # 聚类数 ≈ √N
quantizer = faiss.IndexFlatIP(dimension)  # 内积量化器（因为已做L2归一化）
index = faiss.IndexIVFFlat(quantizer, dimension, nlist, faiss.METRIC_INNER_PRODUCT)

# 训练索引（必须先训练再添加！）
if not index.is_trained:
    index.train(embeddings)

# 添加向量到索引
index.add(embeddings)
print(f"FAISS 索引构建完成: {index.ntotal} 个向量")


# ══════════════════════════════════════════════
# Phase 3: 执行向量检索
# ══════════════════════════════════════════════
query_text = "茅台今年赚了多少钱？"
query_vec = model.encode(
    ["为这个句子生成表示以用于检索相关文章：" + query_text],
    normalize_embeddings=True
).astype(np.float32)

# 设置探测数（nprobe 越大越准确但越慢）
index.nprobe = min(nlist, 10)

# 搜索 Top-3
k = 3
scores, indices = index.search(query_vec, k)

# 解析结果
print(f"\n查询: {query_text}")
print("─" * 50)
for rank, (idx, score) in enumerate(zip(indices[0], scores[0]), 1):
    doc = documents[idx]
    print(f"#{rank} [{score:.4f}] {doc['text']}")


# ══════════════════════════════════════════════
# Phase 4: 持久化保存 & 加载
# ══════════════════════════════════════════════
faiss.write_index(index, "financial_docs.index")
print("\n索引已保存到 financial_docs.index")

# 下次使用时直接加载，无需重新构建
loaded_index = faiss.read_index("financial_docs.index")
print(f"加载成功: {loaded_index.ntotal} 个向量")
FAISS 常见坑点
⚠ IVF 索引必须先 train 再 add！未训练直接 add 会抛异常或产生错误结果。

⚠ nprobe 的选择是精度 vs 速度的核心权衡参数。一般设为 nlist 的 5%~20%， 生产环境中建议通过 A/B 测试确定最优值。

⚠ 数据类型必须是 float32。FAISS 不支持 float64，numpy 数组必须显式转换。

⚠ 已 L2 归一化的向量应使用 Inner Product 而非 L2 距离。 此时内积等价于余弦相似度，且 FAISS 对 IP 有更多优化。

中国A股市场研究。你擅长从碎片化的财经信息中提炼投资洞见。

## 你的工作模式
你将收到一个**用户查询**和一组**由语义检索系统找到的相关文档**。
你需要基于这些文档（仅基于这些文档），运用专业分析能力回答用户问题。

## 分析框架（Chain-of-Thought）

### Step 1: 信息提取
从每篇参考文档中提取：
- 核心事实（数字、日期、主体）
- 关键观点/结论
- 信息来源的可信度评估

### Step 2: 交叉验证
- 不同文档之间的信息是否一致？
- 是否存在矛盾或互补？
- 哪些信息是最新的/权威的？

### Step 3: 综合推理
- 将分散的信息整合成连贯的分析
- 给出明确的结论（避免模棱两可）
- 标注置信度和风险提示

### Step 4: 结构化输出
按指定 JSON 格式输出最终答案。

## 重要约束
- **只使用提供的参考文档**，不得编造信息
- 如果参考文档不足以回答问题，明确说明
- 所有数字引用必须注明出处（文档编号）
- 保持客观中立的投资分析立场

{format_instructions}
"""

完整 Pipeline 代码

Python / 金融 RAG 系统完整 Pipeline 
import faiss
import numpy as np
from pydantic import BaseModel, Field
from typing import Optional, list, Literal
from sentence_transformers import SentenceTransformer
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import PydanticOutputParser
from langchain_openai import ChatOpenAI


# ════════════════════════════════════════
# Pydantic Schema: RAG 分析结果
# ════════════════════════════════════════
class SourceReference(BaseModel):
    """单条参考来源"""
    doc_id: str
    title: str
    relevance_score: float = Field(description="语义相关性评分")
    key_facts: list[str] = Field(description="从中提取的关键事实")

class FinancialAnalysisResult(BaseModel):
    """
    金融 RAG 分析的最终输出
    融合了 P01-P06 全部技术的结晶！
    """
    answer: str = Field(description="对用户问题的专业分析回答")
    confidence: float = Field(ge=0.0, le=1.0, description="回答置信度")
    sources: list[SourceReference] = Field(description="参考来源列表")
    risk_warning: Optional[str] = Field(None, description="必要的风险提示")
    suggested_follow_up: list[str] = Field(description="建议的后续追问")


# ════════════════════════════════════════
# FinancialRAGSystem: 终极系统
# ════════════════════════════════════════
class FinancialRAGSystem:
    """
    金融领域 RAG 系统 —— 融合全部 6 集技术
    
    Architecture:
    User Query → Embedding → FAISS Retrieval → Context Assembly
              → CoT Reasoning (LLM) → Pydantic Output
    """
    
    def __init__(self):
        # --- P06: Embedding 模型 ---
        self.encoder = SentenceTransformer("BAAI/bge-large-zh-v1.5")
        
        # --- P06: FAISS 向量索引 ---
        self.faiss_index = None
        self.documents = []
        
        # --- P04/P05: LLM + Parser ---
        self.llm = ChatOpenAI(model="gpt-4o", temperature=0)
        self.parser = PydanticOutputParser(pydantic_object=FinancialAnalysisResult)
        
        # --- P01/P03: Prompt Template ---
        self.prompt = ChatPromptTemplate.from_messages([
            ("system", FINANCIAL_RAG_SYSTEM_PROMPT.format(
                format_instructions=self.parser.get_format_instructions()
            )),
            ("human", """## 用户查询
{query}

## 参考文档（由语义检索系统提供）
{retrieved_context}
""")
        ])
        
        # 组装 Chain
        self.chain = self.prompt | self.llm | self.parser
    
    def add_documents(self, docs: list[dict]):
        """添加文档并构建 FAISS 索引"""
        self.documents = docs
        texts = [d["content"] for d in docs]
        
        # Embedding 编码
        embeddings = self.encoder.encode(
            texts, normalize_embeddings=True
        ).astype(np.float32)
        
        # 构建 FAISS IVF 索引
        dim = embeddings.shape[1]
        nlist = max(int(np.sqrt(len(docs))), 4)
        quantizer = faiss.IndexFlatIP(dim)
        self.faiss_index = faiss.IndexIVFFlat(quantizer, dim, nlist, 
                                               faiss.METRIC_INNER_PRODUCT)
        self.faiss_index.train(embeddings)
        self.faiss_index.add(embeddings)
        self.faiss_index.nprobe = min(nlist, 10)
    
    def query(self, user_query: str, top_k: int = 3) -> FinancialAnalysisResult:
        """
        完整的 RAG 查询流程
        
        这是全部 6 集技术的集大成调用！
        """
        # ===== Phase 1: 语义检索 (P06) =====
        q_vec = self.encoder.encode(
            ["为这个句子生成表示以用于检索相关文章：" + user_query],
            normalize_embeddings=True
        ).astype(np.float32)
        
        scores, indices = self.faiss_index.search(q_vec, top_k)
        
        # ===== Phase 2: 上下文组装 =====
        context_parts = []
        for rank, idx in enumerate(indices[0]):
            doc = self.documents[idx]
            context_parts.append(
                f"### 文档 {rank+1} (相关度: {scores[0][rank]:.3f})\n"
                f"**标题**: {doc['title']}\n"
                f"**内容**: {doc['content']}\n"
            )
        retrieved_context = "\n\n".join(context_parts)
        
        # ===== Phase 3: CoT 推理 + 结构化输出 (P03+P04+P05) =====
        result: FinancialAnalysisResult = self.chain.invoke({
            "query": user_query,
            "retrieved_context": retrieved_context
        })
        
        return result

这个系统的精髓在于「分层解耦」的设计哲学。

检索层（FAISS+BGE）负责「找对文档」——利用向量语义匹配从百万级语料中快速定位相关内容；

输出层（Pydantic）负责「规范交付」——强类型保证下游系统可以直接消费。

每一层都可以独立替换和优化——换一个 Embedding 模型不需要改动推理层的任何代码。 这就是工程化思维在 AI 系统设计中的最佳实践。
