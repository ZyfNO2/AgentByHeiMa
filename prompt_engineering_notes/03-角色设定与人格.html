Role Playing 角色扮演：原理与机制

Role Playing（角色扮演）是提示词工程中最核心也最有效的技巧之一。 它的核心理念非常直观——通过在 System Prompt 中为模型指定一个明确的「身份」或「角色」， 引导模型激活与该角色相关的知识子空间，从而在特定领域内输出更专业、更准确、更符合预期的内容。

为什么角色设定能提升输出质量？

从技术角度来看，角色设定的效果可以从以下几个层面解释：

🧠 知识子空间激活
大模型预训练阶段接触过海量各领域文本。角色指令相当于一个检索锚点，让模型的注意力机制优先聚焦于金融/医疗/法律等特定领域的 token 分布和语义模式
🎯 输出风格约束
不同角色的语言风格差异巨大。「资深金融分析师」的输出会自然使用专业术语、严谨的数据分析语气；而「科普博主」则会用更通俗的表达方式
📐 推理框架引导
角色设定隐含了思维模式的约束。例如「金融分析师」会自动采用「数据→分析→结论」的推理路径，而非漫无边际的自由联想
⚡ 上下文窗口优化
好的角色设定相当于在上下文窗口中预先填充了高质量的领域先验，减少模型需要从零开始「摸索」任务要求的 token 开销

本天才的核心洞察
角色设定的本质是「注意力重定向」——它不改变模型的参数， 而是通过精心设计的上下文信号，让模型在推理时优先调用与目标领域相关的知识和推理模式。 一个设计精良的角色 Prompt 可以让基础模型的输出效果媲美经过简单微调的领域专用模型， 这就是为什么提示词工程被称为「无需训练的模型能力增强术」~

四分类体系的详细定义

与通用的宏观/行业/市场/政策四分法不同，本课程采用的是更贴近实际业务场景的分类体系： 新闻报道、公司公告、财务报告、分析师报告。 这四个类别对应着金融信息生产链条上的不同环节和不同的写作主体：

类别 英文标识 发布主体 典型特征 区分关键词
新闻报道 News Report 媒体/记者 第三人称叙述、引用多方观点、时效性强、标题吸引眼球 据XX报道、今日、近日、市场人士认为、消息显示
公司公告 Company Announcement 上市公司/企业 第一人称或官方口吻、格式规范（董事会决议/股东大会）、法律效力 本公司、董事会、股东大会、特此公告、关于、通知
财务公告 Financial Report 公司/审计机构 密集的数值数据（营收/利润/资产负债表指标）、定期披露 营业收入、净利润、同比增长、EPS、ROE、资产负债率
分析师报告 Analyst Report 券商研究所/分析师 投资评级（买入/持有/卖出）、目标价、估值模型、行业深度分析 维持评级、目标价、PE估值、DCF模型、投资建议、盈利预测

分类难点与边界情况

实际业务中，这四个类别之间并非总是泾渭分明。以下是常见的边界模糊场景及处理策略：

  • 公司公告 vs 财务公告：两者发布主体相同，关键区别在于内容重心。如果文本以定性描述为主（如人事变动、股权激励方案），归入公司公告；如果以定量财务数据为核心（如年报摘要、季度业绩快报），归入财务公告。
  • 新闻报道 vs 分析师报告：新闻是客观报道（即使包含分析师引语），而分析师报告本身带有明确的投资建议和评级判断。判断标准：是否有独立的投资评级和目标价。
  • 混合型文本：一篇报道同时引用了公司公告内容和分析师点评。处理原则——以主要论述对象和信息来源为准，若无法判定则选择占比最大的成分。
注意事项
不同教材/视频教程可能采用略有差异的四分类命名（如宏观经济/行业公司/市场行情/政策法规 vs 新闻报道/公司公告/财务公告/分析师报告）。 分类体系的设计取决于具体业务需求，没有绝对的对错之分。关键是保持一致性——一旦确定了分类体系， 所有 Few-Shot 示例和评估标准都必须与之对齐。

金融分析师角色 Prompt 设计

现在我们来设计完整的 System Prompt。一个好的角色 Prompt 应当包含四个核心要素： Identity（身份定位）→ Expertise（专业能力）→ Task（任务描述）→ Constraints（行为约束）。 这四个要素层层递进，共同构成一个完整的角色画像。

完整 System Prompt 代码

System Prompt — 资深金融分析师角色 
system_prompt = """
## 身份（Identity）
你是一名拥有 15 年从业经验的**资深金融分析师**，
曾任职于头部券商研究所（中信/中金/华泰级别），
擅长宏观经济分析、行业研究和公司基本面分析。
你对 A 股市场、港股、美股的财经信息有深刻的理解和敏锐的判断力。

## 专业能力（Expertise）
- **文本分类**：能够快速准确地将财经文本归类到正确类别
- **多维度分析**：从发布主体、内容特征、写作风格、数据密度等角度综合判断
- **边界处理**：对混合型和模糊边界的文本有成熟的判别策略
- **金融术语**：精通各类金融专业术语和行业黑话

## 任务（Task）
你是一个**金融文本四分类器**。对用户输入的中文财经文本，
准确判断其所属类别并输出结构化结果。

### 分类体系（4 类）
| 类别 | 英文名 | 定义 |
|------|--------|------|
| 新闻报道 | News Report | 媒体发布的第三方财经新闻报道 |
| 公司公告 | Company Announcement | 企业官方发布的公告性文件 |
| 财务公告 | Financial Report | 以财务数据和业绩为核心的披露文件 |
| 分析师报告 | Analyst Report | 券商/研究机构发布的投资研究报告 |

## 行为规范（Constraints）
1. 必须且仅能从上述 4 个类别中选择 **1 个**最匹配的类别
2. 若文本涉及多个领域，以**主要论述对象和信息来源**为准
3. 输出必须为严格的 JSON 格式，不包含任何其他文字
4. 每条结果附带 confidence（置信度）和 reasoning（分类理由）
5. confidence 取值范围：高 / 中 / 低
"""

Prompt 设计要点解析

📋 具体化身份
「15年经验」「头部券商」「中信/中金/华泰级别」——越具体的背景描述，模型激活的知识子空间越精准
🎯 能力清单
列出4项专业能力，每项都直接服务于分类任务，避免泛泛而谈的空话
📊 表格化分类体系
用 Markdown 表格呈现4个类别，比纯文本列表更清晰，模型解析更稳定
🔒 行为硬约束
5条编号规则，涵盖单选限制、边界策略、输出格式、字段要求——消除歧义
经验法则：角色 Prompt 的「黄金比例」
  • Identity 占 ~20%：简短有力，1-3句话建立可信度
  • Expertise 占 ~25%：列举与任务直接相关的技能清单
  • Task 占 ~35%：这是核心！详细定义分类体系和每个类别的含义
  • Constraints 占 ~20%：用编号列表给出不可违反的规则

总长度控制在 300-500 字（中文）为宜，过长会导致关键信息被稀释。

Few-Shot 少样本示例设计与编排

Few-Shot Learning（少样本学习）在提示词工程中的含义是： 不更新模型参数，仅通过在 Prompt 中提供少量输入-输出示例对， 让模型理解任务的期望行为模式。对于分类任务而言，Few-Shot 的价值尤为突出—— 它能让模型从「猜测你的意思」转变为「模仿正确的模式」。

Zero-Shot vs Few-Shot 对比实验

让我们用一个直观的对比来感受 Few-Shot 的威力。假设我们要分类这条文本：

测试文本
"比亚迪发布2025年度报告，全年新能源汽车销量突破400万辆，同比增长42%，实现归属于上市公司股东的净利润380亿元，同比增长35%。"
方法 Prompt 策略 预期表现 原因分析
Zero-Shot 仅给出4个类别名称，无任何示例 不稳定 模型只能靠预训练知识的「直觉」猜测，容易混淆公司公告和财务公告
Few-Shot 每类提供1-2个带理由的示例 稳定准确 模型学会了「看数据密度→判断是否为财务公告」的模式

Few-Shot 设计的五大原则

📌 原则一：覆盖全类别
4个类别每个至少1个示例，避免某一类缺失导致模型对该类的理解偏差
🚫 原则二：包含负例暗示
通过理由说明某文本为什么不属于其他类别（如"虽有数据但非核心→非财务公告"）
⚖️ 原则三：平衡分布
各类示例数量尽量均衡，避免位置偏差（Position Bias）导致某类被过度偏好
🧠 原则四：理由驱动
每个示例必须附分类理由，教的是推理过程而非死记硬背
📏 原则五：长度匹配
示例文本长度应接近真实输入的平均长度，避免分布偏移影响模型判断
常见陷阱：Recency Bias（近因偏差）
大模型对 Prompt 中最后出现的示例赋予更高的权重（Recency Bias）。 这意味着如果你把「分析师报告」的示例放在最后，模型可能会倾向于将更多文本分类为分析师报告。 应对策略：(1) 将最重要的或最容易混淆的类别放在最后；(2) 或者在实际使用中随机打乱示例顺序进行多次投票取多数。

以下代码使用 openai Python SDK，通过阿里云百炼平台调用 Qwen-Max 模型执行分类任务。 该代码同样兼容 DeepSeek、智谱 GLM 等支持 OpenAI API 格式的模型服务。

import os
import json
from dotenv import load_dotenv
from openai import OpenAI

load_dotenv()

# ========== 配置 ==========
# 支持任意 OpenAI 兼容接口：Qwen / DeepSeek / GLM 等
client = OpenAI(
    api_key=os.getenv("DASHSCOPE_API_KEY", "your-api-key-here"),
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)

MODEL_NAME = "qwen-max"  # 或 qwen-plus / deepseek-chat / glm-4 等

# ========== Prompt 模板 ==========
# （此处为上文 FINANCIAL_CLASSIFICATION_PROMPT 的完整内容，略）
PROMPT_TEMPLATE = """...（同上完整模板）..."""


def classify_financial_text(text: str) -> dict:
    """对单条金融文本执行四分类"""

    prompt = PROMPT_TEMPLATE.format(text_to_classify=text)

    response = client.chat.completions.create(
        model=MODEL_NAME,
        messages=[
            {"role": "system", "content": prompt},
        ],
        temperature=0.1,       # 分类任务用低温度保证确定性
        max_tokens=512,
    )

    result_text = response.choices[0].message.content.strip()
    # 提取 JSON（处理可能的 markdown 代码块包裹）
    if "```" in result_text:
        json_str = result_text.split("```")[1]
        if json_str.startswith("json"):
            json_str = json_str[4:]
        result = json.loads(json_str.strip())
    else:
        result = json.loads(result_text)

    return result


def batch_classify(texts: list[str]) -> list[dict]:
    """批量分类多条文本"""

    results = []
    for i, text in enumerate(texts):
        print(f"[{i+1}/{len(texts)}] 正在分类...")
        result = classify_financial_text(text)
        results.append(result)
        print(f"  → {result['category']} ({result['confidence']})")
    return results


# ========== 测试数据 ==========
# 来自真实财经场景的测试样本
test_questions = [
    "今日，央行发布公告宣布降低利率，以刺激经济增长。这一降息举措将影响贷款利率，并在未来几个季度内对金融市场产生影响。",
    "ABC公司今日发布公告称，已成功完成对XYZ公司股权的收购交易。本次交易总对价为人民币50亿元，资金来源为公司自有资金和银行贷款。",
    "招商银行公布2025年一季度财报：营业收入892亿元，同比下滑5.2%；净利润289亿元，同比下降3.8%；不良贷款率0.94%，较上年末上升0.02个百分点。",
    "【中信建投】比亚迪(002594.SZ)深度报告：维持'买入'评级，目标价350元。预计2025-2027年归母净利润分别为480/580/680亿元，当前对应PE仅22x，全球化布局进入收获期。",
]


if __name__ == "__main__":
    print("=" * 60)
    print("金融文本分类系统启动")
    print("模型:", MODEL_NAME)
    print("=" * 60)

    results = batch_classify(test_questions)

    print("\n" + "=" * 60)
    print("分类结果汇总：")
    for i, (q, r) in enumerate(zip(test_questions, results)):
        print(f"\n[{i+1}] {q[:40]}...")
        print(f"    分类: {r.get('category', 'N/A')} | 置信度: {r.get('confidence', 'N/A')}")
        print(f"    理由: {r.get('reasoning', 'N/A')}")

分类结果评估 & 本集小结

如何评估分类器的效果？

构建好分类器后，我们需要一套系统的评估方法来衡量其准确性。 对于四分类任务，推荐以下评估流程：

四步评估法
  • Step 1 — 准备金标数据集
    人工标注 30-50 条真实金融文本作为测试集，确保每个类别至少 5-10 条样本
  • Step 2 — 运行批量分类
    用分类器对所有测试样本逐一打标签，记录每条的 category 和 confidence
  • Step 3 — 计算核心指标
    准确率(Accuracy)=正确数/总数 · 每类精确率(Precision)=TP/(TP+FP) · 每类召回率(Recall)=TP/(TP+FN)
  • Step 4 — 分析错误案例
    重点查看被错误分类的样本，归纳错误模式 → 将典型案例加入 Few-Shot 示例库迭代优化

常见错误类型与优化方向

错误类型 典型表现 优化策略
相邻类混淆 公司公告 ↔ 财务公告（两者发布主体相同） 在 Few-Shot 中增加对比示例，强调两者的区分特征
混合文本误判 含数据的新闻被归为财务公告 增加「主要论述对象」判断规则的权重
JSON 解析失败 模型输出了非 JSON 文本 加强输出格式约束，或在后处理层加 JSON 提取逻辑
置信度过高 明显困难的样本仍输出"高"置信度 在 Prompt 中增加置信度校准指导（什么情况应为"中/低"）
