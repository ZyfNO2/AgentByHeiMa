01

JSON 结构介绍

在进入代码实操之前，我们需要先理解 JSON（JavaScript Object Notation） 的基本数据结构。 JSON 是一种轻量级的数据交换格式，易于人阅读和编写，同时也易于机器解析和生成。 它是当前 Web 开发和 LLM 应用中最主流的结构化数据格式。

两种核心数据结构

{ } JSON 对象（Object）
由键值对组成，用花括号包裹。
类似 Python 的 dict。键必须是字符串，值可以是任意合法 JSON 类型。
[ ] JSON 数组（Array）
有序的值列表，用方括号包裹。
类似 Python 的 list。元素之间用逗号分隔，可以是任意类型。

为什么 LLM 要输出 JSON 格式？

在提示词工程的实战场景中，让 LLM 以 JSON 格式输出结果具有决定性意义：

  • 便于程序自动解析：LLM 返回的是一段文本字符串， 如果是自由文本，程序很难可靠地从中提取信息；而如果是标准 JSON 格式， 用 json.loads() 一行代码就能转为 Python 字典/列表，后续处理非常方便。
  • 降低后处理成本：不需要写复杂的正则表达式来从文本中"抠"数据， 不需要处理各种不确定的换行、空格、标点变化——JSON 格式的确定性让整个 Pipeline 更健壮。
  • 结构化信息抽取的前提：下一集（P05）将讲解金融文本的信息抽取实战， 其核心技术就是让 LLM 输出 JSON 格式的结构化数据，然后用程序直接消费这些数据。 本集就是在为下一集打基础！
本集定位说明
⚠️ 这不是讲 PydanticOutputParser 或 LangChain Output Parser 体系的内容。

本集的核心内容是：Python 原生 json 模块的基础操作——json.dumps()、 json.loads()、ensure_ascii 参数等。这是从"普通 Python 编程" 到 "LLM 输出格式控制"之间的过渡集，目的是确保每位学习者都掌握了 JSON 序列化/反序列化的基本功， 为后面 LLM 返回 JSON 字符串后的解析操作做好准备。
02

Python 中 JSON 的使用 —— 06_JSON_Usage_Demo.py

本节通过视频课程中的完整示例代码 06_JSON_Usage_Demo.py， 系统演示 Python json 模块的两大核心操作： 序列化（dumps）和反序列化（loads）。 代码包含三个典型示例，覆盖了字典转 JSON、列表转 JSON、以及 JSON 字符串转回字典的完整流程。

完整源码：06_JSON_Usage_Demo.py

Python / 06_JSON_Usage_Demo.py 
import json


# ============================================================
# 示例1：字典 → JSON 字符串（含中文 + 嵌套结构）
# 演示 json.dumps() 的基本用法、ensure_ascii 和 indent 参数
# ============================================================
person_data = {
    "name": "张三",
    "age": 25,
    "skills": ["Python", "JavaScript", "SQL"],
    "contact": {
        "email": "zhangsan@example.com",
        "phone": "13800138000"
    }
}

# 将 Python 字典转换为 JSON 字符串
# ensure_ascii=False: 让中文正常显示为汉字，而不是转义成 \uXXXX 形式
# indent=2: 美化输出，缩进2个空格，使 JSON 更易读
json_str = json.dumps(person_data, ensure_ascii=False, indent=2)
print("=== 示例1：字典 → JSON ===")
print(json_str)
print("类型:", type(json_str))
print()

# 输出结果：
# {
#   "name": "张三",
#   "age": 25,
#   "skills": ["Python", "JavaScript", "SQL"],
#   "contact": {
#     "email": "zhangsan@example.com",
#     "phone": "13800138000"
#   }
# }
# 类型: <class 'str'>


# ============================================================
# 示例2：列表 → JSON 字符串（产品价格库存列表）
# 演示列表类型的序列化
# ============================================================
products = [
    {"name": "笔记本电脑", "price": 5999, "stock": 120},
    {"name": "无线鼠标", "price": 79, "stock": 500},
    {"name": "机械键盘", "price": 299, "stock": 80}
]

products_json = json.dumps(products, ensure_ascii=False, indent=2)
print("=== 示例2：列表 → JSON ===")
print(products_json)
print()

# 输出结果：
# [
#   {"name": "笔记本电脑", "price": 5999, "stock": 120},
#   {"name": "无线鼠标", "price": 79, "stock": 500},
#   {"name": "机械键盘", "price": 299, "stock": 80}
# ]


# ============================================================
# 示例3：JSON 字符串 → Python 字典（反序列化）
# 演示 json.loads() 将 JSON 字符串还原为 Python 对象
# 这是 LLM 应用中最关键的操作——LLM 返回的就是 JSON 字符串！
# ============================================================
json_string = '''{
  "school": "江汉大学",
  "major": "计算机科学与技术",
  "courses": ["数据结构", "算法分析", "机器学习", "深度学习"],
  "grade": 3


# 将 JSON 字符串解析为 Python 字典
parsed_data = json.loads(json_string)
print("=== 示例3：JSON 字符串 → 字典 ===")
print("学校:", parsed_data["school"])
print("专业:", parsed_data["major"])
print("课程列表:", parsed_data["courses"])
print("年级:", parsed_data["grade"])
print("类型:", type(parsed_data))

# 输出结果：
# 学校: 江汉大学
# 专业: 计算机科学与技术
# 课程列表: ['数据结构', '算法分析', '机器学习', '深度学习']
# 年级: 3
# 类型: <class 'dict'>

两个核心方法详解

方法 方向 作用 关键参数
json.dumps(obj) Python → JSON 字符串 将 Python 对象（dict/list）序列化为 JSON 格式的字符串 ensure_ascii=False（中文不转义）、indent=2（美化缩进）
json.loads(s) JSON 字符串 → Python 将 JSON 格式的字符串反序列化为 Python 对象（dict/list） 无需额外参数，输入必须是合法 JSON 字符串
ensure_ascii 参数的重要性
这是本集最重要的一个参数细节。

当 JSON 数据中包含中文字符时：
▶ ensure_ascii=True（默认）：中文会被转义为 \u5f20\u4e09 这种 Unicode 编码形式，人类不可读
▶ ensure_ascii=False：中文原样保留为 "张三"，清晰可读

在 LLM 应用场景中务必设置 ensure_ascii=False， 否则模型返回的中文信息会变成一堆乱码般的 Unicode 转义字符。

学校: 江汉大学

为什么示例 3 最重要？
因为这就是 LLM 应用中的核心操作模式！

当你调用大语言模型 API 时，模型返回的就是一个字符串（比如 OpenAI API 返回的 message.content）。 如果你通过 Prompt 引导模型输出了 JSON 格式，那么拿到的就是一个 JSON 字符串—— 和示例 3 中的 json_string 一模一样。

此时你需要做的就是调用 json.loads(llm_response)， 把这个字符串变成 Python 字典，然后就可以用 data["school"]、 data["courses"] 这样的方式来访问各个字段了。

这就是本集要传达的最关键知识点：掌握 json.loads()， 就等于拿到了打开 LLM 结构化输出大门的钥匙。

JSON 操作在 LLM Pipeline 中的具体角色

下图展示了从用户输入到最终结构化数据的完整链路，以及本集所学的 JSON 操作在其中扮演的角色：

LLM × JSON 数据流
用户输入文本
   ↓
Prompt 引导 LLM 输出 JSON 格式（P03 学到的角色设定 + P02 学到的结构化提示词）
   ↓
LLM 返回：'{"company":"xxx","amount":123,...}' （这是一个字符串！）
   ↓
★ json.loads() 解析 ★ （本集学的核心技能）
   ↓
得到 Python dict 对象 → 程序可以直接使用各字段数据

四个关键连接点

  • json.loads() 解析 LLM 返回值：LLM API 返回的 content 是字符串类型， 即使内容看起来像 JSON，它本质上仍然是 str。必须用 json.loads() 转换为 dict 才能编程操作。
  • ensure_ascii=False 保证中文不乱码：当 LLM 返回包含中文的 JSON 时， 如果在某个环节用了默认的 ensure_ascii=True，所有中文都会变成 Unicode 转义序列。 这是在中文 LLM 应用开发中最常见的"坑"之一。
  • json.dumps() 用于调试和日志：当你需要把 LLM 的输出记录到日志文件、 或者在调试时打印中间结果时，json.dumps(data, ensure_ascii=False, indent=2) 是最佳选择——格式清晰、中文可读。
  • 为 Few-Shot 信息抽取打基础：下一集 P05 将进入实战阶段， 通过 Few-Shot 示例引导 LLM 从金融文本中抽取实体信息并以 JSON 格式返回。 届时本集学的每一个知识点都会派上用场。
