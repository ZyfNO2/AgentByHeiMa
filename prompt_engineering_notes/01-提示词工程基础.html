什么是 Prompt Engineering？

Prompt Engineering（提示词工程）是指通过设计和优化输入给大语言模型（LLM）的文本指令， 来引导模型产生期望输出的系统性方法与技巧。简单来说，就是学会如何用自然语言精确地「编程」大模型的思维过程。

核心理念
任何 Prompt 技巧都不如清晰表达需求来得重要。这就像人与人之间的沟通—— 如果话都说不明白，对方就不可能理解你的意思。本集的 6 个技巧， 本质上都是在围绕「如何更清晰、更结构化地向大模型传达意图」这一核心目标展开。

T1

技巧一：详细的描述

核心原理
任何 Prompt 技巧都不如清晰表达需求。 这类似于人与人之间的日常沟通——如果连话都说不清楚、说不完整， 对方就不可能真正理解你的意思。对大模型而言同样如此： 你的描述越详细、约束越明确，模型的输出就越符合预期。

图 1-1：课程 PPT 截图 —— 技巧一「详细的描述」讲解页

为什么详细描述如此重要？

大语言模型虽然能力强大，但它本质上是一个文本补全引擎—— 它根据你给出的上文来预测下一个最可能的文本。如果你给的上下文信息不足、模糊不清， 模型就只能靠「猜」来填充空白，而猜测的结果往往偏离你的真实意图。

  • 字数/长度约束：告诉模型你期望多长的输出
  • 风格/语气要求：正式还是轻松？专业还是通俗？
  • 格式规范：段落、列表、表格、JSON？
  • 目标受众：写给谁看的？需要什么背景知识？
  • 具体内容要素：必须包含哪些信息点？

实战示例

示例：写情书任务 — 详细描述 vs 模糊描述 
# ❌ Bad — 模糊描述，模型不知道风格、长度、内容要求
prompt_bad = "帮我写一封情书"

# ✅ Good — 详细描述，来自课程原文示例
prompt_good = "用一些温柔的话语写一封情书，来表达我对你的仰慕和思念。最后，我要求书写字体数要不低于500个字"
要点总结
详细描述的关键在于：把你知道的所有约束条件都告诉模型。 包括语气风格（温柔的话语）、内容方向（仰慕和思念）、量化指标（不低于500个字）。 约束越具体，模型的输出就越可控。
T2

技巧二：让模型充当某个角色

核心原理
通过在 Prompt 中为模型指定一个角色身份，可以让模型以该角色的专业知识背景、 语言风格和思维方式来回答问题。这相当于给模型设置了一个「人设」， 使其输出更加聚焦和专业。

图 2-1：课程 PPT 截图 —— 技巧二「角色设定」讲解页

角色设定的作用机制

当你告诉模型「你是一个 XXX」时，模型会从其训练数据中激活与该角色相关的知识领域、 术语体系和表达习惯。这使得：

  • 回答更有专业性：AI面试官会用面试官的口吻和关注点来提问
  • 术语使用更准确：程序员角色会使用正确的技术术语
  • 视角更加聚焦：产品经理角色会从产品和用户角度分析问题
  • 风格保持一致：整个对话过程中角色特征稳定

实战示例

示例：AI算法面试官角色 — 来自课程原文 
prompt = "我需要你充当一个AI算法面试官的角色，要求你自主的对我进行AI面试过程中常考的面试题"
常用角色类型参考
  • 面试官角色：「充当XXX面试官，自主进行面试常考题目」
  • 专家顾问：「你是一位有10年经验的XXX领域专家」
  • 写作助手：「你是一个专业的XXX文案撰稿人」
  • 代码审查员：「你是一个严格的代码审查专家」
  • 学习导师：「你是一个耐心的XXX学科老师」
T3

技巧三：使用分隔符标明输入的不同部分

核心原理
在 Prompt 中使用分隔符（Delimiter）来划分不同部分的文本， 帮助模型区分哪些是指令、哪些是需要处理的数据。常用的分隔符包括： 三引号（'''）、中括号（[]）、XML标签（<tag>）、破折线（---）等。

图 3-1：课程 PPT 截图 —— 技巧三「分隔符」讲解页

为什么需要分隔符？

当你的 Prompt 中同时包含指令和待处理的文本数据时， 如果没有明确的分隔标记，模型可能会混淆： 把本该被处理的文本误认为是指令的一部分，或者把指令当成数据处理。 分隔符的作用就是划清界限，让模型清楚地知道「这是命令，那是数据」。

常用分隔符类型

分隔符类型 示例 适用场景
三引号 '''文本内容''' 最常用，适合包裹长文本段落
XML 标签 <text>内容</text> 结构化强，适合多段数据
中括号 [文本内容] 简洁，适合短文本
破折线 --- 内容 --- 视觉分隔明显

实战示例

示例：用三引号分割待处理文本 — 来自课程原文 
prompt = "用20个字符总结由三引号分割的文本。'''在此插入文本'''"
注意事项
选择一种分隔符并在整个 Prompt 中保持一致。 最推荐使用三引号 '''，因为它在大多数场景下不会与正常文本内容冲突， 且视觉辨识度高。避免使用可能在文本中自然出现的符号作为分隔符。
T4

技巧四：对任务指定步骤

核心原理
对于可以拆分的复杂任务，尽量将其拆开，指定一系列明确的步骤让模型依次执行。 这本质上是将一个大任务分解为多个小任务，每一步都有清晰的输入和输出， 从而显著提升最终结果的质量和可控性。

图 4-1：课程 PPT 截图 —— 技巧四「指定步骤」讲解页

为什么要拆分步骤？

当你给模型一个复杂的复合任务时（比如「先总结再翻译再润色」）， 模型需要在一次生成中完成所有子任务，容易出现：

  • 步骤遗漏：跳过了中间某个环节
  • 质量不均：前面的步骤认真执行，后面的草草了事
  • 逻辑混乱：各步骤之间衔接不自然

通过显式地指定步骤顺序，可以让模型按部就班地执行，每个步骤都能得到充分的「注意力」。

实战示例

示例：两步流程 — 先总结后翻译 
prompt = """
请按以下步骤执行任务：

步骤1：阅读下面的文本，用一句话总结其核心内容。

步骤2：将步骤1的总结翻译成英文。

【待处理文本】
{your_text_here}
"""
步骤设计要点
  • 给步骤编号：使用「步骤1」「步骤2」「Step 1」「Step 2」等明确编号
  • 每步只做一件事：不要在一个步骤里塞入多个动作
  • 说明每步的输出：让模型知道每一步应该产出什么
  • 步骤间可传递信息：后续步骤可以引用前面步骤的输出结果
T5

技巧五：提供例子（Few-Shot 思想）

核心原理
先给模型举例，让模型按照例子的格式和风格来输出。 这种做法的本质就是机器学习中的 Few-Shot Learning（少样本学习）思想在 Prompt 层面的应用—— 不需要微调模型参数，仅通过在输入中提供少量示例就能让模型学会新的任务模式。

图 5-1：课程 PPT 截图 —— 技巧五「提供例子/Few-Shot」讲解页

Few-Shot 的威力

Few-Shot Prompting 是从 GPT-3 时代就被验证极其有效的技术。 它的核心优势在于：

📐 格式对齐
模型会严格模仿示例的输出格式
🎯 风格一致
语气、用词习惯与示例保持一致
⚡ 零训练成本
无需微调，换几个示例即可适配新任务
🔢 示例数量灵活
1个(One-Shot)到多个(Few-Shot)均可

实战示例

示例：按照评论文本格式创造新样本 — 来自课程原文 
prompt = """
请按照下面这句评论文本的格式和风格，帮我创造一个新的评价样本：

【示例】
"这个产品的质量真的很好，包装也很精致，物流也很快，
客服态度也非常好，下次还会继续购买的！"

【要求】
请仿照以上示例的格式，生成一条新的商品好评评论。
"""
Few-Shot 设计技巧
  • 示例要有代表性：选的示例应该覆盖你想让模型学习的核心模式
  • 示例数量适中：通常 1~5 个示例效果最佳，过多会占用上下文窗口
  • 示例格式一致：所有示例应遵循相同的格式模式
  • 多样性考虑：如果任务有多种变体，每种变体至少提供一个示例
T6

技巧六：使用参考文本作答（RAG 雏形）

核心原理
基于文本文档辅助大模型问答，让模型使用我们提供的参考信息来组成答案， 而不是完全依赖模型自身的参数知识。这种方法可以有效降低大模型的「幻觉」（Hallucination）问题—— 即模型编造不存在的事实或信息。这正是 RAG（Retrieval-Augmented Generation，检索增强生成）技术的雏形。

图 6-1：课程 PPT 截图 —— 技巧六「使用参考文本作答」讲解页

RAG 雏形的经典用法

知识库问答是该技巧最典型的应用场景：

  • 提供参考材料：将文档、文章、手册等文本作为参考信息传入 Prompt
  • 约束答案来源：要求模型仅基于提供的参考文本来回答问题
  • 诚实处理未知：如果在参考文本中找不到答案，要求模型明确说「我找不到答案」，而不是自己编造

为什么能减少幻觉？

大模型的「幻觉」源于其本质是一个概率文本生成器—— 当它面对不确定的知识时，倾向于生成看起来合理但不一定正确的内容。 通过提供参考文本并约束模型「只能基于这些文本作答」， 相当于给了模型一个可验证的事实锚点， 将生成的自由度限制在了已知正确的信息范围内。

实战示例

示例：基于参考文档回答问题 
prompt = """
请仅基于以下参考文档中的信息来回答用户的问题。
如果文档中没有相关信息，请直接回答"我找不到答案"，不要编造内容。

【参考文档】
'''在此插入参考文档内容'''

【用户问题】
{user_question}
"""
关键原则：找不到就承认找不到
使用此技巧时，务必在 Prompt 中明确告知模型： 如果在提供的参考文本中找不到答案，就写「我找不到答案」， 绝对不要自己编造答案。这个约束是防止幻觉的最后一道防线。
