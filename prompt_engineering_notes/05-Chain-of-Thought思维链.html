CoT 核心原理：为什么「思考过程」能提升准确率

Chain-of-Thought（CoT，思维链） 是由 Google Research 团队（Wei et al., 2022） 在论文《Chain-of-Thought Prompting Elicits Reasoning in Large Language Models》中首次系统提出的一种提示策略。 其核心思想极其朴素却威力巨大：让大语言模型在给出最终答案之前，先显式地展示中间推理步骤。

直觉类比：人类是如何解决复杂问题的？

想象一道小学数学应用题：「一个商店进了 50 箱苹果，每箱有 24 个。 第一天卖掉了总数的 30%，第二天又卖掉了剩下的一半。请问还剩多少个苹果？」

如果你直接脱口而出答案，大概率会算错。但如果你一步步写下来： 总数 = 50 × 24 = 1200 → 第一天卖出 = 1200 × 0.3 = 360 → 剩余 = 1200 - 360 = 840 → 第二天卖出 = 840 ÷ 2 = 420 → 最终剩余 = 840 - 420 = 420 个。 这种「把思考过程展开」的方式，就是 CoT 的本质。

为什么 CoT 有效？三个层面的解释

  • 计算分配效应（Computational Allocation）
    大模型的注意力机制和前向传播计算量是固定的。不使用 CoT 时，模型必须在一个 forward pass 中 同时完成「理解题意 + 规划解题路径 + 执行计算 + 验证结果」四个子任务，每个子任务分到的「认知带宽」有限。 CoT 通过增加中间 token 数量，实质上给模型分配了更多的计算步骤，每一步可以更专注地处理单一子任务。
  • 错误定位与自我纠错（Error Localization）
    当模型将完整推理过程写出来时，中间步骤的错误更容易被模型自身或外部校验机制发现。 这类似于程序调试中的「打印日志」——你不需要猜测哪里出错了，因为每一步的结果都清晰可见。 后续研究（Self-Consistency, Reflexion）进一步利用了这一特性来实现自动纠错。
  • 知识激活与关联（Knowledge Activation）
    推理过程中的自然语言描述会激活模型训练数据中相关的领域知识和模式。 例如提到「同比增长率」时，模型会更倾向于激活财务分析相关的知识簇， 而非通用的文本生成模式。这种上下文引导效应显著提升了专业领域的推理质量。
重要前提：CoT 的效果依赖于模型规模
Wei et al. (2022) 的实验表明：CoT 在小规模模型（如 GPT-3 175B 以下的版本）上几乎没有提升， 只有当模型规模超过某个阈值（约 100B 参数）后，CoT 才开始展现出显著的性能增益。 这一现象被称为「突现能力」（Emergent Ability）——CoT 不是通过微调学到的技能， 而是足够大的语言模型在 in-context learning 场景下自发涌现出的推理能力。 因此，使用 CoT 前请确认你的底层模型具备足够的参数规模（建议 ≥ 30B 或等效能力）。

CoT 的三种主要模式对比

模式 触发方式 优点 缺点 适用场景
Zero-Shot CoT "Let's think step by step" 零示例成本、即插即用 推理链质量不稳定 快速原型验证、通用推理任务
Manual CoT 手动编写 Few-Shot 推理链示例 推理链质量高、可控性强 需要人工设计示例、成本较高 生产级应用、复杂专业任务
Auto-CoT 自动生成推理链（聚类+采样） 无需人工标注、可扩展性好 可能引入噪声推理步骤 大规模部署、多领域泛化

模式一：Zero-Shot CoT —— 一句话触发推理

这是 CoT 最简单的形式。Kojima et al. (2022) 在论文《Large Language Models are Zero-Shot Reasoners》中 发现了一个惊人的事实：仅仅在 Prompt 末尾加上 "Let's think step by step" 这一句话， 就能让模型在各种推理任务上的准确率大幅提升。

Zero-Shot CoT 示例 
# 传统 Zero-Shot（直接问答案）
"""Q: 罗杰有5个网球。他又买了2罐网球，每罐3个。他现在有多少个网球？
A: """
# 模型输出: "11" （可能正确也可能错误，没有推理过程）


# Zero-Shot CoT（加一句魔法短语）
"""Q: 罗杰有5个网球。他又买了2罐网球，每罐3个。他现在有多少个网球？
Let's think step by step.
A: """
# 模型输出:
"""
罗杰一开始有5个网球。
他买了2罐网球，每罐3个，所以是 2 * 3 = 6 个网球。
5 + 6 = 11 个网球。
所以答案是11。
"""
魔法短语的变体
除了经典的 "Let's think step by step"，以下变体同样有效：
▶ "让我们一步一步来分析"（中文场景推荐）
▶ "First, ... Then, ... Finally, ..."（英文结构化提示）
▶ "请先给出推理过程，再给出最终结论"（中文指令式）
关键不在于具体措辞，而在于向模型传递「我需要看到你的思考过程」这一信号。

模式二：Manual CoT —— 手动构建高质量推理链

Manual CoT 是最经典也最强大的形式。你需要为模型提供包含完整推理过程的 Few-Shot 示例， 让模型模仿这种「逐步推理 → 得出结论」的模式来处理新问题。

Manual CoT 金融推理示例 
"""
=== 示例 1 ===

【问题】
某公司2023年营业收入为100亿元，2024年营业收入增长至130亿元。
请问该公司2024年的营收同比增速是多少？

【思考过程】
步骤1：确认已知条件——2023年营收（基期）= 100亿元，2024年营收（报告期）= 130亿元
步骤2：确定计算公式——同比增速 = (报告期数值 - 基期数值) / 基期数值 × 100%
步骤3：代入数值计算——(130 - 100) / 100 × 100% = 30 / 100 × 100% = 30%
步骤4：合理性检验——30%的增长属于合理范围，无异常

【答案】
该公司2024年营收同比增速为30%。

---

=== 示例 2 ===

【问题】
投资者A以每股10元买入某股票1000股，后以每股15元卖出800股，
又以每股12元补仓200股。若当前股价为14元，投资者的持仓盈亏是多少？

【思考过程】
步骤1：梳理交易流水
  - 初始买入：1000股 × 10元 = 10000元
  - 卖出部分：800股 × 15元 = 12000元（实现盈利2000元）
  - 补仓操作：200股 × 12元 = 2400元
步骤2：计算当前持仓
  - 剩余持股：1000 - 800 + 200 = 400股
  - 当前市值：400股 × 14元 = 5600元
步骤3：计算总投入成本
  - 净投入 = 10000 - 12000 + 2400 = 400元
步骤4：计算总体盈亏
  - 浮动盈亏 = 当前市值 - 净投入 = 5600 - 400 = 5200元
  - 含已实现利润的总盈亏 = 5200 + 2000 = 7200元

【答案】
投资者当前总盈亏为+7200元（含已实现盈利2000元），浮动盈亏为+5200元。

"""

模式三：Auto-CoT —— 自动化推理链生成

Zhang et al. (2022) 提出了 Auto-CoT 框架，旨在自动化地生成推理链示例， 解决 Manual CoT 中人工编写示例的高成本问题。其核心流程分为两步：

Auto-CoT 核心算法伪代码 
def auto_cot_pipeline(questions, llm, k=8):
    """
    Auto-CoT 自动推理链生成管线
    
    Args:
        questions: 问题列表
        llm: 大语言模型接口
        k: 最终选取的示例数量
    
    Returns:
        demos: 包含自动生成推理链的示例集合
    """
    # Phase 1: 问题划分（Question Partition）
    # 使用 K-Means / DBSCAN 对问题进行语义聚类
    embeddings = get_embeddings(questions)
    clusters = cluster_questions(
        embeddings,
        method="kmeans",
        n_clusters=k
    )
    
    demos = []
    # Phase 2: 推理链生成与示例选择
    for cluster_id, cluster_questions in enumerate(clusters):
        # 从每个聚类中选择距离质心最近的问题
        question = select_representative(cluster_questions)
        
        # 用 Zero-Shot CoT 触发器自动生成推理链
        prompt = f"{question}\nLet's think step by step.\n"
        reasoning_chain = llm.generate(prompt)
        
        demos.append({
            "question": question,
            "reasoning": reasoning_chain,
            "cluster": cluster_id
        })
    
    return demos

🎯 Manual CoT
生产环境首选。精心设计的推理链示例带来最高的准确率和可控性
⚙️ Auto-CoT
大规模部署利器。自动聚类+自动生成，降低人工标注成本 80%+

金融文本信息抽取：CoT + 结构化输出的完美结合

信息抽取（Information Extraction, IE）是从非结构化或半结构化文本中识别并提取预定义类型实体信息的任务。 在金融领域，IE 的价值尤为突出——每天海量的研报、公告、新闻、财报解读中蕴含着关键商业情报， 人工逐篇阅读摘录既低效又容易遗漏。CoT + PydanticOutputParser 的组合， 为金融 IE 提供了一种兼顾推理深度和输出规范性的解决方案。

任务定义：从金融新闻中提取什么？

本节聚焦于一个典型的金融 IE 场景：给定一篇中文金融新闻/公告/财报文章， 自动提取出公司名称、股票代码、财务指标、关键事件、情感倾向等结构化字段。 这不是简单的关键词匹配或正则提取，而是需要模型理解语义后进行归纳和推理的信息抽取任务。

端到端 Pipeline 实现：从预处理到 JSON 输出

设计好 Prompt 之后，下一步是用 LangChain 将其组装成可执行的完整 Pipeline。 本节展示从原始文档预处理 → CoT 推理 → 结构化抽取 → 结果校验的全链路代码实现， 并特别介绍 markitdown 这个在生产环境中极为实用的文档预处理工具。

Step 0：文档预处理 —— markitdown 的妙用

金融文档来源多样：PDF 财报、Word 公告、网页新闻、Excel 数据表…… 直接将这些格式的原始内容喂给 LLM 效果往往不佳。markitdown 是微软开源的一个轻量工具， 能将各种文件格式统一转换为干净的 Markdown 文本，保留表格结构和层级关系。

Python / markitdown 预处理 
from markitdown import MarkItDown
from pathlib import Path

def preprocess_financial_doc(file_path: str) -> str:
    """
    使用 markitdown 将各类金融文档统一转换为 Markdown 文本
    
    支持格式：PDF, DOCX, XLSX, PPTX, HTML, 图片(OCR), EPUB 等
    
    Args:
        file_path: 原始文档路径
        
    Returns:
        清洗后的 Markdown 文本
    """
    md = MarkItDown()
    result = md.convert(Path(file_path))
    
    raw_text = result.text_content
    
    # 后处理清洗：去除多余空白、合并断行
    cleaned_lines = []
    for line in raw_text.split('\n'):
        stripped = line.strip()
        if stripped:
            cleaned_lines.append(stripped)
    
    return '\n'.join(cleaned_lines)


# 使用示例
markdown_text = preprocess_financial_doc("./reports/贵州茅台_2024Q1_季报.pdf")
print(f"预处理完成，共 {len(markdown_text)} 字符")
为什么 markitdown 比 PDF 解析库更适合 LLM 预处理？
传统 PDF 解析（如 PyPDF2、pdfplumber）提取的是纯文本流，丢失了表格结构、标题层级等语义信息。 markitdown 会将 PDF 表格转换为 Markdown 表格格式（| 列1 | 列2 |）、 将标题转换为 # ## ### 层级标记，这些结构化标记能被 LLM 更好地理解和利用， 显著提升后续信息抽取的准确率。

Step 1：定义 Pydantic 输出 Schema

Python / Pydantic Schema 定义 
from pydantic import BaseModel, Field
from typing import Optional
from enum import Enum


class Sentiment(str, Enum):
    """情感倾向枚举"""
    POSITIVE = "正面"
    NEGATIVE = "负面"
    NEUTRAL = "中性"


class FinancialMetric(BaseModel):
    """单个财务指标"""
    metric_name: str = Field(..., description="指标名称，如'营业收入'")
    value: Optional[float] = Field(None, description="数值")
    unit: Optional[str] = Field(None, description="单位，如'亿元'")
    yoy_change: Optional[str] = Field(None, description="同比变化率，如'+18.01%'")


class SentimentAnalysis(BaseModel):
    """情感分析结果"""
    overall_sentiment: Sentiment
    confidence: float = Field(ge=0.0, le=1.0, description="置信度 0~1")
    reasoning: str = Field(..., description="情感判断的理由说明")


class ExtractionResult(BaseModel):
    """
    金融信息抽取的完整输出 Schema
    
    设计原则：
    - 必填字段确保核心信息不缺失
    - Optional 字段允许部分信息不存在时优雅降级
    - 嵌套模型保证结构清晰和类型安全
    """
    company_name: str = Field(..., description="公司全称")
    stock_code: Optional[str] = Field(None, description="股票代码，如600519.SH")
    report_type: str = Field(..., description="报告类型：季度报告/年度报告/风险公告等")
    report_period: str = Field(..., description="报告期间，如2024Q1")
    financial_metrics: list[FinancialMetric] = Field(
        default_factory=list,
        description="财务指标列表"
    )
    key_events: list[str] = Field(
        default_factory=list,
        description="关键事件要点列表"
    )
    sentiment_analysis: SentimentAnalysis = Field(
        ...,
        description="情感分析结果"
    )
    extraction_confidence: float = Field(
        ge=0.0, le=1.0,
        default=0.8,
        description="整体提取置信度"
    )

Step 3：结果校验与质量控制

Python / 业务层二次校验 
from dataclasses import dataclass, field
from enum import Enum as EnumAlias


class Severity(str, EnumAlias):
    CRITICAL = "严重"
    WARNING = "警告"
    INFO = "提示"


@dataclass
class ValidationWarning:
    severity: Severity
    message: str
    field: str = ""


def validate_extraction_result(result: ExtractionResult) -> tuple[bool, list[ValidationWarning]]:
    """
    对抽取结果进行业务层面的多层校验
    
    校验层次：
    Level 1 - Schema 层面（Pydantic 已保证）：类型正确、必填不为空
    Level 2 - 业务层面（本函数）：数值合理、逻辑自洽
    Level 3 - 领域层面（可选）：交叉验证外部数据源
    
    Returns:
        (is_valid, warnings)
    """
    warnings: list[ValidationWarning] = []
    
    # ---- 校验 1: 必填字段完整性 ----
    if not result.company_name or len(result.company_name.strip()) < 2:
        warnings.append(ValidationWarning(
            severity=Severity.CRITICAL,
            message="公司名称为空或过短",
            field="company_name"
        ))
    
    # ---- 校验 2: 财务数据合理性 ----
    for metric in result.financial_metrics:
        if metric.value is not None:
            # 负值警告（某些指标如亏损可为负，需区分）
            if metric.value < 0 and metric.metric_name not in ["净亏损", "亏损额"]:
                warnings.append(ValidationWarning(
                    severity=Severity.WARNING,
                    message=f"{metric.metric_name} 为负值: {metric.value}",
                    field=metric.metric_name
                ))
            
            # 异常大值检测（超过万亿级别的营收需警惕）
            if metric.unit == "亿元" and metric.value > 100000:
                warnings.append(ValidationWarning(
                    severity=Severity.WARNING,
                    message=f"{metric.metric_name} 数值异常偏大: {metric.value}",
                    field=metric.metric_name
                ))
    
    # ---- 校验 3: 置信度阈值过滤 ----
    if result.extraction_confidence < 0.7:
        warnings.append(ValidationWarning(
            severity=Severity.WARNING,
            message=f"整体置信度偏低 ({result.extraction_confidence:.0%})，建议人工复核",
            field="extraction_confidence"
        ))
    
    # ---- 校验 4: 情感一致性检查 ----
    positive_signals = sum(1 for e in result.key_events
                          if any(kw in e for kw in
                              ["增长", "提升", "创新高", "超预期"]))
    negative_signals = sum(1 for e in result.key_events
                           if any(kw in e for kw in
                               ["下降", "亏损", "预警", "处罚", "退市"]))
    
    if result.sentiment_analysis.overall_sentiment == Sentiment.POSITIVE and negative_signals > positive_signals:
        warnings.append(ValidationWarning(
            severity=Severity.INFO,
            message="情感判断与关键事件的信号方向可能不一致",
            field="sentiment_analysis"
        ))
    
    is_valid = not any(w.severity == Severity.CRITICAL for w in warnings)
    return is_valid, warnings


# 执行校验
is_valid, warnings = validate_extraction_result(result)

if is_valid:
    print("✅ 校验通过，数据可入库")
else:
    print("❌ 发现严重问题:")
    for w in warnings:
        icon = {Severity.CRITICAL: "❌", Severity.WARNING: "⚠", Severity.INFO: "ℹ"}.get(w.severity, "")
        print(f"  {icon} [{w.severity.value}] {w.message}")

FinCoT 与前沿延伸：知识要点回顾

FinCoT：面向金融领域的思维链推理

FinCoT（Financial Chain-of-Thought） 是学术界针对金融领域推理任务提出的专门化研究方向。 不同于通用 CoT 主要关注数学推理和常识问答，FinCoT 聚焦于金融文本特有的挑战：

  • 数值精度要求极高：金融数据差一个小数点就是天壤之别（亿 vs 万亿）， CoT 的中间步骤必须精确到每一个数字
  • 领域术语密集：「扣非净利润」「摊薄 EPS」「EBITDA」「经营性现金流」等专业术语 需要模型具备深厚的金融领域知识才能正确理解
  • 时间维度复杂：同比（YoY）、环比（QoQ）、累计值、单季度值的区分， 以及不同会计期间的口径对齐，都需要细粒度的推理
  • 因果关系隐含：「利润增速高于营收增速是因为毛利率提升」这类因果推理， 要求模型不仅提取数据还要理解数据之间的关系
生产环境的关键提醒
LLM 抽取的金融数据绝不能直接用于投资决策！

即使使用了 CoT + Pydantic + 校验的三重保障，LLM 仍可能产生数值幻觉（hallucination）。 正确的做法是将 LLM 作为预筛选/初提取层，最终数据必须经过：
▶ 与原始文档的人工抽检比对（至少 10% 抽样率）
▶ 与Wind/同花顺等结构化数据源的交叉验证
▶ 数值范围的合理性检查（如某白酒公司营收不可能超过 1 万亿）
LLM 是提效工具，不是替代人工审慎义务的理由。
