掌握 ChatOpenAI 的完整初始化参数，学会接入 OpenAI / Anthropic / Google / DeepSeek / Ollama 等多种模型提供商，理解 API Key 安全管理与流式输出配置。

时长 22:18 配置篇 多模型接入

1 安装依赖包

LangChain 采用模块化包设计，不同模型提供商对应不同的安装包。按需安装即可，无需一次性装全部依赖：

Bash / Terminal 
# === 核心框架（必装）===
pip install langchain langchain-core

# === 模型提供商（按需选择）===
pip install langchain-openai        # OpenAI (GPT-4o / GPT-4o-mini / o1 / o3)
pip install langchain-anthropic     # Anthropic (Claude 3.5 Sonnet / Claude 3 Opus)
pip install langchain-google-genai  # Google (Gemini 2.0 Flash / Pro)

# === 辅助工具 ===
pip install python-dotenv           # .env 文件加载环境变量
pip install langchain-community     # 社区工具和集成
💡
为什么分这么多包？LangChain v0.3+ 将核心抽象与具体实现彻底分离。langchain-core 只包含接口定义（零第三方依赖），而具体的模型/工具/向量库实现都在各自的独立包中。这样你可以只安装需要的组件，避免不必要的依赖膨胀。

3 ChatOpenAI 参数详解

ChatOpenAI 是最常用的模型类，以下是其完整参数说明。理解每个参数的含义是写出高质量代码的基础：

参数名类型默认值说明
model str "gpt-4o" 指定使用的模型名称。常用值：gpt-4o、gpt-4o-mini、o1-mini、o3-mini。
temperature float 0.7 控制输出随机性。0 = 确定性输出（适合 Agent/代码生成），1.0 = 高创造性（适合创意写作）。Agent 场景推荐设为 0。
max_tokens int None 单次响应的最大 token 数。不设置则由模型自行决定。建议根据任务复杂度合理限制以控制成本。
api_key str None API 密钥。优先从 OPENAI_API_KEY 环境变量读取，也可显式传入（不推荐硬编码）。
base_url str None 自定义 API 端点。用于接入 OpenAI 兼容服务（DeepSeek / vLLM / Groq）。例："https://api.deepseek.com/v1"
streaming bool False 是否启用流式输出。开启后可逐 token 获取响应，显著改善用户体验（下一集详解）。
timeout float 120.0 请求超时时间（秒）。对于需要长时间推理的模型（如 o1/o3），建议适当增大此值。
max_retries int 2 自动重试次数。当 API 返回限流错误（429）或临时故障时自动重试。
model_kwargs dict {} 传递给底层 API 的额外参数。如 {"top_p": 0.95, "frequency_penalty": 0} 等模型特有参数。
🌟
temperature 选择指南：
• 0 ~ 0.3：Agent 推理、代码生成、数据提取、事实问答 —— 要求精确稳定
• 0.4 ~ 0.7：通用对话、翻译、摘要、分析 —— 平衡创造性与准确性
• 0.8 ~ 1.2：创意写作、头脑风暴、角色扮演 —— 追求多样性和新颖性

4 多模型切换策略

在实际项目中，你可能需要在不同场景下使用不同的模型。以下是几种常见的多模型切换模式：

Python 
import os
from langchain_openai import ChatOpenAI
from langchain_anthropic import ChatAnthropic

# ========== 方式一：环境变量切换 ==========
# 在 .env 中设置 MODEL_PROVIDER=openai 或 anthropic
provider = os.getenv("MODEL_PROVIDER", "openai")

if provider == "openai":
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
elif provider == "anthropic":
    llm = ChatAnthropic(model="claude-sonnet-4-20250514", temperature=0)


# ========== 方式二：工厂函数模式 ==========
def get_llm(model_name: str = "default", temperature: 0):
    """根据模型名称返回对应的 LLM 实例"""
    models = {
        "gpt4o":       {"cls": ChatOpenAI,   "model": "gpt-4o"},
        "gpt4o-mini":  {"cls": ChatOpenAI,   "model": "gpt-4o-mini"},
        "claude":      {"cls": ChatAnthropic,"model": "claude-sonnet-4-20250514"},
        "deepseek":    {"cls": ChatOpenAI,
                              "model": "deepseek-chat",
                              "base_url": "https://api.deepseek.com/v1"},
    }
    cfg = models.get(model_name, models["gpt4o-mini"])
    return cfg["cls"](
        model=cfg["model"],
        temperature=temperature,
        **{k: v for k, v in cfg.items() if k not in ("cls", "model")}
    )


# ========== 方式三：轻量任务用小模型，重任务用大模型 ==========
light_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)    // 快速、便宜
heavy_llm = ChatOpenAI(model="gpt-4o", temperature=0)           // 强力、较贵

# 使用示例
simple_response = light_llm.invoke("把这句话翻译成英文")
complex_analysis = heavy_llm.invoke("分析这段代码的性能瓶颈...")
✅
成本优化建议：日常开发和简单任务用 gpt-4o-mini（价格约为 gpt-4o 的 1/10），正式环境和复杂推理用 gpt-4o 或 claude-sonnet。通过工厂函数统一管理，切换模型只需改一个字符串。

5 DeepSeek 与 Ollama 本地模型

除了云端 API，LangChain 也完美支持本地运行的模型。这对于数据隐私敏感、离线场景或成本控制需求尤为重要：

DeepSeek（OpenAI 兼容 API）

Python 
from langchain_openai import ChatOpenAI

# DeepSeek 完全兼容 OpenAI SDK，只需修改 base_url 和 model 名称
deepseek_chat = ChatOpenAI(
    model="deepseek-chat",         // V3 对话模型
    base_url="https://api.deepseek.com/v1",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    temperature=0,
)

# DeepSeek-R1 推理模型（自带思维链）
deepseek_reasoner = ChatOpenAI(
    model="deepseek-reasoner",      // R1 推理模型
    base_url="https://api.deepseek.com/v1",
    api_key=os.getenv("DEEPSEEK_API_KEY"),
    temperature=0,
)

response = deepseek_chat.invoke("解释量子纠缠现象")
print(response.content)

Ollama 本地部署

Python + Bash 
# === Step 1: 安装 Ollama 并下载模型 ===
# 访问 https://ollama.com 下载安装 Ollama
# 终端执行：ollama pull llama3.2
# 终端执行：ollama pull qwen2.5:7b

# === Step 2: Python 中使用 ===
pip install langchain-ollama

from langchain_ollama import ChatOllama

# 连接本地运行的 Ollama 服务
local_llm = ChatOllama(
    model="llama3.2",            // 已通过 ollama pull 下载的模型
    base_url="http://localhost:11434",  // Ollama 默认端口
    temperature=0,
)

# 完全离线运行，数据不出本机
response = local_llm.invoke("用中文介绍一下你自己")
print(response.content)
💡
Ollama 常用命令速查：
ollama list — 查看已安装的模型  |  ollama pull <model> — 下载新模型
ollama run <model> — 交互式对话  |  ollama ps — 查看正在运行的模型

6 API Key 安全管理

API Key 安全是生产环境的红线问题。一旦泄露，可能导致严重的财务损失和安全风险。请务必遵守以下规范：

.env 文件 + python-dotenv 
# === .env 文件内容（放在项目根目录）===
# 注意：.env 文件必须加入 .gitignore！绝对不能提交到 Git！

OPENAI_API_KEY=sk-proj-xxxxxxxxxxxxxxxxxxxxxxxx
ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxxxxxxxxxx
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
Python 加载方式 
from dotenv import load_dotenv
import os

# 自动从 .env 文件加载所有环境变量
load_dotenv()  // 在程序最开始调用一次即可

# 之后所有使用 os.getenv() 或直接实例化的地方都会自动读取
# LangChain 的 ChatOpenAI 会自动读取 OPENAI_API_KEY 环境变量
llm = ChatOpenAI(model="gpt-4o-mini")  // 无需手动传入 api_key！


# === .gitignore 必须包含以下内容 ===
# .env
# .env.local
# *.key
# credentials.json
⚠️
安全检查清单：
• .env 文件已添加到 .gitignore？
• 代码中没有任何硬编码的 API Key？
• 日志中不会打印出 API Key？
• 生产环境使用了密钥管理服务（如 AWS Secrets Manager / Vault）而非 .env 文件？

7 流式输出配置

流式输出（Streaming）让用户能够实时看到模型的生成过程，而不是等待整个响应完成。这对用户体验至关重要——特别是生成长文本时：

Python 
from langchain_openai import ChatOpenAI
import sys

# 创建启用流式的 LLM 实例
llm = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0.7,
    streaming=True,    // 开启流式输出
)


# ========== 方式一：使用 stream() 方法（推荐）==========
print("AI: ", end="", flush=True)

for chunk in llm.stream("用生动的语言描述一下春天的公园"):
    # 每个 chunk 包含一个或多个 token
    print(chunk.content, end="", flush=True)

print()  // 换行


# ========== 方式二：使用 Callback 实现流式 ==========
from langchain_core.callbacks import StreamingStdOutCallbackHandler

llm_with_callback = ChatOpenAI(
    model="gpt-4o-mini",
    streaming=True,
    callbacks=[StreamingStdOutCallbackHandler()],  // 自动打印流式输出
)

response = llm_with_callback.invoke("写一首关于编程的诗")
