第 19 集 · 工具体系核心

工具 Tools

深入理解 LangChain 的 Tool 体系 —— 从 @tool 装饰器到 StructuredTool，从 bind_tools() 绑定到动态工具选择，掌握 Agent 与外部世界交互的核心机制。

核心概念 Tool / Bind BV178w1z7EHQ

1@tool 装饰器创建自定义工具

@tool 是 LangChain 中创建自定义工具最简洁、最推荐的方式。只需在普通 Python 函数上添加装饰器，即可将其转换为可供 LLM 调用的标准 Tool 对象。

基本语法与参数规范

Python 
from langchain_core.tools import tool


# ========== 最简形式：自动推断参数 ==========@
@tool
def get_weather(city: str) -> str:
    """查询指定城市的当前天气情况"""
    # 函数的 docstring 会自动成为 tool 的 description
    return f"{city}今天晴朗，气温 25°C"


# ========== 带参数的完整形式 ==========@
@tool(
    name="calculate_tip",        // 自定义工具名称（可选）
    description="根据账单金额和小费比例计算小费金额",  // 自定义描述（可选）
    return_direct=False,            // 是否直接返回结果给用户
)
def compute_tip(bill_amount: float, tip_percent: float = 15.0) -> str:
    """
    计算小费金额。

    Args:
        bill_amount: 账单总金额（元）
        tip_percent: 小费百分比，默认 15%
    """

    tip = bill_amount * (tip_percent / 100)
    total = bill_amount + tip
    return f"小费: ¥{tip:.2f}, 总计: ¥{total:.2f}"
@tool
装饰器方式
最简单直接，一行装饰器将函数转为 Tool。适合大多数场景。
StructuredTool
类封装
适合复杂参数 schema、需要精细控制输入输出的场景。
BaseTool
继承方式
完全自定义行为，需要实现 _run / _arun 方法。

name 和 description 自动生成规则

当你不显式指定 name 和 description 时，LangChain 会按以下规则自动生成：

属性来源规则说明
name 函数名 取函数名本身，下划线替换为空格（如 get_weather → "get_weather"）。建议使用 snake_case 命名。
description docstring 取函数的第一行 docstring 作为描述。这是 LLM 决定是否调用该工具的关键依据，务必写得清晰准确。
args_schema 类型注解 从函数签名的类型注解自动推断参数 schema，用于告诉 LLM 该工具接受什么参数。
💡
description 是工具的灵魂：LLM 通过读取每个 tool 的 description 来决定调用哪个工具。如果 description 写得模糊或错误，LLM 可能选错工具或传错参数。
• 好："查询指定城市的实时天气，返回温度和天气状况"
• 差："查天气" — 太模糊，LLM 不知道能获取什么信息

args_schema 自定义参数 Schema

当默认的类型注解无法满足需求时（如需要添加字段描述、约束条件），可以通过 Pydantic BaseModel 自定义参数 schema：

Python 
from pydantic import BaseModel, Field
from langchain_core.tools import tool
from typing import Optional


# === 定义参数 Schema ===
class SearchInput(BaseModel):
    """搜索工具的输入参数定义"""
    query: str = Field(
        description="要搜索的关键词或问题",
        min_length=1,
        max_length=200,
    )
    category: Optional[str] = Field(
        default=None,
        description="搜索分类：tech / news / general 等",
    )
    limit: int = Field(
        default=5,
        ge=1,
        le=20,
        description="返回结果的最大数量",
    )


# === 将 Schema 绑定到工具 ===
@tool(args_schema=SearchInput)
def web_search(query: str, category: Optional[str] = None, limit: int = 5) -> str:
    """在互联网上搜索相关信息并返回结果摘要"""
    # 模拟搜索结果
    results = [
        f"[{i+1}] 关于 '{query}' 的搜索结果..."
        for i in range(limit)
    ]
    return "\n".join(results)


# 验证生成的工具信息
print(web_search.name)         // "web_search"
print(web_search.description)  // docstring 内容
print(web_search.args_schema.model_json_schema())  // 完整 JSON Schema

2StructuredTool 与 BaseTool

除了 @tool 装饰器，LangChain 还提供了两种更底层的工具构建方式，适用于不同复杂度的场景。

StructuredTool — 复杂参数的工具封装

当你的工具逻辑不适合写成简单函数时（比如需要维护状态、异步操作等），StructuredTool.from_function() 提供了更大的灵活性：

Python 
from langchain_core.tools import StructuredTool
from pydantic import BaseModel, Field


# === 定义输入 Schema ===
class DatabaseQueryInput(BaseModel):
    table_name: str = Field(description="要查询的数据表名")
    filter_condition: str = Field(default="", description="WHERE 过滤条件")
    limit: int = Field(default=10, ge=1, le=100, description="最大返回行数")


# === 同步执行函数 ===
def run_query_sync(table_name: str, filter_condition: str = "", limit: int = 10) -> str:
    """执行数据库查询（同步版本）"""
    # 这里模拟数据库查询
    return f"SELECT * FROM {table_name} WHERE {filter_condition or '1=1'} LIMIT {limit}"


# === 异步执行函数 ===
async def run_query_async(table_name: str, filter_condition: str = "", limit: int = 10) -> str:
    """执行数据库查询（异步版本）"""
    import asyncio
    await asyncio.sleep(0.1)  // 模拟 I/O 延迟
    return f"[ASYNC] SELECT * FROM {table_name} LIMIT {limit}"


// === 创建 StructuredTool 实例 ===
db_query_tool = StructuredTool.from_function(
    func=run_query_sync,
    coroutine=run_query_async,       // 可选：提供异步版本
    name="database_query",
    description="查询数据库表中的数据，支持 WHERE 条件过滤和 LIMIT 限制",
    args_schema=DatabaseQueryInput,
)

// 直接调用测试
result = db_query_tool.invoke({"table_name": "users", "limit": 5})
print(result)  // SELECT * FROM users WHERE 1=1 LIMIT 5

BaseTool 继承自定义

对于需要完全控制行为的场景（如带状态的工具、复杂的初始化逻辑），可以直接继承 BaseTool 类：

Python 
from langchain_core.tools import BaseTool
from pydantic import BaseModel, Field
from typing import Type, Dict, Any, Optional
import time


class CalculatorInput(BaseModel):
    expression: str = Field(description="要计算的数学表达式，如 '2 + 3 * 4'")


class SafeCalculator(BaseTool):
    """安全的数学计算工具，带超时和异常保护"""

    name: str = "safe_calculator"
    description: str = "安全地计算数学表达式，仅支持基础运算"
    args_schema: Type[BaseModel] = CalculatorInput

    // 可自定义属性
    timeout_seconds: float = 5.0
    _call_count: int = 0   // 内部状态计数器

    def _run(self, expression: str, run_manager=None, **kwargs) -> str:
        """同步执行计算"""
        self._call_count += 1
        start_time = time.time()

        try:
            // 安全检查：只允许数字和基本运算符
            allowed_chars = set("0123456789+-*/().% ")
            if not all(c in allowed_chars for c in expression):
                raise ValueError("表达式包含不允许的字符")

            result = eval(expression, {"__builtins__": {}}, {})  // 限制内置函数

            elapsed = time.time() - start_time
            if elapsed > self.timeout_seconds:
                return f"计算超时 (>{self.timeout_seconds}s)"

            return f"{expression} = {result} (耗时: {elapsed:.3f}s)"

        except Exception as e:
            return f"计算错误: {type(e).__name__}: {e}"

    async def _arun(self, expression: str, run_manager=None, **kwargs) -> str:
        """异步执行计算"""
        // 复用同步方法（纯 CPU 计算，无需真正异步）
        return self._run(expression, run_manager, **kwargs)


// 创建实例并使用
calc = SafeCalculator()
result = calc.invoke({"expression": "(2 + 3) * 4"})
print(result)  // (2 + 3) * 4 = 20 (耗时: 0.000s)
🌟
三种方式的选用指南：
• @tool — 90% 的场景首选，零配置、最简洁
• StructuredTool — 需要同时提供 sync/async 版本、或从已有函数动态创建
• BaseTool 继承 — 需要内部状态、复杂初始化、细粒度控制

原则：能用 @tool 就用 @tool，不够再升级。

3工具绑定到 LLM

创建了工具之后，下一步是将它们绑定到 LLM 上，让模型知道它可以使用哪些工具。bind_tools() 是这一过程的核心方法。

bind_tools() 基础用法

Python 
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import HumanMessage


// === Step 1: 创建工具 ===
@tool
def get_stock_price(symbol: str) -> str:
    """查询股票实时价格"""
    prices = {"AAPL": "$189.50", "TSLA": "$245.30", "NVDA": $880.20"}
    return prices.get(symbol.upper(), f"未找到 {symbol} 的价格数据")


@tool
def get_company_info(company: str) -> str:
    """查询公司基本信息（行业、市值、成立年份）"""
    info = {
        "Apple": "科技 | 市值 2.9T | 1976年成立",
        "Tesla": "新能源汽车 | 市值 780B | 2003年成立",
        "NVIDIA": "AI芯片 | 市值 2.2T | 1993年成立",
    }
    return info.get(company, f"未找到 {company} 的公司信息")


// === Step 2: 初始化 LLM 并绑定工具 ===
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

tools = [get_stock_price, get_company_info]
llm_with_tools = llm.bind_tools(tools)  // 关键步骤！


// === Step 3: 调用绑定后的 LLM ===
response = llm_with_tools.invoke([
    HumanMessage(content="Apple 公司现在的股价是多少？给我也看看它的基本信息。")
])

// === Step 4: 解析响应中的工具调用 ===
print("=== 模型回复内容 ===")
print(response.content)           // 通常为空字符串（因为模型选择了调用工具）

print("\n=== 工具调用请求 ===")
if response.tool_calls:
    for tc in response.tool_calls:
        print(f"  工具名: {tc['name']}")
        print(f"  参数:   {tc['args']}")
        print(f"  ID:     {tc['id']}")
        print()

tool_choice 参数控制

通过 tool_choice 参数可以精确控制模型的工具调用行为：

Python 
from langchain_core.messages import SystemMessage, HumanMessage


// === 方式一：auto（默认）—— 模型自行决定是否调用工具 ===
llm_auto = llm.bind_tools(tools, tool_choice="auto")
response_auto = llm_auto.invoke([HumanMessage(content="今天天气怎么样？")])
// 如果没有匹配的工具，模型会正常回答文本


// === 方式二：none —— 强制不调用任何工具 ===
llm_none = llm.bind_tools(tools, tool_choice="none")
response_none = llm_none.invoke([HumanMessage(content="AAPL股价多少？")])
// 即使问题匹配工具，也不会调用，直接文本回答


// === 方式三：指定特定工具 —— 强制调用某个工具 ===
llm_forced = llm.bind_tools(tools, tool_choice="get_stock_price")
response_forced = llm_forced.invoke([
    SystemMessage(content="你是一个金融助手"),
    HumanMessage(content="随便说点什么"),
])
// 无论用户说什么，都会强制调用 get_stock_price 工具
print(response_forced.tool_calls)
// [{'name': 'get_stock_price', 'args': {...}, 'id': '...'}]


// === 方式四：required / any —— 必须至少调用一个工具 ===
llm_required = llm.bind_tools(tools, tool_choice="any")
response_req = llm_required.invoke([HumanMessage(content="帮我查查 NVIDIA")])
tool_choice 值行为典型用途
"auto"模型自主决定是否/调用哪个工具通用 Agent 场景（默认值）
"none"禁止调用任何工具，仅文本回复纯对话模式、降级方案
"tool_name"强制调用指定的工具强制提取、固定工作流
"any" / "required"必须至少调用一个工具确保工具被使用

parallel_tool_calls 并行调用

当用户的请求涉及多个独立操作时，现代 LLM 支持在一次响应中并行发起多个工具调用，大幅提升效率：

Python 
// 开启/关闭并行工具调用（默认开启）
llm_parallel = llm.bind_tools(
    tools,
    parallel_tool_calls=True,   // 允许一次返回多个 tool_calls
)

response = llm_parallel.invoke([
    HumanMessage(content="对比一下 Apple 和 Tesla 的股价和公司信息")
])


// 一次响应中可能包含多个工具调用
print(f"共触发 {len(response.tool_calls)} 个工具调用:\n")

for idx, tc in enumerate(response.tool_calls, 1):
    print(f"  [{idx}] {tc['name']}({tc['args']})")

// 输出示例：
// 共触发 4 个工具调用:
✅
并行调用的优势：对于上述例子，串行调用需要 4 次 LLM 往返（问一次调一次），而并行调用只需 1 次往返就拿到全部 4 个调用请求。在实际应用中，这意味着延迟降低 60%~80%，用户体验显著提升。

ToolMessage 类型详解

ToolMessage 是工具执行结果的载体，它的核心职责是通过 tool_call_id 将结果「归还」给对应的工具调用请求：

Python 
from langchain_core.messages import ToolMessage, AIMessage, HumanMessage


// === AIMessage 中的工具调用请求 ===
ai_response = AIMessage(
    content="",  // 选择调用工具时 content 通常为空
    tool_calls=[
        {
            "id": "call_abc123",        // 唯一标识符（由 LLM 生成）
            "name": "get_stock_price",
            "args": {"symbol": "AAPL"},
        },
        {
            "id": "call_def456",
            "name": "get_company_info",
            "args": {"company": "Apple"},
        },
    ],
)


// === 执行工具后构造 ToolMessage ===
// 注意：tool_call_id 必须与 AIMessage 中的 id 一一对应！
tool_results = [
    ToolMessage(
        content="$189.50",
        tool_call_id="call_abc123",  // 匹配第一个 tool_call
    ),
    ToolMessage(
        content="科技 | 市值 2.9T | 1976年成立",
        tool_call_id="call_def456",  // 匹配第二个 tool_call
    ),
]


// === 构建完整的消息历史 ===
conversation_history = [
    HumanMessage(content="Apple 股价和公司信息？"),
    ai_response,              // AI 请求调用工具
    *tool_results,            // 工具执行结果（展开列表）
]

// 将完整历史再次发给 LLM，它会基于工具结果生成最终回答
final_response = llm.invoke(conversation_history)
print(final_response.content)
// "根据最新数据，Apple(AAPL) 当前股价为 $189.50..."

tool_call_id 关联机制

ID 来源
由 LLM API 在生成 tool_calls 时自动分配唯一 ID
格式示例
call_abc123 / toolu_xxxxx
匹配要求
ToolMessage.id 必须等于 对应 tool_call.id
错误后果
ID 不匹配会导致 LLM 无法关联结果与调用

错误返回与容错处理

工具执行过程中可能出现各种异常，正确的做法是将错误信息作为 ToolMessage 返回，而不是抛出异常中断流程：

Python 
from langchain_core.messages import ToolMessage
from langchain_core.tools import tool


@tool
def robust_api_call(endpoint: str, data: str) -> str:
    """调用外部 API 接口，带完善的容错处理"""
    try:
        // ... 实际 API 调用逻辑 ...
        if endpoint == "/error":
            raise ConnectionError("API 服务不可达")

        return f"API 调用成功: {data}"

    except ConnectionError as e:
        // !!! 不要 raise，而是返回错误信息字符串 !!!
        return f"[ERROR] 连接失败: {e}。请检查网络连接或稍后重试。"

    except TimeoutError as e:
        return f"[ERROR] 请求超时: {e}。建议减小数据量或增加超时时间。"

    except Exception as e:
        return f"[ERROR] 未预期错误 ({type(e).__name__}): {e}"


// 在 Agent 中使用时的容错包装
def safe_tool_execute(tool_obj, tool_call) -> ToolMessage:
    """安全执行工具并构造 ToolMessage"""
    try:
        result = tool_obj.invoke(tool_call["args"])
        return ToolMessage(content=str(result), tool_call_id=tool_call["id"])
    except Exception as e:
        // 兜底：即使工具本身没处理好异常，Agent 层也要兜住
        return ToolMessage(
            content=f"[AGENT_ERROR] 工具执行失败: {e}",
            tool_call_id=tool_call["id"],
            is_error=True,  // 标记为错误消息
        )
⚠️
黄金法则：工具永远不要抛异常给 Agent。工具应该始终返回一个字符串（成功结果或错误描述），由 LLM 来决定如何处理错误——它可以重试、换一种方式询问用户、或者向用户报告错误。如果工具抛出未捕获的异常，整个 Agent 流程会崩溃。

5动态工具选择与组合

在生产级应用中，工具集往往不是固定的。根据用户身份、意图上下文、权限等级动态调整可用工具，是构建安全、高效 Agent 的必备能力。

根据意图动态加载工具集

Python 
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import HumanMessage, SystemMessage


// ============================================================
// === 定义不同领域的工具集 ===
// ============================================================

// --- 金融工具集 ---
@tool
def query_stock(symbol: str) -> str:
    """查询股票实时行情数据"""
    return f"{symbol}: $189.50 (+2.3%)"

@tool
def query_fund(fund_code: str) -> str:
    """查询基金净值和持仓信息"""
    return f"{fund_code}: NAV 1.2345"

finance_tools = [query_stock, query_fund]


// --- 天气工具集 ---
@tool
def get_forecast(city: str) -> str:
    """查询城市未来7天天气预报"""
    return f"{city}: 未来7天以晴天为主，气温 18~28°C"

@tool
def get_air_quality(city: str) -> str:
    """查询城市实时空气质量指数(AQI)"""
    return f"{city}: AQI 45 (优)"

weather_tools = [get_forecast, get_air_quality]


// --- 办公工具集 ---
@tool
def send_email(to: str, subject: str, body: str) -> str:
    """发送邮件给指定收件人"""
    return f"邮件已发送至 {to}: {subject}"

@tool
def schedule_meeting(title: str, date: str, attendees: str) -> str:
    """创建会议日程安排"""
    return f"会议已创建: {title} @ {date}, 参会人: {attendees}"

office_tools = [send_email, schedule_meeting]


// ============================================================
// === 意图路由：根据用户输入选择工具集 ===
// ============================================================

TOOL_REGISTRY = {
    "finance": ("金融投资助手", finance_tools),
    "weather": ("天气预报助手", weather_tools),
    "office":  ("办公协作助手", office_tools),
}


def route_intent(user_input: str) -> str:
    """简单的关键词意图分类（生产环境应使用 LLM 分类器）"""
    lower_input = user_input.lower()
    if any(kw in lower_input for kw in ["股票", "基金", "股价", "stock", "投资"]):
        return "finance"
    elif any(kw in lower_input for kw in ["天气", "气温", "下雨", "weather", "空气"]):
        return "weather"
    elif any(kw in lower_input for kw in ["邮件", "开会", "日程", "email", "meeting"]):
        return "office"
    else:
        return "general"  // 无匹配工具，走纯对话


// ============================================================
// === 组装并调用 ===
// ============================================================

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

user_question = "帮我查一下 AAPL 和 TSLA 的股价"
intent = route_intent(user_question)

if intent != "general" and intent in TOOL_REGISTRY:
    role_name, tools = TOOL_REGISTRY[intent]

    // 动态绑定工具集
    contextual_llm = llm.bind_tools(tools)

    response = contextual_llm.invoke([
        SystemMessage(content=f"你是{role_name}。只使用你拥有的工具来回答问题。"),
        HumanMessage(content=user_question),
    ])

    print(f"意图分类: {intent}")
    print(f"加载工具: {[t.name for t in tools]}")
    print(f"工具调用: {response.tool_calls}")
else:
    // 无需工具，普通对话
    response = llm.invoke([HumanMessage(content=user_question)])
    print(response.content)

工具权限分级

不同级别的用户应该看到不同的工具集。这既是安全需求，也是降低 LLM 选择困难度的有效手段：

Python 
from enum import Enum
from typing import List


class UserRole(Enum):
    GUEST = "guest"        // 游客：只读操作
    USER = "user"          // 普通用户：基本查询
    ADMIN = "admin"        // 管理员：包含写操作


// === 不同权限级别的工具定义 ===

// Level 0: 所有人可用
@tool
def public_search(query: str) -> str:
    """公开信息搜索"""
    return f"搜索结果: {query}"

// Level 1: 登录用户可用
@tool
def view_profile(user_id: str) -> str:
    """查看个人资料信息（需登录）"""
    return f"用户 {user_id} 的资料"

@tool
def my_orders(user_id: str) -> str:
    """查看我的订单记录（需登录）"""
    return f"用户 {user_id} 的订单列表"

// Level 2: 仅管理员可用
@tool
def delete_user(user_id: str) -> str:
    """删除用户账号（危险操作，仅管理员）"""
    return f"警告: 用户 {user_id} 已被删除"

@tool
def export_database(format: str = "csv") -> str:
    """导出全量数据库（敏感操作，仅管理员）"""
    return f"数据库已导出为 {format} 格式"


// === 权限分级映射 ===
PERMISSION_MAP = {
    UserRole.GUEST: [public_search],                          // 1 个工具
    UserRole.USER:  [public_search, view_profile, my_orders],  // 3 个工具
    UserRole.ADMIN: [public_search, view_profile, my_orders,
                     delete_user, export_database],               // 5 个工具
}


def get_tools_for_user(role: UserRole) -> List:
    """根据用户角色返回对应的工具集"""
    tools = PERMISSION_MAP.get(role, [])
    print(f"[权限] {role.value} -> {len(tools)} 个工具可用")
    return tools


// === 使用示例 ===
current_role = UserRole.USER
available_tools = get_tools_for_user(current_role)

contextual_llm = llm.bind_tools(available_tools)

// 普通用户即使要求删除账号，LLM 也没有 delete_user 工具可用
response = contextual_llm.invoke([
    HumanMessage(content="帮我把用户 test_user 删掉")
])
print(response.content)
// "抱歉，我没有删除用户的功能。如果您需要注销账号，请联系客服..."

实际案例：多步骤工具协作

下面展示一个完整的多步骤工具协作案例 —— 用户想规划一次旅行，Agent 需要依次调用多个工具来完成：

Python 
from langchain_core.messages import (
    HumanMessage, AIMessage, ToolMessage, SystemMessage
)
from langchain_core.tools import tool


// === 旅行规划工具集 ===

@tool
def search_flights(origin: str, destination: str, date: str) -> str:
    """搜索航班信息"""
    return (
        f"航班搜索结果 ({origin} -> {destination}, {date}):\n"
        "1. CA1831 08:00-10:30 ¥850\n"
        "2. MU5132 14:20-16:45 ¥720\n"
        "3. CZ3456 19:00-21:15 ¥680"
    )

@tool
def search_hotels(city: str, check_in: str, check_out: str) -> str:
    """搜索酒店住宿"""
    return (
        f"酒店搜索结果 ({city}, {check_in} ~ {check_out}):\n"
        "1. 万豪酒店 ★★★★★ ¥1,200/晚\n"
        "2. 希尔顿酒店 ★★★★ ¥680/晚\n"
        "3. 如家快捷 ★★ ¥260/晚"
    )

@tool
def get_attractions(city: str) -> str:
    """获取城市热门景点推荐"""
    attractions = {
        "杭州": "西湖、灵隐寺、宋城、千岛湖、西溪湿地",
        "北京": "故宫、长城、颐和园、天坛、南锣鼓巷",
        "成都": "大熊猫基地、宽窄巷子、锦里、都江堰、春熙路",
    }
    return attractions.get(city, f"暂无 {city} 的景点信息")

@tool
def estimate_budget(flights_cost: float, hotel_per_night: float, nights: int) -> str:
    """估算旅行总预算"""
    total_hotel = hotel_per_night * nights
    other_expense = (flights_cost + total_hotel) * 0.3  // 餐饮交通等约30%
    total = flights_cost + total_hotel + other_expense
    return (
        f"预算估算:\n"
        f"  机票: ¥{flights_cost:.0f}\n"
        f"  住宿: ¥{total_hotel:.0f} ({nights}晚)\n"
        f"  其他: ¥{other_expense:.0f}\n"
        f"  ──────────────\n"
        f"  总计: ¥{total:.0f}"
    )


travel_tools = [search_flights, search_hotels, get_attractions, estimate_budget]
llm_travel = ChatOpenAI(model="gpt-4o-mini", temperature=0).bind_tools(travel_tools)


// === 模拟完整的多轮工具调用流程 ===
def simulate_agent_loop(user_query: str, max_rounds: int = 5):
    """模拟 Agent 的工具调用循环"""
    messages = [
        SystemMessage(content="你是一个智能旅行规划助手。使用可用工具帮助用户规划旅行，综合所有信息给出建议。"),
        HumanMessage(content=user_query),
    ]

    for round_num in range(max_rounds):
        print(f"\n--- 第 {round_num + 1} 轮 ---")

        // 调用 LLM
        response = llm_travel.invoke(messages)
        messages.append(response)

        // 如果没有工具调用，说明 LLM 已经给出最终答案
        if not response.tool_calls:
            print("最终回答:")
            print(response.content)
            break

        // 执行所有工具调用
        for tc in response.tool_calls:
            print(f"  >> 调用: {tc['name']}({tc['args']})")

            // 根据名称找到对应工具并执行
            tool_obj = next((t for t in travel_tools if t.name == tc['name']), None)
            if tool_obj:
                result = tool_obj.invoke(tc["args"])
                tool_msg = ToolMessage(content=result, tool_call_id=tc["id"])
                messages.append(tool_msg)
                print(  "  << 结果已返回")
            else:
                print(  "  !! 未找到工具")


// 启动旅行规划
simulate_agent_loop(
    user_query="我想下周三去杭州玩3天，帮我查一下机票酒店和景点，做个预算估算。我出发地是北京。"
)

// 输出示例：
// --- 第 1 轮 ---
//   >> 调用: search_flights({'origin':'北京','destination':'杭州','date':'下周三'})
> 调用: search_hotels({'city':'杭州','check_in':'下周三','check_out':'周六'})
> 调用: get_attractions({'city':'杭州'})

> 调用: estimate_budget({'flights_cost':850,'hotel_per_night':680,'nights':3})
