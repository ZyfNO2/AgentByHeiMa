1 Python 版本要求

选择正确的 Python 版本是项目成功的第一步。不同版本的兼容性差异会直接影响后续开发体验：

Python 版本状态LangChain 兼容性说明
Python 3.10 推荐 ✓ 完美支持 最稳定的选择，所有依赖库均已验证，社区使用量最大
Python 3.11 推荐 ✓ 完美支持 性能提升明显（~10-25%），异常信息更清晰，同样稳定
Python 3.12 可用 ✓ 支持 最新特性，大部分库已适配，适合追求新特性的开发者
Python 3.13+ 暂不推荐 ✗ 部分库不兼容 部分第三方库（如 numpy 的某些版本）可能尚未完全适配
Python 3.8/3.9 可运行但即将淘汰 ⚠ 基本支持 能跑但缺少新语法特性，部分最新版依赖不再支持
💡
本教程统一使用 Python 3.11作为演示版本。如果你还没有安装，推荐从 python.org 下载安装，安装时务必勾选 "Add Python to PATH" 选项。

2 虚拟环境管理

为什么必须用虚拟环境？因为不同的项目需要不同版本的依赖。如果不隔离，全局的 pip install 会导致包冲突噩梦 —— 项目 A 需要 requests==2.28，项目 B 需要 requests==2.31，直接炸裂。

🔢
venv
Python 内置 · 零依赖
Python 自带的虚拟环境工具，无需额外安装任何东西。轻量、简单、开箱即用。
  • Python 内置，无需安装
  • 跨平台一致的行为
  • 足够应对大多数场景
🌟
Conda / Miniconda
AI 开发首选 · 强烈推荐
Anaconda 生态的核心工具。不仅能管理 Python 包，还能管理非 Python 依赖（CUDA、cuDNN 等），是 AI/ML 开发的黄金标准。
  • 自动处理 C/C++ 依赖
  • PyTorch/TensorFlow 一键安装
  • 支持多语言环境 (R, Julia)
  • 环境导出/导入方便迁移
⚡
uv
新一代 · 极速包管理
由 Astral 团队（Ruff 作者）开发的新一代 Python 包管理器。速度比 pip 快 10~100 倍，正在快速获得社区认可。
  • Rust 编写，极速安装
  • 内置虚拟环境管理
  • pip + venv + poetry 替代品
  • 锁文件保证可复现性
Bash - 三种方式对比 
# ========== 方式一：venv（Python 内置）==========
# 创建虚拟环境（只需执行一次）
python -m venv .venv

# 激活虚拟环境
# Windows:
.venv\Scripts\activate
# Linux/Mac:
# source .venv/bin/activate

# 退出虚拟环境
deactivate


# ========== 方式二：conda（推荐 AI 开发）==========
# 创建新环境并指定 Python 版本
conda create -n langchain python=3.11 -y

# 激活环境
conda activate langchain

# 查看所有环境
conda env list


# ========== 方式三：uv（新一代超快方案）==========
# 安装 uv（如果还没装）
# curl -LsSf https://astral.sh/uv/install.sh | sh   # Linux/Mac
# powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"  # Windows

# 创建虚拟环境（自动激活）
uv venv
source .venv/bin/activate  // Linux/Mac
// .venv\Scripts\activate       // Windows

// uv 会自动使用 uv.lock 锁文件，保证依赖一致性

3 项目初始化步骤

以下是从零开始创建一个 LangChain 项目的完整流程，按顺序执行即可：

1
创建项目目录
在合适的位置创建项目文件夹，建议使用有意义的名称：
mkdir langchain-project && cd langchain-project
2
创建虚拟环境
在项目目录下创建独立的虚拟环境，隔离依赖：
python -m venv .venv
.venv\Scripts\activate # Windows
3
安装核心依赖
安装 LangChain 核心框架和 OpenAI 集成包：
pip install langchain langchain-openai python-dotenv
4
创建 .env 文件
将 API Key 存入环境变量文件（绝不能硬编码到代码中！）：
echo OPENAI_API_KEY=sk-xxx > .env
echo DEEPSEEK_API_KEY=sk-xxx >> .env
5
创建入口文件 main.py
编写第一个 LangChain Hello World 程序（详见下一节）

5 .env 文件安全规范

.env 文件用于存储敏感配置信息（API Key、数据库密码等）。它的安全管理是生产环境的红线问题：

.env 文件示例 
# ============================================
# LangChain 项目环境变量
# 注意：此文件包含敏感信息，绝对不能提交到 Git！
# ============================================

# === OpenAI API ===
OPENAI_API_KEY=sk-proj-your-api-key-here

# === DeepSeek API（可选）===
DEEPSEEK_API_KEY=sk-your-deepseek-key-here

# === Anthropic API（可选）===
ANTHROPIC_API_KEY=sk-ant-your-anthropic-key-here

# === Ollama 本地服务地址（可选）===
OLLAMA_BASE_URL=http://localhost:11434

安全铁律

规则优先级说明
.gitignore 必须包含 .env CRITICAL 这是第一道防线。一旦 .env 被 commit 并 push 到公开仓库，Key 就等于泄露了
提供 .env.example 模板 重要 .env.example 只包含键名不含值，提交到仓库供其他开发者参考格式
代码中禁止硬编码 Key CRITICAL 永远不要写 api_key = "sk-xxx" 在源码中，用 os.getenv() 或 load_dotenv()
定期轮换 API Key 建议 怀疑泄露时立即在厂商后台撤销旧 Key 并生成新的
⚠️
.gitignore 必须包含：
.env   .env.local   .env.*.local   *.key   credentials.json   secrets.yaml

6 基础项目结构

一个规范的 LangChain 项目应该遵循清晰的目录结构。以下是推荐的基础模板：

# 项目根目录 langchain-project/ | +- .env # 环境变量（不入库！） +- .env.example # 环境变量模板（入库） +- .gitignore # Git 忽略规则 +- requirements.txt # Python 依赖列表 +- main.py # 入口文件 +- agents/ # Agent 定义 | +- __init__.py | +- research_agent.py +- tools/ # 自定义工具 | +- __init__.py | +- search_tool.py +- prompts/ # 提示词模板 | +- system_prompt.txt +- utils/ # 工具函数 | +- __init__.py | +- helpers.py +- tests/ # 测试文件 | +- test_main.py
requirements.txt 示例 
# ============================================
# LangChain 核心依赖
# ============================================
langchain>=0.3,<0.4
langchain-core>=0.3,<0.4
langchain-openai>=0.3,<0.4
python-dotenv>=1.0,<2.0

# 可选：Anthropic 支持
# langchain-anthropic>=0.3,<0.4

# 可选：Ollama 本地模型
# langchain-ollama>=0.2,<0.4

# 可选：搜索工具
# tavily-python>=0.4

7 第一个 LangChain 程序

一切准备就绪后，让我们编写第一个 LangChain Hello World 程序来验证环境是否正确搭建：

Python - main.py 
"""
LangChain Hello World
===================
第一个 LangChain 程序 —— 验证开发环境是否正确搭建。
"""

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI

# 加载 .env 文件中的环境变量
load_dotenv()

# 创建 LLM 实例
# ChatOpenAI 会自动从环境变量读取 OPENAI_API_KEY
llm = ChatOpenAI(
    model="gpt-4o-mini",     // 使用性价比最高的小模型做测试
    temperature=0.7,
)

# 发起调用
response = llm.invoke("你好！请用一句话介绍你自己。")

# 打印结果
print("=" * 50)
print("LangChain Hello World!")
print("=" * 50)
print(f"模型回复: {response.content}")
print(f"消息类型: {type(response)}")
print("=" * 50)
print("环境验证通过！可以开始学习 LangChain 了 ~")
Terminal - 运行命令 
# 确保虚拟环境已激活（提示符前有 (.venv) 字样）
# 运行程序：
python main.py

# 预期输出：
# ==================================================
# LangChain Hello World!
# ==================================================
# 模型回复: 你好！我是由Z.ai训练的大语言模型...
# 消息类型: <class 'langchain_core.messages.ai.AIMessage'>
# ==================================================
# 环境验证通过！可以开始学习 LangChain 了 ~
