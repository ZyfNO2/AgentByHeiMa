2 ReAct Agent 最终实现

下面是 AI 私厨的核心 Agent 代码 —— 这是整个项目的灵魂所在。基于 ReAct（Reasoning + Acting）模式，让 Agent 具备自主思考和调用工具的能力：

Python — app/agents/personal_chef.py 
# ================================================================
# AI Personal Chef — ReAct Agent 核心实现（最终版）
# ================================================================

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain.agents import create_react_agent
from langchain_tavily import TavilySearchResults
from langchain.chat_models import init_chat_model
from langchain_community.chat_message_histories import SQLChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory
import os

# === Step 1: 初始化多模态 LLM ===
llm = init_chat_model(
    model="qwen-vl-max",
    model_provider="openai",
    base_url=os.getenv("DASHSCOPE_BASE_URL"),
    api_key=os.getenv("DASHSCOPE_API_KEY"),
    temperature=0.3,     // 降低温度，提高稳定性
)

# === Step 2: 定义工具集 ===
tools = [
    TavilySearchResults(
        max_results=5,
        name="recipe_search",
        description="根据菜名或食材搜索详细做法和营养信息，返回结构化结果",
    ),
]

# === Step 3: 设计 System Prompt（关键！）===
SYSTEM_PROMPT = """你是一位经验丰富的私人厨师 AI 助手，名字叫「小厨」。

## 你的能力
1. **食材识别**：用户发送冰箱/厨房照片后，你能识别出所有可见食材
2. **菜谱搜索**：根据识别到的食材搜索合适的菜谱做法
3. **智能推荐**：综合考虑营养、难度、口味偏好给出最佳推荐

## 工作流程（必须严格遵守）
收到用户消息后：
1. 如果用户发了图片 → 先描述图片中的所有食材
2. 调用 recipe_search 工具搜索匹配菜谱（用中文关键词）
3. 从搜索结果中筛选 2~3 道最合适的推荐给用户
4. 每道推荐包含：菜名 | 难度 | 预计时间 | 主要步骤

## 回复风格
- 温暖友好，像一位贴心的厨师朋友
- 推荐格式清晰，使用 emoji 增加可读性
- 如果信息不足，主动询问用户的口味偏好
"""

# === Step 4: 创建 Prompt Template ===
prompt = ChatPromptTemplate.from_messages([
    ("system", SYSTEM_PROMPT),
    MessagesPlaceholder(variable_name="chat_history", optional=True),
    ("human", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])

# === Step 5: 组装 ReAct Agent ===
agent = create_react_agent(
    llm=llm,
    tools=tools,
    prompt=prompt,
    verbose=True,
)

# === Step 6: 绑定持久化记忆 ===
agent_with_memory = RunnableWithMessageHistory(
    agent,
    get_session_history=lambda session_id: SQLChatMessageHistory(
        session_id=session_id,
        connection_string="sqlite:///db/chats.db"
    ),
    input_messages_key="input",
    history_messages_key="chat_history",
)

# === 导出供 FastAPI 调用 ===
chef_agent = agent_with_memory
✅

代码设计亮点解析

Prompt 工程：System Prompt 明确了角色定位、工作流程和回复风格，这是 Agent 质量的核心。
ReAct 循环：create_react_agent 自动处理 Thought→Action→Observation 的循环。
记忆持久化：RunnableWithMessageHistory + SQLite 让会话跨请求保持连续。

3 多工具协同工作流详解

当用户上传一张冰箱照片时，Agent 内部会执行一个完整的多步推理链路。以下是一个真实运行案例的时间线拆解：

Step Type Content 耗时
1 User Input [图片] 冰箱.jpg + "帮我看看能做什么" —
2 Thought 用户发了一张图片，我需要先识别里面的食材... ~120ms
3 Action (LLM) VL Model 视觉理解：检测到鸡蛋、番茄、葱花 ~800ms
4 Thought 识别到鸡蛋+番茄+葱花，适合做快手菜。开始搜索... ~80ms
5 Action (Tool) Tavily Search: "番茄炒蛋 做法 营养" ~650ms
6 Observation 返回 5 条菜谱结果（含做法、热量、时间） —
7 Thought 搜索结果很好，筛选出最匹配的 2 道菜推荐给用户... ~60ms
8 Final Output 结构化推荐报告（含 emoji、步骤、营养数据） ~200ms
💡

为什么 ReAct 比「一次性调用」更优？

如果直接把图片丢给 LLM 说「推荐菜谱」，模型只能靠训练数据中的知识「猜」菜谱，容易过时或不准确。而 ReAct 模式让 Agent 能在推理过程中主动获取实时信息—— 先看图识别食材，再搜索最新菜谱，最后综合判断。这就是「思考 + 行动」的力量。

Python — 错误容错与降级策略 
# === 错误容错包装器 ===
import asyncio
from functools import wraps

def retry_with_fallback(max_retries=2, fallback_response=None):
    """
    工具调用失败时的自动重试 + 降级装饰器。
    
    Args:
        max_retries: 最大重试次数
        fallback_response: 全部失败后的降级响应
    """
    def decorator(func):
        @wraps(func)
        async def wrapper(*args, **kwargs):
            last_error = None
            for attempt in range(max_retries + 1):
                try:
                    result = await func(*args, **kwargs)
                    return result
                except Exception as e:
                    last_error = e
                    if attempt < max_retries:
                        await asyncio.sleep(1 * (attempt + 1))  // 指数退避
                        continue
            
            # 全部重试失败，使用降级响应
            if fallback_response:
                return fallback_response
            raise last_error
        return wrapper
    return decorator

# 使用示例
@retry_with_fallback(
    max_retries=2,
