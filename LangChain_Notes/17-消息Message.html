01

消息系统的核心概念

在 LangChain 中，消息（Message）是连接用户、AI 和工具的核心纽带。它是聊天模型的基本上下文单元，代表模型的输入和输出，携带内容和元数据，用于表示与 LLM 交互时的对话状态。

为什么需要结构化消息？
使用语义化的消息类（而非原始字典），可以避免手动写 {"role": ...} 字典， 更重要的是可以直接用 isinstance(last_message, AIMessage) 进行类型判断， 代码可读性和可维护性显著提升。

每条消息是一个对象，包含三个核心要素：

  • 角色（Role）：标识消息类型（如 system、user、assistant）
  • 内容（Content）：消息的实际内容，可以是文本、图像、音频等
  • 元数据（Metadata）：可选字段，如响应信息、消息 ID、token 使用量等
02

三种核心消息类型

消息类型 Role 值 用途说明
SystemMessage "system" 设定 AI 行为规范、背景知识、角色定位
HumanMessage "user" 代表用户的输入或提问
AIMessage "assistant" 模型回复，可能包含 tool_calls 工具调用

SystemMessage — 系统消息

用于"洗脑"或初始化，告诉模型它的身份和行为约束。优先级最高，通常作为消息列表的首条消息。

Python 
from langchain_core.messages import SystemMessage

# 定义系统消息：设定 AI 角色和行为边界
system_msg = SystemMessage(
    content="你是一名金融分析师，仅回答2023年后的A股市场数据问题，"
             "超出范围时回复'该问题超出我的知识边界'"
)

print(system_msg.content)
# 输出: 你是一名金融分析师，仅回答2023年后的A股市场数据问题...
print(system_msg.type)
# 输出: system
关键要点
若模型不支持系统消息（如部分旧版 API），LangChain 会自动将其合并到 HumanMessage 中。 SystemMessage 决定了模型的"身份设定"，直接影响输出风格和内容范围。

HumanMessage — 用户消息

表示用户输入内容，是对话的核心触发点。支持纯文本或多模态输入（如文本+图片，需模型本身支持多模态能力）。

Python 
from langchain_core.messages import HumanMessage

# 纯文本输入
human_msg = HumanMessage(content="2024年上证指数最高点是多少？")

# 多模态输入（需 GPT-4o 等支持多模态的模型）
human_msg_multimodal = HumanMessage(
    content=[
        {"type": "text", "text": "描述这张图片的金融含义"},
        {"type": "image_url", "image_url": {"url": "https://example.com/chart.png"}}
    ]
)

AIMessage — AI 回复消息

存储模型生成的响应，包含文本回复和可选的工具调用请求（tool_calls）。当模型决定调用外部工具时，content 可能为空字符串。

Python 
from langchain_core.messages import AIMessage

# 普通文本回复
ai_msg = AIMessage(
    content="2024年上证指数最高点为3,400点（截至2024年12月）"
)

# 包含工具调用的回复（模拟模型需查询实时数据）
ai_msg_with_tool = AIMessage(
    content="",
    tool_calls=[{
        "name": "get_stock_data",
        "args": {"market": "A股", "metric": "index_high"},
        "id": "call_abc123"  # 必须唯一标识调用
    }]
)

print(ai_msg_with_tool.tool_calls)
# [{'name': 'get_stock_data', 'args': {...}, 'id': 'call_abc123'}]
03

消息的核心属性

所有消息都继承自 BaseMessage 基类，该基类定义了所有消息共有的属性结构：

content
消息主体内容
str | list
type
消息类型标识
"human" | "ai" | "system"
additional_kwargs
供应商扩展参数
dict
response_metadata
响应元数据（token 等）
dict
id
唯一标识符（可选）
str | None
name
发送者名称（可选）
str | None
additional_kwargs 的作用
additional_kwargs 用于存储特定于模型提供商的额外参数。 例如 OpenAI 可能在此处放置 function_call 信息， Anthropic 可能在其中放置特定的元数据。这是实现跨模型兼容性的关键设计。
04

messages 参数传递给模型

将消息列表传递给聊天模型是 LangChain 最基础的操作方式。模型接收完整的对话历史（消息列表），然后生成对应的响应。

Python 
from langchain_openai import ChatOpenAI
from langchain_core.messages import SystemMessage, HumanMessage, AIMessage

# 初始化模型
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 构建消息列表（完整对话上下文）
messages = [
    SystemMessage(content="你是一名专业的 Python 编程助手，只输出代码，不做额外解释。"),
    HumanMessage(content="请写一个快速排序函数")
]

# 调用模型，传入 messages 参数
response = model.invoke(messages)

print(type(response))     # <class 'langchain_core.messages.ai.AIMessage'>
print(response.content)      # 模型生成的代码内容
print(response.type)         # "ai"
返回值类型
model.invoke(messages) 返回的是一个 AIMessage 对象， 而不是普通字符串。这意味着你可以直接访问其 .content、.tool_calls、 .response_metadata 等属性进行后续处理。
05

完整对话流与工具调用闭环

在 Agent 场景中，消息流转形成一个完整的闭环：用户提问 → AI 判断是否调用工具 → 执行工具 → 将结果传回 AI → AI 给出最终答案。

Python 
from langchain_core.messages import(
    SystemMessage, HumanMessage, AIMessage, ToolMessage
)

# 构建一个完整的工具调用对话链
messages = [
    # Step 1: 系统指令 — 定义 AI 角色
    SystemMessage(content="你是一个智能助手，可以查询天气和股票数据。"),

    # Step 2: 用户输入 — 具体查询需求
    HumanMessage(content="北京今天天气怎么样？"),

    # Step 3: AI 决定调用工具（tool_calls 不为空）
    AIMessage(
        content="",
        tool_calls=[{
            "name": "get_weather",
            "args": {"city": "北京"},
            "id": "call_xyz789"
        }]
    ),

    # Step 4: 工具执行结果 — 必须匹配 tool_call_id
    ToolMessage(
        content="晴，气温 25°C，湿度 45%",
        tool_call_id="call_xyz789"
    ),

    # Step 5: AI 根据工具结果给出最终回答
    AIMessage(content="北京今天天气晴朗，气温 25 摄氏度，湿度 45%，适合外出活动。")
]

# 遍历消息查看完整流程
for msg in messages:
    print(f"[{msg.type:>12}] ", end="")
    if hasattr(msg, 'tool_calls') and msg.tool_calls:
        print(f"调用工具: {msg.tool_calls[0]['name']}")
    elif hasattr(msg, 'tool_call_id'):
        print(f"工具结果 ({msg.tool_call_id})")
    else:
        print(msg.content[:50] + ("..." if len(msg.content) > 50 else ""))
ToolMessage 的关键约束
ToolMessage 是闭环的关键环节。它必须通过 tool_call_id 与之前 AIMessage 中的工具调用一一对应， 否则模型无法正确关联工具结果与调用请求。
06

消息历史管理最佳实践

在实际应用开发中，管理消息历史需要注意以下关键实践：

  • 必须使用类型化消息对象：官方明确要求使用 SystemMessage/HumanMessage/AIMessage 等类，而非原始字典，以确保跨模型兼容性。
  • SystemMessage 放在首位：系统消息通常位于消息列表的开头，用于设定全局行为约束。
  • 控制消息长度：随着对话轮次增加，消息列表会不断增长，需要配合记忆管理组件（如窗口裁剪、摘要压缩）来控制 token 消耗。
  • 保持对话结构完整性：在工具调用场景中，必须确保 AIMessage(tool_calls) → ToolMessage → AIMessage(final_answer) 的顺序不被打乱。
  • 使用 AnyMessage 类型注解：在函数签名中使用 AnyMessage 类型别名来接收任意消息类型，提升代码灵活性。
Python 
from langchain_core.messages import AnyMessage, AIMessage, HumanMessage

# 使用 AnyMessage 处理任意消息类型
def process_chat(msg: AnyMessage):
    print(msg.content)

    # 类型判断后访问特定属性
    if isinstance(msg, AIMessage):
        if msg.tool_calls:
            print(f"检测到工具调用: {len(msg.tool_calls)} 个")

# 可以接收任何子类型
process_chat(HumanMessage(content="你好"))
process_chat(AIMessage(content="你好！有什么可以帮助你的？"))
