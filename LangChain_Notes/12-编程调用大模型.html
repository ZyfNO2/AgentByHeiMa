1 OpenAI Python SDK 入门

OpenAI Python SDK 是官方提供的 Python 客户端库，封装了与 OpenAI API 及所有兼容接口通信的全部逻辑。它是目前 LLM 应用开发中最基础、最核心的依赖之一。

💡
为什么从 SDK 学起？LangChain 底层的 Model I/O 模块本质上就是对各厂商 SDK 的统一抽象封装。理解了原生 SDK 的调用方式、参数含义和返回值结构，后续学习 LangChain 的 ChatOpenAI、invoke()、stream() 等概念时就会豁然开朗——它们只是换了一层更优雅的外衣。

关键参数详解

参数说明典型值
base_urlAPI 服务端点地址。不同平台此处不同，是切换模型提供商的核心参数。https://api.openai.com/v1
api_key身份认证密钥。每个平台注册后独立生成，切勿泄露或硬编码。sk-xxx...
timeout请求超时时间（秒）。网络不稳定时可适当调大。httpx.Timeout(60.0)

organizationOpenAI 组织 ID（仅 OpenAI 官方需要）。org-xxx
✅
同步 vs 异步客户端：SDK 提供两个类——OpenAI（同步）和 AsyncOpenAI（异步）。对于简单的脚本和命令行工具，用 OpenAI 即可；对于 Web 服务、高并发场景，应使用 AsyncOpenAI + async/await 以获得更好的性能。两者的 API 接口完全一致，只是返回类型不同（直接结果 vs Coroutine）。

2 基础调用：chat.completions.create()

chat.completions.create() 是 SDK 中最核心的方法，用于向聊天模型发送请求并获取回复。理解它的参数和返回值结构，是掌握整个 SDK 的基石。

最简调用示例

Python 
from openai import OpenAI

client = OpenAI(base_url="...", api_key="...")

response = client.chat.completions.create(
    model="gpt-4o-mini",       # 指定使用的模型名称
    messages=[                        // 消息列表（必填）
        {"role": "user", "content": "你好，请用一句话介绍 Python。"}
    ],
    temperature=0.7,              // 随机性控制（0=确定性，2=最大随机）
    max_tokens=500,               // 最大输出 token 数
)

# === 提取回复文本（三种常用方式）===
# 方式 1：最常用的属性访问
print(response.choices[0].message.content)

# 方式 2：使用 model_dump 转为字典
print(response.model_dump_json(indent=2))

# 方式 3：访问元数据
print(f"模型: {response.model}")
print(f"用量: {response.usage}")

返回值 ChatCompletion 结构解析

字段路径类型含义
response.idstr本次请求的唯一标识符，用于日志追踪和调试
response.modelstr实际使用的模型名称（可能与请求的不完全一致）
response.choices[0].message.rolestr回复角色，通常为 "assistant"
response.choices[0].message.contentstr模型的文本回复——这是你最常需要的字段
response.usage.prompt_tokensint输入（prompt）消耗的 token 数量
response.usage.completion_tokensint输出（completion）消耗的 token 数量
response.usage.total_tokensint总 token 数 = prompt + completion
response.createdint响应生成的 Unix 时间戳

流式调用（Streaming）

Python 
from openai import OpenAI

client = OpenAI(base_url="...", api_key="...")

stream = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "写一首关于春天的短诗"}],
    stream=True,     
)

// 逐块（chunk）接收并打印回复
for chunk in stream:
    content = chunk.choices[0].delta.content
    if content:
        print(content, end="", flush=True)  // flush=True 实现逐字显示效果

print()  // 换行
🚀
流式 vs 非流式的选择策略：
• 非流式（默认）：适合后台任务、批量处理、需要完整结果再处理的场景。代码简单，一次性拿到全部结果。
• 流式（stream=True）：适合聊天界面、实时展示、用户体验优先的场景。用户无需等待整段文字生成完毕，可以「打字机效果」逐字看到输出。
• 在 LangChain 中对应的就是 .invoke() vs .stream() 的区别。

3 多轮对话实现

真实应用中几乎都是多轮对话场景——用户提问、模型回答、用户追问、模型继续回答……SDK 通过 messages 列表来实现这一机制，每次调用都把完整的对话历史传给模型。

三种消息角色（Role）

角色role 值作用出现位置
系统消息"system"设定模型的行为准则、身份定位、输出约束。相当于给模型下达「总指令」。通常在 messages 列表的第一条
用户消息"user"用户的实际输入内容——问题、指令、文本等。交替出现于对话中
助手消息"assistant"模型之前的回复。需要手动把上一次的回复追加到 messages 中，模型才能「记住」上下文。紧随对应的 user 消息之后
💡
System Prompt 最佳实践：
• 明确身份：「你是一位资深 Python 开发者」比「你很懂编程」效果好得多
• 约束格式：「请用 JSON 格式输出」「每条不超过50字」可大幅提升输出质量
• 提供范例：给出期望输出的示例（Few-Shot），让模型模仿
• 避免矛盾：不要在 system 和 user 中给出冲突指令

完整多轮对话循环

Python 
from openai import OpenAI

client = OpenAI(base_url="...", api_key="...")

// === 初始化对话历史（包含 System Prompt）===
messages = [
    {"role": "system", "content": (
        "你是一个友好的 AI 学习助手。"
        "你的任务是帮助用户解答编程问题，"
        "回答要简洁、准确、附带代码示例。"
        "如果你不确定答案，请诚实地说出来。"
    )},
]

print("=== AI 助手已启动（输入 quit 退出）===")
print()

// === 对话主循环 ===
while True:
    user_input = input("\n▶ 你：").strip()

    // 退出条件
    if user_input.lower() in ("quit", "exit", "q"):
        print("再见！")
        break

    // 1. 将用户消息加入历史
    messages.append({"role": "user", "content": user_input})

    // 2. 调用 API 获取回复（传入完整历史！）
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=messages,
        temperature=0.7,
    )

    // 3. 提取助手回复
    assistant_msg = response.choices[0].message.content

    // 4. 打印回复
    print("\n🤖 助手：", assistant_msg)

    // 5. 将助手回复也加入历史（关键！否则模型会"失忆"）
    messages.append({
        "role": "assistant",
        "content": assistant_msg
    })

    // 可选：打印当前 token 用量
    print(f"   [Token: {response.usage.total_tokens}]")
⚠️
常见陷阱 —— Token 窗口溢出：随着对话轮次增加，messages 列表越来越长，最终可能超出模型的上下文窗口限制（如 gpt-4o-mini 为 128K tokens）。解决方案：
• 使用 max_tokens 限制单次回复长度
• 实现滑动窗口：只保留最近 N 轮对话
• 使用摘要压缩：定期将早期对话总结为一句话
• 这正是 LangChain Memory 模块要解决的核心问题！

统一工厂函数封装

Python 
import os
from openai import OpenAI

// === 工厂函数：根据环境变量自动选择平台 ===
PLATFORMS = {
    "openai": {
        "base_url": "https://api.openai.com/v1",
        "model": "gpt-4o-mini",
    },
    "deepseek": {
        "base_url": "https://api.deepseek.com/v1",
        "model": "deepseek-chat",
    },
    "bailian": {
        "base_url": "https://dashscope.aliyuncs.com/compatible-mode/v1",
        "model": "qwen-plus",
    },
    "ollama": {
        "base_url": "http://localhost:11434/v1",
        "model": "qwen2.5:7b",
    },
}

def create_client(platform=None):
    """根据环境变量或参数创建 OpenAI 兼容客户端"""
    platform = platform or os.environ.get("LLM_PLATFORM", "deepseek")
    config = PLATFORMS[platform]

    return OpenAI(
        base_url=config["base_url"],
        api_key=os.environ.get("LLM_API_KEY", ""),
    ), config["model"]


// === 使用方式 ===
// 方式 1：通过环境变量切换
// export LLM_PLATFORM=deepseek
// export LLM_API_KEY=sk-xxx
client, model = create_client()

// 方式 2：直接指定
client, model = create_client("ollama")

response = client.chat.completions.create(
    model=model,
    messages=[{"role": "user", "content": "你好！"}],
)
print(response.choices[0].message.content)
🌟
设计精髓：这种「base_url + api_key」驱动的切换模式，正是 LangChain 能够统一抽象数十种模型提供商的底层原理。你在本集学到的每一个概念——Client、messages、streaming——都会在后续 LangChain 章节中以更高层次的 API 重新出现。

5 实用技巧汇总

除了基础的调用方式，SDK 还提供了许多高级功能，能显著提升应用的可靠性和可控性。

JSON Mode 可靠输出
强制模型输出合法 JSON 格式，避免解析错误。适用于需要结构化数据的场景（如 API 调用、数据提取）。
response = client.chat.completions.create(
  model="gpt-4o-mini",
  messages=[...],
  response_format={"type": "json_object"}
)
Seed 参数 可复现性
固定随机种子，使相同输入在 temperature > 0 时仍能得到确定性的输出。对测试调试和结果复现至关重要。
response = client.chat.completions.create(
  model="gpt-4o-mini",
  messages=[...],
  temperature=0.7,
  seed=42
)
Stop 序列 输出控制
指定停止词列表，当模型生成到这些词时立即终止。可用于精确控制输出长度或格式边界。
response = client.chat.completions.create(
  model="gpt-4o-mini",
  messages=[...],
  stop=["\n\n", "---"]
)
Logprobs 概率分析
获取每个生成 token 的对数概率分布，用于分析模型置信度、检测幻觉、实现不确定性量化等高级场景。
response = client.chat.completions.create(
  model="gpt-4o-mini",
  messages=[...],
  logprobs=True, top_logprobs=3
)

6 常见错误排查表

在实际开发中，你会不可避免地遇到各种 API 错误。下面是一份经过实践检验的错误排查速查表，按出现频率排序：

错误现象异常类可能原因解决方案
认证失败
Incorrect API key		 AuthenticationError API Key 无效、过期、或复制时多了空格/换行 检查 api_key 是否正确；确认环境变量是否加载成功；重新生成 Key
请求过于频繁
Rate limit reached		 RateLimitError 短时间内发送了过多请求，触发了平台的频率限制 添加 time.sleep(1) 重试间隔；使用指数退避策略；考虑升级套餐
上下文过长
Maximum context length		 ContextLengthError messages 总 token 数超过了模型的上下文窗口上限 减少 max_tokens；截断对话历史；使用滑动窗口或摘要压缩
连接失败
Connection refused		 ConnectionError / APITimeoutError 网络不通、DNS 解析失败、代理配置错误、VPN 未开启 检查网络连接；确认代理设置（HTTP_PROXY）；Ping 目标地址；开启 VPN
参数无效
Invalid request		 InvalidRequestError model 名称拼写错误、不支持的参数组合、messages 为空 仔细核对 model 名称（区分大小写）；查阅官方文档确认支持的参数
服务器错误
500 Internal Server Error		 InternalServerError 平台服务端暂时不可用（维护、过载、Bug） 等待几秒后重试；查看平台状态页（Status Page）；联系技术支持
余额不足
Insufficient quota		 AuthenticationError 账户余额耗尽或免费额度用完 充值账户；切换到免费模型（如 Ollama 本地部署）；申请免费额度
🛡️
健壮的错误处理模板：在生产环境中，永远不要假设 API 调用一定会成功。建议使用 try/except 包裹所有调用，针对不同的异常类型采取不同的重试策略——RateLimitError 应退避重试，AuthenticationError 应立即报错，ConnectionError 可有限次重试后降级。
Python 
import time
from openai import OpenAI, AuthenticationError, RateLimitError, \
    ConnectionError as OpenAIConnectionError, APITimeoutError

client = OpenAI(base_url="...", api_key="...")

MAX_RETRIES = 3
BASE_DELAY = 1  // 秒

def call_with_retry(**kwargs):
    """带重试和退避机制的稳健调用"""
    for attempt in range(MAX_RETRIES):
        try:
            return client.chat.completions.create(**kwargs)
        except RateLimitError:
            delay = BASE_DELAY * (2 ** attempt)  // 指数退避
            print(f"限流中，{delay}s 后重试... (第{attempt+1}次)")
            time.sleep(delay)
        except (OpenAIConnectionError, APITimeoutError) as e:
            if attempt < MAX_RETRIES - 1:
                print(f"网络异常，重试中... ({e})")
                time.sleep(BASE_DELAY)
            else:
                raise
        except AuthenticationError:
            raise Exception("API Key 无效，请检查配置！")  // 认证错误不重试
    raise Exception("达到最大重试次数")


// 使用
response = call_with_retry(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "你好"}],
)
