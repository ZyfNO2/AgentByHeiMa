1 三种调用方式总览

LangChain 的所有 Runnable 组件（包括 ChatModel）都统一实现了三种调用方法。它们适用于不同的使用场景：

.invoke()
同步调用
一次性获取完整响应。最简单直接的方式，适合脚本、批量处理和不需要实时反馈的场景。
适用：数据处理、后端 API、Agent 内部调用
.stream()
流式调用
逐 token 返回生成内容。用户可以实时看到输出过程，大幅降低感知延迟。
适用：聊天界面、CLI 工具、长文本生成
.ainvoke()
异步调用
非阻塞的异步版本。在等待模型响应期间可以处理其他任务，适合高并发 Web 服务。
适用：FastAPI / Django、高并发服务、WebSocket
💡
设计哲学：这三种方法构成了 LangChain 的Runnable 统一接口的核心。不仅是 ChatModel，Chains、Agents、Retrievers 等所有组件都支持这三种调用方式。你学会了其中一个，就等于学会了全部。

2.invoke() 同步调用详解

.invoke() 是最基本的调用方式，传入输入，等待返回完整结果：

Python 
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# ========== 基础用法：传入字符串 ==========
response = llm.invoke("什么是机器学习？用三句话解释")
print(response.content)
# 输出: "机器学习是人工智能的一个子领域..."


# ========== 进阶用法：传入 Message 列表 ==========
messages = [
    SystemMessage(content="你是一个专业的技术文档翻译官，只输出翻译结果"),
    HumanMessage(content="Translate the following to Chinese:\n\nMachine learning is a subset of artificial intelligence..."),
]

response = llm.invoke(messages)
print(response.content)


# ========== 访问元数据（Token 用量等）==========
response = llm.invoke("写一首关于 Python 的诗")
print("=== 回答内容 ===")
print(response.content)
print("\n=== Token 使用量 ===")
print(response.response_metadata)   // 包含 token_usage、finish_reason、model_name 等
print("\n=== Token 详情 ===")
print(response.usage_metadata)     // 标准化的 token 统计信息
🌟
invoke() 返回的 AIMessage 对象包含三个关键属性：
• response.content —— 模型生成的文本内容（字符串）
• response.response_metadata —— 原始 API 返回的元数据字典
• response.usage_metadata —— 标准化的 token 使用量 {'input_tokens': 20, 'output_tokens': 150, 'total_tokens': 170}

3.stream() 流式调用

流式调用让模型「边想边说」，每个 chunk 包含一个或多个 token。这是构建交互式应用的关键技术：

Python 
import sys
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0.7,
    streaming=True,   // 必须开启 streaming 参数
)


# ========== 方式一：逐 chunk 迭代 ==========
print("Assistant: ", end="", flush=True)

full_content = []
for chunk in llm.stream("用生动的语言描述一下春天的公园"):
    if chunk.content:
        full_content.append(chunk.content)
        print(chunk.content, end="", flush=True)  // 实时打印到终端

result = "".join(full_content)
print(f"\n\n[共生成 {len(result)} 个字符]")


# ========== 方式二：收集所有 chunks 后统一处理 ==========
chunks = list(llm.stream("列出 Python 的三大优点"))
combined = "".join([c.content for c in chunks if c.content])
print(combined)
特性invoke()stream()
返回类型AIMessage（单个对象）Iterator[AIMessageChunk]（迭代器）
阻塞行为完全阻塞直到完成逐 chunk 返回，可并行处理 UI 更新
首字延迟需等待全部生成完毕通常 100~500ms 即可获得首个 token
内存占用需要缓存完整响应流式处理，峰值内存更低
中断能力无法中途取消可随时 break 中断生成
适用场景后端处理、数据管道聊天界面、CLI 工具、实时展示

4 结构化输出 with_structured_output

很多时候我们需要的不是自由文本，而是结构化的 JSON 数据——比如从一段文字中提取实体、将非结构化文本转为表格等。with_structured_output() 让 LLM 直接输出符合 Pydantic 模型的结构化数据：

Python 
from pydantic import BaseModel, Field
from typing import List
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)


# === 定义输出的数据结构 ===
class MovieReview(BaseModel):
    """电影评论的结构化提取结果"""
    title: str = Field(description="电影名称")
    rating: "评分 (0-10)", ge=0, le=10)
    genre: str = Field(description="电影类型")
    pros: List[str] = Field(description="影片优点列表")
    cons: List[str] = Field(description="影片缺点列表")
    summary: str = Field(description="一句话总结")


with_structured_output(MovieReview)


# === 调用 —— 直接得到 Pydantic 对象！===
review = structured_llm.invoke("""
最近看了《星际穿越》，诺兰真的太会拍了。
画面震撼，汉斯季默的配乐简直神了，尤其是那个管风琴的旋律。
不过剧情有些地方确实有点难懂，时间膨胀那段我看了两遍才明白。
马修麦康纳西的表演很到位，父女情那块看哭了。
整体给个9分吧，科幻片里的天花板。
""")

# review 现在是 MovieReview 类型，可以直接访问属性
print(f"电影: {review.title}")
print(f"评分: {review.rating}/10")
print(f"类型: {review.genre}")
print(f"优点: {' | '.join(review.pros)}")
print(f"缺点: {' | '.join(review.cons)}")
print(f"总结: {review.summary}")

# 还可以直接转成 JSON 或 Dict
print(review.model_dump_json())  // JSON 字符串
print(review.model_dump())     // Python 字典
✅
为什么 with_structured_output 这么好用？它底层利用了 LLM 原生的 Function Calling / JSON Mode 能力，让模型直接输出符合 schema 的 JSON，然后自动反序列化为 Pydantic 对象。你得到的不再是需要自己解析的字符串，而是有类型约束、可直接编程操作的数据对象。这在信息抽取、数据清洗、表单填充等场景下极为强大。

5 多模态模型调用（图像理解）

GPT-4o、Claude 3.5、Gemini 等现代多模态模型原生支持图像输入。LangChain 通过 HumanMessage 的 content 多模态格式轻松实现：

Python 
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
import base64

llm = ChatOpenAI(model="gpt-4o")  // 注意：必须用支持视觉的模型


# ========== 方式一：通过 URL 传入图片 ==========
message = HumanMessage(content=[
    {"type": "text", "text": "这张图片里有什么？请详细描述。"},
    {"type": "image_url", "image_url": {"url": "https://upload.wikimedia.org/wikipedia/commons/thumb/4/47/PNG_transparency_demonstration_1.png/280px-PNG_transparency_demonstration_1.png"}},
])

response = llm.invoke([message])
print(response.content)


# ========== 方式二：通过本地文件 Base64 传入 ==========
def image_to_base64(image_path: str) -> str:
    """读取图片文件并转换为 base64 编码"""
    with open(image_path, "rb") as f:
        data = base64.b64encode(f.read()).decode("utf-8")
    return data


image_b64 = image_to_base64("./photo.jpg")

message = HumanMessage(content=[
    {"type": "text", "text": "分析这张图片中的物体数量和位置关系"},
    {"type": "image_url", "image_url": {"url": f"data:image/jpeg;base64,{image_b64}"}},
])

response = llm.invoke([message])
print(response.content)
💡
多模态支持的模型列表：
• GPT-4o / GPT-4o-mini：图片 + 文本，支持 URL 和 Base64
• Claude 3.5 Sonnet：图片 + 文本，支持最高 20MB 图片
• Gemini 2.0 Pro：图片 + 视频 + 音频 + 文本，原生多模态
• Qwen-VL：开源中文多模态模型，可通过 Ollama 本地运行

6 错误处理与重试机制

调用 LLM API 时可能遇到各种错误：网络超时、限流（Rate Limit）、服务不可用等。良好的错误处理是生产级代码的基本要求：

Python 
import time
from langchain_openai import ChatOpenAI
from langchain_core.exceptions import OutputParserException

llm = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0,
    max_retries=3,          // LangChain 内置的重试次数
    request_timeout=30.0,       // 单次请求超时（秒）
)


# ========== 方式一：try-except 捕获异常 ==========
def safe_invoke(prompt: str) -> str:
    """带异常捕获的安全调用封装"""
    try:
        response = llm.invoke(prompt)
        return response.content
    except OutputParserException as e:
        print(f"[解析错误] {e}")
        return "抱歉，回答格式出现异常，请重试。"
    except Exception as e:
        error_type = type(e).__name__
        print(f"[{error_type}] {e}")
        return "服务暂时不可用，请稍后再试。"


# ========== 方式二：指数退避重试 ==========
def invoke_with_retry(prompt: str, max_retries: int = 3) -> str:
    """带指数退避的重试逻辑"""
    for attempt in range(max_retries):
        try:
            response = llm.invoke(prompt)
            return response.content
        except Exception as e:
            if attempt == max_retries - 1:
                raise  // 最后一次重试仍然失败，抛出异常
            wait_time = (2 ** attempt)  // 1s -> 2s -> 4s
            print(f"第 {attempt+1} 次失败，{wait_time}秒后重试... ({e})")
            time.sleep(wait_time)
常见错误类型HTTP 状态码原因与处理建议
RateLimitError429API 调用频率超限。解决方案：降低并发数、增加重试间隔、考虑升级套餐。
APITimeoutErrorTimeout请求超时。对于 o1/o3 等推理模型，建议增大 timeout 到 300s+。
AuthenticationError401API Key 无效或过期。检查 .env 文件和环境变量配置。
BadRequestError400请求参数错误。检查 model 名称是否正确、消息格式是否符合要求。
InternalServerError500服务商内部故障。通常是临时性的，重试即可恢复。

7 并发调用：batch / abatch

当需要对大量输入进行批量处理时，逐个 invoke 效率太低。LangChain 提供了 .batch() 和 .abatch() 方法用于批量并发调用：

Python 
import asyncio
import time
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

prompts = [
    "用一句话解释什么是 AI",
    "用一句话解释什么是 ML",
    "用一句话解释什么是 DL",
    "用一句话解释什么是 NLP",
    "用一句话解释什么是 CV",
]


# ========== batch(): 同步批量调用 ==========
# 内部使用线程池并发执行，但对外仍是同步阻塞的
start = time.time()
results = llm.batch(prompts)
elapsed = time.time() - start

for i, result in enumerate(results):
    print(f"[{i+1}] {result.content[:60]}...")
print(f"\nbatch() 总耗时: {elapsed:.2f}s (串行约需 {elapsed*5:.2f}s)")


# ========== abatch(): 异步批量调用 ==========
# 使用 asyncio 并发，效率更高，适合 I/O 密集场景
async def batch_demo():
    start = time.time()
    results = await llm.abatch(prompts)
    elapsed = time.time() - start

    for i, result in enumerate(results):
        print(f"[{i+1}] {result.content[:60]}...")
    print(f"\nabatch() 总耗时: {elapsed:.2f}s")

asyncio.run(batch_demo())
方法并发模型特点
invoke() x N串行最简单但最慢，一个接一个执行，总耗时 = 所有请求之和
batch()线程池内部用 ThreadPoolExecutor 并发，适合 CPU 密集型后处理
abatch()asyncio基于事件循环的真正并发，I/O 等待时不阻塞，效率最优
