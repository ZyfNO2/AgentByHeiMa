ChatPromptTemplate 创建模板

ChatPromptTemplate 是 LangChain 中用于构建结构化提示词的核心类。它允许开发者定义带有变量的提示词模板，在运行时动态注入参数，从而实现提示词的复用与管理。相比手动拼接字符串，使用模板可以大幅降低出错概率并提高代码可维护性。

from_template() — 字符串模板基础用法

最简单的创建方式，直接从字符串模板生成 ChatPromptTemplate 实例：

Python 
from langchain_core.prompts import ChatPromptTemplate

# 定义带变量的字符串模板（使用 Python f-string 风格的占位符）
template = ChatPromptTemplate.from_template(
    "你是一名{role}专家，请用{tone}的语气回答以下问题：\n\n{question}"
)

# 调用 .format() 注入变量，返回完整的消息列表
messages = template.format(
    role="Python 编程",
    tone="专业且友好",
    question="什么是装饰器？"
)

print(messages)
# 输出：你是一名Python 编程专家，请用专业且友好的语气回答以下问题：
#       什么是装饰器？

from_messages() — 消息列表模板

更灵活的方式，支持按角色分别定义每条消息的内容模板，适合多轮对话场景：

Python 
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.messages import SystemMessage, HumanMessage

# 使用 from_messages 构建多角色消息模板
template = ChatPromptTemplate.from_messages([
    ("system", "你是{name}，一个{personality}的 AI 助手。只回答关于{topic}的问题。"),
    ("human", "{user_input}")
])

# 格式化后得到完整的消息对象列表
messages = template.format_messages(
    name="小智",
    personality="幽默风趣",
    topic="机器学习",
    user_input="解释一下梯度下降"
)

# messages[0] 是 SystemMessage, messages[1] 是 HumanMessage
print(type(messages[0]))  # <class 'langchain_core.messages.system.SystemMessage'>
print(messages[0].content)     # 你是小智，一个幽默风趣的 AI 助手。只回答关于机器学习的问题。

两种方式对比

对比维度 from_template() from_messages()
输入形式 单个字符串模板 消息元组/消息对象列表
输出类型 String（纯文本） List[Message]（结构化消息）
角色控制 隐式（需在文本中描述） 显式（每条消息指定 role）
适用场景 简单单轮提示词 多轮对话、System/User 分离
灵活性 较低 较高，可混合 Message 对象与模板
本天才的建议
在实际项目中优先使用 from_messages()。 它输出的结构化消息可以直接传给 model.invoke(messages)， 无需额外转换。而且当你的提示词需要同时包含 system、user、assistant 角色时， 只有 from_messages() 能优雅地表达这种结构。

变量注入与部分填充

提示词模板的真正威力在于变量管理。LangChain 提供了三种层次的变量注入机制： 完整填充（format）、部分填充（partial）、以及动态变量（partial_variables）， 分别适用于不同的使用场景。

.format() — 完整填充所有变量

最基础的用法，一次性提供所有必需变量的值：

Python 
from langchain_core.prompts import ChatPromptTemplate

template = ChatPromptTemplate.from_template(
    "将以下内容翻译为{target_lang}：\n\n{text}"
)

# 一次性填入所有变量
result = template.format(
    target_lang="English",
    text="人工智能正在改变世界"
)
print(result)
# 将以下内容翻译为 English：
# 人工智能正在改变世界

.partial() — 预填充部分变量

当某些变量是固定的（如系统角色、日期等），可以使用 .partial() 预先填充， 返回一个新的模板实例，剩余变量稍后再填入。这在管道（Pipeline）中特别有用—— 上游组件固定一部分变量，下游组件再补充剩余部分。

Python 
from langchain_core.prompts import ChatPromptTemplate

# 定义包含多个变量的模板
template = ChatPromptTemplate.from_template(
    "当前时间：{current_time}\n"
    "角色：{role}\n"
    "用户问题：{question}"
)

# 使用 partial() 预填充固定变量，返回新模板
partial_template = template.partial(
    current_time="2025-01-15 10:30",
    role="技术支持工程师"
)

# 后续只需填入剩余变量
result = partial_template.format(question="如何重置密码？")
print(result)

partial_variables — 动态变量

对于每次调用时值都可能变化的变量（如当前日期、随机数、外部 API 结果）， 可以传入可调用对象（Callable），LangChain 会在每次 format 时自动执行该函数获取最新值。

Python 
from datetime import datetime
from langchain_core.prompts import ChatPromptTemplate

# 定义动态获取当前时间的函数
def get_current_time() -> str:
    return datetime.now().strftime("%Y-%m-%d %H:%M:%S")

# 创建模板时通过 partial_variables 绑定动态变量
template = ChatPromptTemplate.from_template(
    "现在是 {current_time}。\n请回答：{question}",
    partial_variables={
        "current_time": get_current_time  # 传入函数引用
    }
)

# 每次 format 都会重新调用 get_current_time()
r1 = template.format(question="今天星期几？")
import time; time.sleep(2)
r2 = template.format(question="现在几点了？")

print(r1)  # 现在是 2025-01-15 10:30:01...
print(r2)  # 现在是 2025-01-15 10:30:03... （时间不同！）
方法 触发时机 适用场景 返回值
.format(**vars) 立即 一次性完整填充 格式化后的字符串/消息列表
.partial(**vars) 立即（固定值） 固定值的预填充 新的 Template 实例
partial_variables={} 每次 format 时 动态变化的值（时间、API 等） 构造时绑定 Callable

Few-Shot Prompting 实现

Few-Shot Learning（少样本学习） 是提升 LLM 输出质量最有效的技巧之一。 通过在提示词中提供若干高质量的输入-输出示例，模型能够快速理解期望的输出格式和风格， 从而显著减少幻觉和不一致问题。LangChain 为此提供了完善的模板和示例选择机制。

FewShotPromptTemplate — 文本模式少样本

用于传统的文本补全场景，将示例拼接到提示词中：

Python 
from langchain_core.prompts import FewShotPromptTemplate, PromptTemplate

# 定义示例集合 —— 每个示例是一个字典
examples = [
    {"input": "开心", "output": "情绪积极指数：9/10，建议保持现状"},
    {"input": "焦虑", "output": "情绪积极指数：3/10，建议深呼吸放松"},
    {"input": "平静", "output": "情绪积极指数：7/10，状态良好"},
]

# 定义单个示例的格式模板
example_prompt = PromptTemplate.from_template(
    "用户输入：{input}\n分析结果：{output}"
)

# 创建 Few-Shot 提示词模板
few_shot_template = FewShotPromptTemplate(
    examples=examples,              # 示例数据源
    example_prompt=example_prompt,  # 单个示例的渲染格式
    suffix="用户输入：{user_input}\n分析结果：",  # 待预测的后缀
    input_variables=["user_input"]      # 最终用户输入的变量名
)

# 生成最终提示词（包含示例 + 待预测输入）
prompt = few_shot_format.format(user_input="兴奋")

FewShotChatMessagePromptTemplate — 聊天模式少样本

专为聊天模型设计，示例以消息列表的形式组织，更适合 ChatModel：

Python 
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.prompt_values import FewShotChatMessagePromptTemplate

# 定义聊天模式的示例（每个示例是一组消息）
examples = [
    [
        ("human", "将'hello world'翻译成中文"),
        ("ai", "'你好世界'")
    ],
    [
        ("human", "将'good morning'翻译成中文"),
        ("ai", "'早上好'")
    ],
]

# 定义示例的消息模板
example_prompt = ChatPromptTemplate.from_messages([
    ("human", "{user_input}"),
    ("ai", "{ai_output}")
])

# 创建聊天模式 Few-Shot 模板
few_shot_chat_prompt = FewShotChatMessagePromptTemplate(
    examples=examples,
    example_prompt=example_prompt
)

// 组合到完整的提示词模板中
final_prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名专业翻译，请将英文翻译为中文并用引号包裹结果。"),
    few_shot_chat_prompt,           
    ("human", "{query}")     
])

示例选择器（Example Selector）

当示例库很大时，全部塞进上下文会消耗大量 token 且可能造成干扰。 Example Selector 可以根据策略智能选取最相关的子集：

LengthBasedExampleSelector
根据 token 长度限制自动截取示例数量
SemanticSimilarityExampleSelector
基于语义相似度选择最相关示例（需向量库）
MaxMarginalRelevanceExampleSelector
兼顾相似度与多样性的平衡选择
Custom Selector
继承 BaseExampleSelector 自定义选择逻辑
Python 
from langchain_core.example_selectors import LengthBasedExampleSelector
from langchain_core.prompts import FewShotPromptTemplate, PromptTemplate

# 准备大量示例（假设有 20+ 条）
all_examples = [
    {"word": "happy", "antonym": "sad"},
    {"word": "tall", "antonym": "short"},
    # ... 更多示例 ...
]

# 创建基于长度的选择器 —— 自动控制示例数量以适应 token 预算
selector = LengthBasedExampleSelector(
    examples=all_examples,
    max_length=200,          # 最大字符长度限制
    example_prompt=PromptTemplate.from_template("单词：{word} → 反义词：{antonym}"),
    get_text_length=lambda x: len(x)  # 长度计算函数
)

# 选择器会根据 max_length 自动决定放入多少条示例
few_shot = FewShotPromptTemplate(
    example_selector=selector,    # 使用选择器替代固定 examples
    example_prompt=...,           # 同上
    suffix="单词：{input} → 反义词：",
    input_variables=["input"]
)
Few-Shot 最佳实践
  • 示例质量 > 数量：3 个精准示例优于 10 个模糊示例
  • 示例应覆盖边界情况（edge cases），而非仅展示正常路径
  • 对于聊天模型，优先使用 FewShotChatMessagePromptTemplate
  • 配合 Example Selector 控制 token 消耗，避免超出上下文窗口

输出解析器（Output Parsers）

LLM 的原始输出是自由格式的文本，但在实际应用中我们往往需要结构化的数据（JSON、特定 Schema 等）。 Output Parser 正是解决这个问题的桥梁——它在提示词中嵌入格式指令， 并在模型输出后将文本解析为目标数据结构。

StrOutputParser — 字符串输出解析

最简单的解析器，将 AIMessage 的 content 直接提取为纯字符串，常用于 LCEL 管道末端：

Python 
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

# 构建 LCEL 管道：prompt | model | parser
chain = (
    ChatPromptTemplate.from_template("用一句话解释：{topic}")
    | ChatOpenAI(model="gpt-4o-mini")
    | StrOutputParser()         # AIMessage -> str
)

# 直接得到字符串，无需 .content 属性访问
result = chain.invoke({"topic": "量子纠缠"})
print(result)       # "量子纠缠是两个粒子间存在的神秘关联..."
print(type(result))  # <class 'str'>

JSONOutputParser — JSON 结构化输出

引导模型输出合法的 JSON 格式，并自动解析为 Python dict：

Python 
from langchain_core.output_parsers import JsonOutputParser
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

# 创建 JSON 解析器（会自动生成格式指令）
parser = JsonOutputParser()

# 将格式指令注入提示词 —— 这一步至关重要！
prompt = ChatPromptTemplate.from_template(
    "提取以下文本中的实体信息，并以 JSON 格式输出。\n"
    "{format_instructions}\n\n"
    "文本内容：{text}"
).partial(format_instructions=parser.get_format_instructions())

# 构建管道
chain = prompt | ChatOpenAI(model="gpt-4o-mini") | parser

# 输出已经是 Python dict，可直接程序化处理
result = chain.invoke({"text": "苹果公司总部位于加州库比蒂诺，由史蒂夫·乔布斯创立"})
print(result)
# {'entities': [{'name': '苹果公司', 'type': '组织'}, {'name': '加州库比蒂诺', 'type': '地点'}, ...]}
print(type(result))  # <class 'dict'>

PydanticOutputParser — Pydantic 模型验证输出

最强大的解析器，结合 Pydantic 模型定义严格的输出 Schema， 不仅解析 JSON 还会进行字段类型验证，确保输出完全符合预期结构：

Python 
from pydantic import BaseModel, Field
from langchain_core.output_parsers import PydanticOutputParser
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

# === Step 1: 用 Pydantic 定义输出结构 ===
class MovieReview(BaseModel):
    """电影评论的结构化输出"""
    title: str = Field(description="电影名称")
    rating: float = Field(description="评分，范围 0-10")
    summary: str = Field(description="一句话剧情概括")
    pros: list[str] = Field(description="优点列表")
    cons: list[str] = Field(description="缺点列表")
    recommendation: str = Field(description="推荐程度：强烈推荐/推荐/一般/不推荐")

# === Step 2: 创建解析器 ===
parser = PydanticOutputParser(pydantic_object=MovieReview)

# === Step 3: 构建含格式指令的提示词 ===
prompt = ChatPromptTemplate.from_template(
    "你是一位资深影评人。请对以下电影进行深度点评。\n"
    "{format_instructions}\n\n"
    "电影名称：{movie_name}"
).partial(format_instructions=parser.get_format_instructions())

# === Step 4: 执行管道 ===
chain = prompt | ChatOpenAI(model="gpt-4o-mini") | parser

result = chain.invoke({"movie_name": "盗梦空间 Inception"})

# 输出是 MovieReview 实例，具有完整的类型提示和字段验证
print(result.title)           # 盗梦空间 Inception
print(result.rating)          # 9.2
print(result.pros)            # ['视觉效果震撼', '叙事结构精妙', ...]
print(type(result))         # <class '__main__.MovieReview'>
print(result.model_dump())   # 转换为标准 dict

三种解析器对比

特性 StrOutputParser JSONOutputParser PydanticOutputParser
输出类型 str dict BaseModel 子类
Schema 约束 无 弱（任意 JSON） 强（Pydantic 模型定义）
类型校验 - 无 有（字段类型 + 必填检查）
IDE 支持 一般 一般 优秀（自动补全 + 类型检查）
适用场景 简单文本输出 通用结构化数据 严格 Schema 的 API/数据处理

解析器工作原理
所有 Output Parser 的核心机制相同：(1) 通过 get_format_instructions() 生成格式指令文本 → (2) 将指令注入提示词告诉模型期望的输出格式 → (3) 模型按要求输出 → (4) Parser 的 parse() 方法将文本转换为目标类型。 如果模型输出不符合格式，Parser 会抛出 OutputParserException。

提示词优化最佳实践

写好提示词是一门兼具工程性与艺术性的技能。以下是经过大量实践验证的最佳实践原则， 遵循这些准则可以显著提升 LLM 应用的可靠性和输出质量。

System Prompt 设计原则

  • 明确身份与职责边界：开篇即声明"你是 XXX"，限定回答范围。 例如："你是一名专注于 React 生态的前端顾问，仅回答 18 版本以上的相关问题。"
  • 指定输出语言和风格：明确要求"使用中文回答"、"代码使用 TypeScript"、 "解释要面向初中级开发者"等约束条件。
  • 设置拒绝策略：告知模型在什么情况下应拒绝回答。 例如："如果问题涉及医疗诊断，请明确说明无法提供专业建议并建议就医。"
  • 控制输出长度：通过指令约束回复篇幅。 例如："回答不超过 200 字"、"分 3 点简要说明"、"以表格形式呈现"。

角色设定技巧

具体胜于模糊
"资深 Go 工程师，10年分布式系统经验" > "编程专家"
赋予思维框架
"采用 First Principles 思考方式逐步拆解问题"
模拟受众定位
"向没有技术背景的产品经理解释"
设定行为约束
"先给出结论，再用论据支撑，最后举例"

Chain-of-Thought (CoT) 引导

通过引导模型逐步推理而非直接给出答案，可以显著提升复杂问题的解决准确率：

Python 
cot_prompt = ChatPromptTemplate.from_template(
    """你是一位逻辑严密的数学老师。解答问题时请遵循以下步骤：

**解题步骤要求：**
1. **理解题意**：用自己的话复述题目要求和已知条件
2. **制定计划**：列出你打算使用的公式或方法
3. **逐步推导**：一步一步展示计算过程，不要跳步
4. **验证结果**：检查答案是否合理
5. **最终答案**：用一句话总结答案

---
题目：{problem}
"""
)

# CoT 的关键：给模型"思考的空间"，而不是催促它快速作答

常见反模式与避坑指南

这些错误本天才见得多了
  • 提示词过长导致注意力稀释： System Prompt 超过 500 字后效果递减。核心指令前置，次要信息放后或移入 Few-Shot 示例。
  • 矛盾指令引发混乱： 同时要求"详细解释"和"简洁回答"。每个提示词聚焦单一目标，不要让模型做不可能的事。
  • 忽略 Output Parser 的格式指令： 创建了 Parser 却忘记把 get_format_instructions() 注入提示词， 导致模型根本不知道你要什么格式。
  • Few-Shot 示例与任务不匹配： 示例展示的是简短回答，却期望模型输出长篇分析。示例的风格和长度必须与期望输出一致。
  • 过度依赖默认行为： 不写 System Prompt 直接丢问题给模型，然后抱怨输出不稳定。 明确的指令永远是稳定性的基石。
  • 缺少负面示例（Negative Examples）： 只展示正确做法却不说明"不要做什么"。在 Few-Shot 中加入反面案例往往能大幅减少错误模式。
