时长 18:36 核心篇 ReAct 循环

1 Agent vs Chain：本质区别

在 LangChain 中，Chain（链）和 Agent（智能体）是两种截然不同的执行模式，理解它们的区别是掌握 LangChain 的第一步。

对比维度Chain（链）Agent（智能体）
执行逻辑 预定义的固定流程——开发者事先确定好每一步的执行顺序，代码按既定路径运行 动态自主决策——LLM 根据当前上下文实时决定下一步该做什么，路径不固定
适用场景 流程明确、步骤可预知的任务，如：文本摘要、翻译流水线、格式转换 开放性问题、需要多步推理的任务，如：复杂问答、研究分析、多工具协作
工具调用 按代码写死的顺序依次调用，无法跳过或动态选择 根据推理结果自主选择调用哪个工具，可以多次调用不同工具
可控性 高 —— 每一步都由开发者精确控制 中 —— 通过 System Prompt 和工具约束间接控制
类比 像工厂流水线：原料进来，经过固定的加工工序，产出成品 像有经验的员工：接到任务后自己判断需要用什么工具、查什么资料、怎么完成
💡
选择建议：如果你的任务流程清晰、步骤固定（如「读取PDF -> 提取关键信息 -> 生成报告」），用 Chain + LCEL 更高效可靠；如果任务需要 LLM 自主判断和规划（如「帮我调研某个技术方案并给出建议」），则应该使用 Agent。

2 Agent 工作循环：ReAct 模式

目前 LangChain 中最主流的 Agent 模式是 ReAct（Reasoning + Acting），它源自 Yao et al. (2022) 的论文《ReAct: Synergizing Reasoning and Acting in Language Models》。ReAct 将「思考」和「行动」交织在一起，形成一个闭环推理过程：

🧠
Thought（思考）
LLM 分析当前问题
决定下一步行动策略
→
🔧
Action（行动）
选择并调用一个工具
传入参数执行操作
→
🔎
Observation（观察）
获取工具返回的结果
作为新的上下文输入
↻
🌟
ReAct 的核心优势：传统的 Chain 是「一步到位」，而 ReAct 允许 Agent 在获得中间结果后重新评估并调整策略。如果第一次搜索结果不够好，Agent 可以换关键词再搜一次，或者换个工具尝试。这种「试错-修正」的能力使 Agent 能够处理远比 Chain 复杂的任务。

完整执行示例

假设用户问：「北京今天天气如何？适合户外运动吗？」 Agent 的完整思考链路如下：

Agent 执行日志 
=== 用户输入 ===
"北京今天天气如何？适合户外运动吗？"

=== 第 1 轮循环 ===
Thought: 我需要查询北京今天的天气情况，然后根据温度和天气状况判断是否适合户外运动。让我先搜索北京今天的天气。

Action: duckduckgo_search
Action Input: "北京今天天气"

Observation: 北京今天晴转多云，气温 18~28°C，空气质量良，紫外线中等...

=== 第 2 轮循环 ===
Thought: 已经获取到北京的天气信息了。气温 18~28°C，晴天转多云，空气质量良好。这个条件非常适合户外运动。我可以直接回答用户的问题了。

Final Answer: 北京今天的天气非常不错！气温在 18~28°C 之间，晴天转多云，空气质量为良。这样的天气条件非常适合户外运动，比如跑步、骑行、登山等。建议避开正午时段（紫外线中等），早晚时段更为舒适。
✅
关键观察：注意 Agent 在第一轮获得搜索结果后，并没有立即输出答案，而是进行了第二轮 Thought来综合分析结果，最终才给出 Final Answer。这种多轮推理能力正是 Agent 区别于简单 API 调用的核心所在。

3 create_react_agent() 使用方法

create_react_agent() 是 LangChain 创建 ReAct 类型 Agent 的核心函数。它接收三个核心参数：LLM 实例、工具列表、以及可选的系统提示词模板。

Python 
from langchain_openai import ChatOpenAI
from langchain.agents import create_react_agent, AgentExecutor
from langchain_community.tools import DuckDuckGoSearchRun, WikipediaQueryRun
from langchain_community.utilities import WikipediaAPIWrapper

# ========== 1. 初始化 LLM ==========llm = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0,       # Agent 场景推荐 temperature=0，保证推理稳定
)

# ========== 2. 准备工具集 ==========
tools = [
    DuckDuckGoSearchRun(),                    # 网络搜索
    WikipediaQueryRun(api_wrapper=WikipediaAPIWrapper()),  # 维基百科查询
]

# ========== 3. 创建 ReAct Agent ==========
prompt = """你是一个乐于助人的 AI 助手。请使用提供的工具来回答用户的问题。
当你不知道答案时，主动使用搜索工具查找相关信息。

可用工具：
{tool_names}

{instructions}"""

agent = create_react_agent(
    llm=llm,
    tools=tools,
    prompt=prompt,           // 可选：自定义系统提示词
)

# ========== 4. 包装为 AgentExecutor ==========
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,              // 打印完整的思考链路
    handle_parsing_errors=True,   // 解析失败时自动重试
    max_iterations=10,            // 最大循环次数，防止无限循环
    return_intermediate_steps=True, // 返回中间步骤用于调试
)

# ========== 5. 运行 Agent ==========
result = agent_executor.invoke({
    "input": "什么是量子计算？它和经典计算有什么区别？"
})

print(result["output"])
⚠️
重要提示：create_react_agent() 只负责创建 Agent 的推理逻辑（即 LLM 如何思考和选择工具），而实际的执行管理（循环控制、错误处理、最大迭代次数等）是由 AgentExecutor 来完成的。两者配合使用才是完整的 Agent 运行时。

4 Agent 的四大核心组件

一个完整的 Agent 由四个核心组件构成，每个组件各司其职又紧密协作：

🤖
LLM（大脑）
Agent 的「大脑」，负责理解用户意图、进行推理判断、生成 Action 决策和最终回答。推荐使用支持 Tool Calling 的模型（GPT-4o / Claude 3.5 / DeepSeek-V3），temperature 设为 0 以保证推理稳定性。
🔧
Tools（手脚）
Agent 可调用的外部能力集合。每个 Tool 包含名称、描述、参数 schema。LLM 根据 Tool 的描述来判断何时以及如何调用它们。工具描述写得越清晰，Agent 的调用准确率越高。
🗃
Memory（记忆）
让 Agent 具备跨轮次记忆能力。在单次对话中，AgentExecutor 自动维护 conversation history；跨会话场景则需要配置 ConversationBufferMemory 或其他持久化存储方案。
📝
System Prompt（人设）
定义 Agent 的角色、行为规范和使用约束。好的 System Prompt 能显著提升 Agent 表现：明确角色定位、指定输出格式、限制行为边界、设定安全护栏。
💡
组件协作关系：用户提问进入 Agent 后，System Prompt 设定行为框架，LLM 在此框架内进行推理，通过 Tool Calling 机制选择合适的 Tools 获取外部信息，Memory 保证多轮对话的连贯性。四个组件缺一不可，共同构成了 Agent 的完整能力体系。

5 Tool Calling 机制详解

Tool Calling 是 Agent 能力的基石。现代主流 LLM（GPT-4 / Claude / Gemini）原生支持 Function Calling / Tool Use 功能，LangChain 将这一能力标准化为统一的 Tool 接口。

Tool Calling 工作流程

阶段发生的事情说明
1. 注册 将 Tool 列表传给 LLM 每个 Tool 包含 name、description、parameters（JSON Schema）。这些元数据帮助 LLM 理解工具能力。
2. 决策 LLM 输出 tool_call 请求 当 LLM 判断需要调用工具时，不会直接返回文字，而是返回结构化的 tool_call 对象（含工具名和参数）。
3. 执行 LangChain 执行对应 Tool 框架解析 tool_call，找到匹配的 Tool 实例，将参数传入并执行，获取返回结果。
4. 回馈 结果作为新消息回传 LLM Tool 的执行结果被包装为 ToolMessage，追加到对话历史中，供 LLM 进行下一轮推理。
5. 终止 LLM 给出最终回答 当 LLM 认为已收集到足够信息，不再请求工具调用，而是直接返回 Final Answer。

自定义 Tool 示例

Python 
from langchain_core.tools import tool
from typing import Annotated

# 使用 @tool 装饰器快速定义自定义工具
@tool
def calculate(
    expression: Annotated[str, "要计算的数学表达式，如 '(2+3)*4'"]
) -> str:
    """执行数学计算并返回结果。支持加减乘除和括号。"""
    try:
        result = eval(expression)
        return f"计算结果: {expression} = {result}"
    except Exception as e:
        return f"计算错误: {e}"


@tool
def get_word_count(
    text: Annotated[str, "要统计字数的文本内容"]
) -> str:
    """统计文本的字数（中文按字符计，英文按单词计）。"""
    chinese_chars = len([c for c in text if '\u4e00' <= c <= '\u9fff'])
    english_words = len(text.split())
    return f"中文字符数: {chinese_chars}, 英文单词数: {english_words}"


# 将自定义工具加入 Agent
tools = [calculate, get_word_count]
🚀
编写高质量 Tool 的技巧：
• name 要简洁明了：用 snake_case 命名，如 web_search 而非 searchTheInternetForInformation
• docstring 就是 LLM 看到的「说明书」：详细描述功能、使用场景、参数含义和约束
• 参数类型注解 + 描述：用 Annotated[type, description] 格式，LLM 会据此生成正确的参数值
• 错误处理要友好：返回人类可读的错误信息而非抛异常，方便 LLM 理解并调整策略

6 完整案例：多工具协作 Agent

让我们把以上所有知识整合起来，构建一个具备搜索、计算、文本分析能力的全能型 Agent：

Python 
import os
from langchain_openai import ChatOpenAI
from langchain.agents import create_react_agent, AgentExecutor
from langchain_community.tools import DuckDuckGoSearchRun
from langchain_core.tools import tool
from typing import Annotated

# --- 环境变量加载 ---
from dotenv import load_dotenv
load_dotenv()   # 从 .env 文件加载 OPENAI_API_KEY

# --- 自定义工具：单位换算 ---
@tool
def convert_unit(
    value: Annotated["要换算的数值"],
    from_unit: Annotated[str, "原始单位 (km/mile/kg/lb/C/F)"],
    to_unit: Annotated[str, "目标单位"],
) -> str:
    """在不同度量单位之间进行换算。支持长度、重量、温度。"""
    conversions = {
        ('km', 'mile'): lambda v: v * 0.621371,
        ('mile', 'km'): lambda v: v * 1.60934,
        ('kg', 'lb'): lambda v: v * 2.20462,
        ('lb', 'kg'): lambda v: v * 0.453592,
        ('C', 'F'): lambda v: v * 9/5 + 32,
        ('F', 'C'): lambda v: (v - 32) * 5/9,
    }
    key = (from_unit.lower(), to_unit.lower())
    if key not in conversions:
        return f"不支持 {from_unit} 到 {to_unit} 的换算"
    result = conversions[key](value)
    return f"{value} {from_unit} = {result:.2f} {to_unit}"


# --- 组装 Agent ---
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
tools = [
    DuckDuckGoSearchRun(),   // 网络搜索
    convert_unit,                  // 单位换算
]

agent = create_react_agent(llm, tools)
executor = AgentExecutor(
    agent=agent, tools=tools,
    verbose=True,
    handle_parsing_errors=True,
    max_iterations=8,
)

# --- 测试运行 ---
response = executor.invoke({
    "input": (
        "马拉松全程是多少公里？换成英里是多少？"
        "另外帮我查一下今年波士顿马拉松的冠军成绩。"
    )
})

print("\n=== 最终回答 ===")
print(response["output"])
