1 OpenAI API 成为事实标准

在 LLM 应用开发领域，OpenAI API 格式已经成为了事实上的工业标准。这意味着什么？意味着几乎所有主流大模型厂商都选择兼容 OpenAI 的接口设计，让开发者可以用同一套代码切换不同的模型后端。

统一接口的核心价值：切换模型只需修改两个参数 —— base_url（API 地址）和 api_key（密钥）。业务逻辑代码无需任何改动。这让 A/B 测试不同模型、成本优化（日常用小模型、复杂任务切大模型）、多云容灾变得异常简单。

2 核心端点：请求体结构

所有兼容 OpenAI 格式的 API 都使用同一个核心端点：POST /v1/chat/completions。以下是完整的请求体结构及每个字段的详细说明：

// === HTTP 请求头 === POST /v1/chat/completions HTTP/1.1 Host: api.openai.com Authorization: Bearer $API_KEY Content-Type: application/json // === 请求体 (JSON) === { "model": "deepseek-chat", "messages": [ {"role": "system", "content": "你是一个有用的助手。"}, {"role": "user", "content": "你好！请介绍一下你自己。"} ], "temperature": 0.7, "max_tokens": 1024, "stream": false }
字段名类型默认值必填说明
model string - 是 要使用的模型名称。如 "gpt-4o"、"deepseek-chat"、"qwen2.5:7b"
messages array - 是 对话消息列表，按时间顺序排列。每条消息包含 role(system/user/assistant) 和 content
temperature float 1.0 否 控制随机性。0 = 确定性输出，2.0 = 极高创造性。推荐范围 0~1
max_tokens integer 模型默认 否 限制响应的最大 token 数。用于控制成本和防止过长输出
stream boolean false 否 是否启用流式输出。true 时返回 SSE 事件流而非完整 JSON
top_p float 1.0 否 核采样参数。与 temperature 二选一使用即可，通常设为 0.9~1.0
stop string/array null 否 停止序列。当模型生成到这些 token 时立即停止。如 ["\n\nHuman:"]
presence_penalty float 0 否 存在惩罚 (-2.0 ~ 2.0)。正值鼓励讨论新话题
frequency_penalty float 0 否 频率惩罚 (-2.0 ~ 2.0)。正值降低重复内容
🌟
messages 数组规则：
• 第一条通常是 system 消息 —— 设定角色和行为约束
• 必须保持 user/assistant 交替 —— 不能连续两条相同 role
• 最后一条必须是 user —— 表示这是用户当前要问的问题

3 响应体结构详解

当 stream: false（非流式模式）时，API 返回一个完整的 JSON 对象。理解响应结构对于正确解析结果至关重要：

{ "id": "chatcmpl-a1b2c3d4e5f6", // 唯一请求标识符 "object": "chat.completion", // 响应对象类型 "created": 1704067200, // Unix 时间戳 "model": "deepseek-chat", // 实际使用的模型 "choices": [ { "index": 0, "message": { "role": "assistant", // 消息角色 "content": "你好！我是AI助手..." // <== 核心内容在这里 }, "finish_reason": "stop" // 结束原因 } ], "usage": { "prompt_tokens": 25, // 输入 token 数 "completion_tokens": 128, // 输出 token 数 "total_tokens": 153 // 总计 token 数 } }

finish_reason 取值说明

取值含义处理建议
stop正常结束 —— 模型完成了生成或遇到 stop 序列直接使用返回的 content
length达到 max_tokens 上限 —— 输出被截断考虑增大 max_tokens 或分段处理
tool_calls模型请求调用工具（Function Calling）解析 tool_calls 字段并执行工具
content_filter内容被安全策略过滤检查输入是否有敏感内容

4 流式响应（SSE）

当设置 stream: true 时，API 不再返回一个完整 JSON，而是通过 Server-Sent Events (SSE) 协议持续推送数据块（chunk）。每个 chunk 包含增量生成的文本片段。

📤
SSE 数据格式示例：
data: {"choices":[{"delta":{"content":"你"},"index":0}]}
data: {"choices":[{"delta":{"content":"好"},"index":0}]}
data: {"choices":[{"delta":{"content":"！"},"index":0}]}
data: [DONE] <-- 流结束标记
Python - 流式调用 (requests) 
import requests
import json

def stream_chat(message: str, model: str = "deepseek-chat"):
    """使用 SSE 流式读取 API 响应"""
    url = "https://api.deepseek.com/v1/chat/completions"
    headers = {
        "Authorization": f"Bearer {os.getenv('DEEPSEEK_API_KEY')}",
        "Content-Type": "application/json",
    }
    payload = {
        "model": model,
        "messages": [{"role": "user", "content": message}],
        "stream": True,     // 关键：开启流式
        "temperature": 0.7,
    }

    response = requests.post(url, headers=headers, json=payload, stream=True)
    response.raise_for_status()

    full_content = ""
    for line in response.iter_lines():
        if line:
            decoded = line.decode("utf-8")
            if decoded.startswith("data: "):
                data_str = decoded[6:]  // 去掉 "data: " 前缀
                if data_str == "[DONE]":
                    break       // 流结束
                data = json.loads(data_str)
                delta = data["choices"][0].get("delta", {})
                content = delta.get("content", "")
                if content:
                    print(content, end="", flush=True)  // 逐字符打印
                    full_content += content

    return full_content


# 使用示例
result = stream_chat("用生动的语言描述一下春天的公园")

5 错误码与异常处理

在实际生产环境中，完善的错误处理是必不可少的。以下是大模型 API 最常见的错误码及其应对策略：

HTTP 状态码错误码含义解决方案
401 invalid_api_key
authentication_error		 未授权 —— API Key 无效、过期或缺失 检查 .env 中 Key 是否正确，确认账户余额充足
429 rate_limit_exceeded 请求频率超出限额（RPM/TPM/TPD） 添加指数退避重试机制；升级套餐提高限额
429 insufficient_quota 账户额度耗尽 充值或检查用量统计页面
500 internal_server_error 服务器内部错误（厂商侧问题） 等待几秒后自动重试（建议最多 3 次）
503 service_unavailable 服务暂时不可用（维护/过载） 启用降级策略，切换备用模型或缓存历史回复
400 context_length_exceeded 输入 + 预估输出超过模型的上下文窗口上限 减少 messages 长度或降低 max_tokens；考虑摘要压缩
400 invalid_request_error 请求参数格式错误（如 messages 结构不合法） 检查 messages 是否 user/assistant 交替且以 user 结尾
Python - 带重试的封装函数 
import requests
import time
from typing import Optional

def call_llm_api(
    messages: list[dict],
    model: str = "deepseek-chat",
    base_url: str = "https://api.deepseek.com/v1",
    api_key: Optional[str] = None,
    max_retries: 3,
    stream: False,
) -> dict | str:
    """
    可复用的 LLM API 调用函数（带自动重试）

    Args:
        messages: 消息列表 [{"role": "user", "content": "..."}]
        model: 模型名称
        base_url: API 地址（支持切换不同厂商）
        api_key: API 密钥（不传则从环境变量读取）
        max_retries: 最大重试次数
        stream: 是否流式输出
    Returns:
        非流式时返回完整 JSON dict；流式时返回拼接后的字符串
    """
    url = f"{base_url.rstrip('/')}/chat/completions"
    headers = {
        "Authorization": f"Bearer {api_key or os.getenv('DEEPSEEK_API_KEY')}",
        "Content-Type": "application/json",
    }
    payload = {
        "model": model,
        "messages": messages,
        "temperature": 0.7,
        "max_tokens": 2048,
        "stream": stream,
    }

    for attempt in range(max_retries):
        try:
            resp = requests.post(url, headers=headers, json=payload, timeout=60)
            if resp.status_code == 200:
                return resp.json()
            elif resp.status_code == 429:
                wait = 2 ** attempt  // 指数退避: 1s, 2s, 4s
                print(f"限流中，等待 {wait}s 后重试... (第{attempt+1}次)")
                time.sleep(wait)
            elif resp.status_code == 401:
                raise PermissionError("API Key 无效或已过期")
            else:
                resp.raise_for_status()
        except requests.exceptions.Timeout:
            print(f"请求超时，正在重试 ({attempt+1}/{max_retries})...")
        except requests.exceptions.ConnectionError:
            print(f"连接失败，正在重试 ({attempt+1}/{max_retries})...")

    raise RuntimeError(f"API 调用失败，已重试 {max_retries} 次")


# ========== 使用示例 ==========
response = call_llm_api(
    messages=[
        {"role": "system", "content": "你是翻译专家"},
        {"role": "user",   "content": "将以下中文翻译成英文：人工智能正在改变世界"},
    ],
    model="deepseek-chat",
)

answer = response["choices"][0]["message"]["content"]
tokens_used = response["usage"]["total_tokens"]
print(f"回答: {answer}")
print(f"Token 用量: {tokens_used}")
