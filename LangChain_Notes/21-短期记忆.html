为什么需要 Memory？

大模型的"失忆"困境

大语言模型（LLM）本质上是无状态函数 — 每次 API 调用都是独立的计算过程。模型本身不会记住之前的对话内容，就像每轮对话都是"初次见面"。这导致多轮对话中出现严重的上下文断裂问题：

!
典型"金鱼记忆"场景
用户："我想查询订单 12345"
AI："订单 12345 已发货"
用户："什么时候能到？"
AI："请问您要查询哪个订单？"（完全忘了上一句！）

Memory 模块的核心价值：

  • 上下文延续 — 让 AI 能引用之前讨论的内容，理解代词指代关系
  • 个性化体验 — 记住用户偏好、名字等个性化信息
  • 多轮任务完成 — 逐步收集信息，完成复杂任务流程
  • 减少重复输入 — 不需要每次重复背景信息
*
核心原理
Memory 本质上是一个上下文管理中间件 — 在每次 LLM 调用前将历史消息注入 Prompt，在调用后将新的交互追加到历史记录中。模型并非真正"记住"，而是我们每次都把"记忆"重新拼在 Prompt 里让它重读一遍。
@

Memory 基类体系

BaseMemory 与 BaseChatMessageHistory

LangChain 的记忆系统建立在两大抽象基类之上，理解它们是掌握所有 Memory 类型的关键：

BaseMemory — 通用记忆逻辑层

定义了所有 Memory 组件必须实现的四大核心方法：

方法 作用 说明
memory_variables 获取变量键名列表 返回该 Memory 会向 Chain 注入哪些键名（如 "history"）
load_memory_variables(inputs) 加载记忆数据 根据当前输入，抽取相关记忆并返回字典格式
save_context(inputs, outputs) 保存上下文 将本轮的用户输入和模型输出存入记忆
clear() 清空记忆 清除所有已存储的记忆数据

BaseChatMessageHistory — 消息存储抽象层

专注于对话消息的增删查操作，是所有持久化后端的统一接口：

方法/属性 作用
add_messages(messages) 添加会话消息（HumanMessage、AIMessage 等）
messages (property) 获取当前所有历史消息列表
clear() 清空当前会话的所有消息
+
设计思想
无论消息存储在内存、文件还是数据库，核心操作都是"增、查、清"。通过抽象统一接口，不同存储方式的 Memory 可以无缝替换 — 这正是 LangChain 组件化设计的核心思想。
#

ConversationBufferMemory

缓冲区记忆 — 最基础的完整存储方案

ConversationBufferMemory 是最基础也最直观的记忆实现方式。它的核心原理非常简单：完整保存所有对话历史，不做任何删减或压缩，并在生成新响应时将全部历史作为上下文传递给 LLM。

Python 
from langchain_openai import ChatOpenAI
from langchain.memory import ConversationBufferMemory
from langchain.chains import ConversationChain

# 初始化 LLM 和 Memory
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
memory = ConversationBufferMemory(
    memory_key="chat_history",   # 自定义键名
    return_messages=True          # 返回 Message 对象而非字符串
)

# 构建对话链
chain = ConversationChain(llm=llm, memory=memory, verbose=True)

# 多轮对话测试
resp1 = chain.invoke({"input": "我叫小明，今年 25 岁"})
resp2 = chain.invoke({"input": "我叫什么名字？"})
# 输出: 你叫小明，今年 25 岁  成功记住！

关键参数详解

参数 类型 默认值 说明
memory_key str "history" 自定义记忆在 Prompt 中的键名，需与模板中的占位符匹配
return_messages bool False 设为 True 时返回 BaseMessage 对象列表；False 返回拼接字符串
input_key str "input" 用户输入在 inputs 字典中的键名
output_key str "output" 模型输出在 outputs 字典中的键名
i
return_messages=True vs False
当 return_messages=False（默认）：返回格式化字符串如 "Human: 你好\nAI: 你好呀!"
当 return_messages=True：返回 [HumanMessage(content='你好'), AIMessage(content='你好呀!')] 对象列表
推荐使用 True，因为与 ChatModel 配合更自然，便于后续处理。

内部存储结构

Data Structure 
# ConversationBufferMemory 内部存储格式示例{
    "chat_history": [
        {"role": "human",     "content": "你好，介绍一下自己"},
        {"role": "ai",         "content": "我是一个AI助手..."},
        {"role": "human",     "content": "那你能告诉我天气吗"},
        {"role": "ai",         "content": "请问您所在的城市是？"}
        # ... 更多对话按顺序追加
    ]
}

致命缺陷
Token 消耗随对话轮次线性增长！聊到 50 轮可能吃掉半个上下文窗口。长对话场景下极易超出模型的 Token 限制导致报错。

在 Chain 和 Agent 中使用 Memory

实际集成方式详解

方式一：ConversationChain（经典写法）

Python 
from langchain.chains import ConversationChain
from langchain.memory import ConversationBufferMemory
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
memory = ConversationBufferMemory(return_messages=True)

# 将 memory 作为参数传入 Chain
chain = ConversationChain(
    llm=llm,
    memory=memory,          # 核心：绑定 Memory
    verbose=True
)

# 之后每次 invoke 都会自动读写 memory
result = chain.invoke({"input": "你好"})

方式二：AgentExecutor + Memory（智能体场景）

Python 
from langchain.agents import initialize_agent, AgentType
from langchain.tools import Tool
from langchain.memory import ConversationBufferMemory

# 定义工具和 Memory
tools = [Tool(name="Calculator", func=lambda x: eval(x),
              description="用于数学计算")]

memory = ConversationBufferMemory(
    memory_key="chat_history",
    return_messages=True
)

# 创建带记忆的 Agent
agent = initialize_agent(
    tools=tools,
    llm=llm,
    agent=AgentType.CHAT_CONVERSATIONAL_REACT_DESCRIPTION,
    memory=memory,           # Agent 也支持 Memory
    verbose=True
)

agent.run("帮我算一下 123 * 456")
agent.run("刚才的结果加上 100 是多少？")  # 能记住上文！
o
Memory 工作闭环
Chain 执行前：load_memory_variables() 从 Memory 读取历史 注入 Prompt
Chain 执行中：LLM 根据完整上下文（含历史）生成响应
Chain 执行后：save_context() 将本次 input+output 存入 Memory
如此循环，形成完整的状态管理闭环。
!

短期记忆的局限性

重启即丢失 — 为什么需要持久化

默认情况下，所有 Memory 组件都将对话历史存储在进程内存（RAM）中。这意味着：

程序重启
Python 进程退出后，所有对话记录永久丢失
服务崩溃
异常宕机导致未保存的记忆全部消失
多实例部署
不同实例之间无法共享记忆状态
Token 爆炸
BufferMemory 随轮次线性增长 Token 消耗
!
