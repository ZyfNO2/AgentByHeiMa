1 大模型服务的三种形态

在开始调用 LLM API 之前，你需要先理解当前市场上三种主流的大模型服务形态。每种形态都有其独特的适用场景和权衡取舍：

☁️
云端 API
Cloud API
OpenAI / 百炼 / DeepSeek API
  • 即开即用，无需部署基础设施
  • 按量付费，灵活控制成本
  • 自动获得最新模型版本
  • 全球 CDN 加速，低延迟访问
  • 数据传输至第三方服务器
💻
开源部署
Self-Hosted / Local
Ollama / vLLM / TGI
  • 数据完全本地化，隐私安全
  • 无网络依赖，可离线运行
  • 一次部署，无限调用
  • 可自定义微调和优化
  • 需要 GPU 硬件投入与运维
🌐
平台托管
Managed Platform
AWS Bedrock / Azure OpenAI / Vertex AI
  • 企业级 SLA 与合规保障
  • 混合云部署，支持 VPC 私有网络
  • 统一账单，与企业云资源整合
  • 内置监控、日志、权限管理
  • 价格通常高于直接 API
对比维度云端 API开源部署平台托管
启动成本极低（注册即用）高（GPU 硬件）中（企业订阅）
数据隐私依赖服务商政策完全可控较高（VPC 隔离）
运维负担零运维全自主运维低（平台管理）
定制灵活性受限（仅参数层面）极高（可微调/量化）中等（部分支持微调）
适用规模原型 / 中小规模私有化 / 大规模大型企业
典型代表OpenAI API / DeepSeekOllama / vLLMAzure OpenAI / Bedrock
🌟
本课程的选择：我们将以云端 API为主要学习载体（DeepSeek + 百炼），原因有三——门槛最低（无需 GPU）、成本可控（新用户免费额度充足）、与 LangChain 集成最顺滑。后续课程也会介绍 Ollama 本地部署方案。

2 API 调用的基本流程

无论选择哪家服务商，调用 LLM API 的基本流程都是一致的。理解这个流程是后续所有实践操作的基础：

1
注册账号 & 获取 API Key
在目标平台（如 DeepSeek、百炼、OpenAI）注册开发者账号，进入控制台创建 API Key。这是你调用服务的「身份凭证」，务必妥善保管。
2
选择模型端点（Endpoint）
确定要调用的模型名称（如 deepseek-chat、gpt-4o-mini、qwen-plus）以及对应的 API 地址（Base URL）。不同模型的端点和能力各不相同。
3
构建请求（Messages + Parameters）
组装请求体：包含对话消息列表（system/user/assistant 角色）以及可选参数（temperature、max_tokens 等）。消息格式遵循 OpenAI 兼容标准。
4
发送 HTTP 请求
通过 POST 方法将请求发送到指定端点，Header 中携带 Authorization: Bearer YOUR_API_KEY 进行身份认证。
5
解析响应结果
从 JSON 响应中提取模型生成的文本内容（choices[0].message.content），同时可获取 token 用量统计信息用于成本追踪。
Python (requests) 
import requests
import json

# === 核心请求结构 ===
response = requests.post(
    "https://api.deepseek.com/chat/completions",  # Endpoint
    headers={
        "Authorization": f"Bearer {API_KEY}",     # 身份认证
        "Content-Type": "application/json",            # 内容类型
    },
    json={
        "model": "deepseek-chat",                    # 模型名称
        "messages": [                                   # 对话消息列表
            {"role": "system", "content": "你是一个有帮助的助手。"},
            {"role": "user",   "content": "你好！请介绍一下自己。"},
        ],
        "temperature": 0.7,                            # 创造性参数
        "max_tokens": 1024,                           # 最大输出长度
    },
)

result = response.json()
print(result["choices"][0]["message"]["content"])   # 提取回答
💡
关键认知：目前业界已形成事实上的 OpenAI API 兼容标准。DeepSeek、百炼、Ollama 等绝大多数服务商都兼容这一格式，这意味着你写好的代码只需更换 base_url 和 api_key 即可在不同平台间切换。LangChain 的价值之一就是进一步抽象了这层差异。

3 关键参数一览

API 调用中的参数直接影响模型的输出质量和行为特征。以下是四个最核心的参数详解：

model
模型标识符
指定要调用的具体模型。不同模型在能力、速度、价格上差异巨大。选择时需权衡任务复杂度与成本预算。
示例: "deepseek-chat" | "gpt-4o-mini" | "qwen-plus"
messages
对话消息列表
核心输入参数，由一组消息对象组成。每个消息包含 role（system/user/assistant）和 content（文本内容）。多轮对话通过拼接历史消息实现。
结构: [{role:"system",content:"..."}, ...]
temperature
温度参数（创造性 vs 确定性）
控制输出随机性的核心参数。值越低输出越确定性/一致；值越高输出越创造性/多样。范围 [0, 2]，默认 1.0。
0.0 = 精确回答 | 0.7 = 平衡 | 1.5+ = 高创意
max_tokens
最大输出 Token 数
限制模型单次响应的最大长度（以 Token 为单位）。设置过短可能截断回答，过长则浪费 Token 和增加延迟。
建议: 简答 256-512 | 详答 1024-4096
top_p
核采样（Nucleus Sampling）
另一种控制随机性的方式。只从累积概率达到 top_p 的最小 token 集合中采样。常与 temperature 二选一使用，不建议同时调整。
范围 (0, 1] | 默认 1.0 | 推荐 0.9-0.95
stream
流式输出开关
设为 true 时，模型会逐 token 返回结果（Server-Sent Events），而非等待完整生成后一次性返回。对聊天体验至关重要。
false = 一次性返回 | true = 流式逐字返回
⚠️
Temperature 使用建议：
• 事实性问答 / 数据提取 / 代码生成 → temperature 设为 0.0 ~ 0.3（追求准确一致）
• 日常对话 / 通用助手 → temperature 设为 0.5 ~ 0.7（平衡自然与准确）
• 创意写作 / 头脑风暴 → temperature 设为 0.8 ~ 1.2（鼓励多样性输出）

4 计费模式说明

理解计费机制对于控制项目成本至关重要。几乎所有 LLM API 都采用基于 Token 的计量付费模式：

Token 计费基础

💰
什么是 Token？Token 是 LLM 处理文本的最小单位。大致上：
• 英文：约 4 个字符 ≈ 1 个 Token（约 0.75 词 ≈ 1 Token）
• 中文：约 1~2 个汉字 ≈ 1 个 Token
• 费用公式：总费用 = 输入Token数 x 输入单价 + 输出Token数 x 输出单价
• 注意：输出 Token 通常比输入 Token 贵 2~4 倍（因为涉及生成计算）
模型输入单价输出单价定位
GPT-4o$2.5 / 1M tokens$10 / 1M tokens旗舰级通用模型
GPT-4o-mini$0.15 / 1M tokens$0.6 / 1M tokens高性价比轻量模型
DeepSeek-V3¥0.5 / 1M tokens¥2.0 / 1M tokens国产高性价比（约 GPT-4 级）
DeepSeek-R1¥4.0 / 1M tokens¥16.0 / 1M tokens推理增强模型
Qwen-Turbo¥0.3 / 1M tokens¥0.6 / 1M tokens通义千问极速版
Qwen-Plus¥0.8 / 1M tokens¥2.0 / 1M tokens通义千问增强版

成本控制策略

🔌
Prompt 缓存 对重复出现的 System Prompt 和长上下文使用缓存，避免重复计费输入 Token
📤
上下文压缩 在送入 LLM 前对长文档进行摘要压缩，减少实际输入 Token 数量
📈
模型分层路由 简单任务用便宜模型（mini/turbo），复杂任务才升级到旗舰模型
📄
用量监控告警 设置月度预算上限和超额预警，避免意外产生高额账单
