## 1. 时间旅行（Time Travel）概述

### 1.1 什么是时间旅行？

在 LangGraph 的语境中，**时间旅行（Time Travel）** 指的是：

> **回溯图的执行历史，回到之前的某个状态快照（Checkpoint），并可以从该点重新执行或修改后继续执行。**

这不是科幻概念，而是基于 LangGraph 的 **Checkpoint（检查点）机制** 实现的实用功能：

```
传统程序执行：
时间 → t0 → t1 → t2 → t3 → t4
        ↓    ↓    ↓    ↓    ↓
       输入  节点A 节点B 节点C  输出
                         ↑
                    只能看到最终结果
                    无法回到中间状态

LangGraph 时间旅行：
时间 → t0 → t1 → t2 → t3 → t4
        ↓    ↓    ↓    ↓    ↓
      [CP0] [CP1] [CP2] [CP3] [CP4]  ← 每步都有Checkpoint
              ↑              ↑
         可以回到这里     或从这里继续
```

### 1.2 为什么需要时间旅行？

| 场景 | 描述 | 价值 |
|------|------|------|
| **错误纠正** | Agent 理错了用户意图，走偏了方向 | 回退几步，修正后重来 |
| **分支探索** | 想尝试不同的决策路径看哪个结果更好 | 从分岔点出发，探索不同选项 |
| **调试分析** | 在某个节点观察不同的输入会产生什么输出 | 修改输入参数，对比结果 |
| **A/B 测试** | 同一输入在不同策略下的表现对比 | 从同一 Checkpoint 出发，应用不同策略 |
| **学习演示** | 向他人展示 Agent 的决策过程 | 逐步回放每一步的状态变化 |

### 1.3 前置条件：Checkpointer

时间旅行功能依赖于 **Checkpointer** —— 一个负责持久化保存执行状态的组件。

```python
from langgraph.checkpoint.memory import MemorySaver
from langgraph.checkpoint.sqlite import SqliteSaver
from langgraph.checkpoint.postgres import PostgresSaver

# 方式1: 内存存储（开发/测试用）
checkpointer = MemorySaver()

# 方式2: SQLite 存储（轻量级持久化）
checkpointer = SqliteSaver.from_conn_string(":memory:")

# 方式3: PostgreSQL 存储（生产环境）
import psycopg
conn = psycopg.connect("postgresql://user:pass@localhost:5432/langgraph")
checkpointer = PostgresSaver(conn)
checkpointer.setup()  # 初始化表结构

# 编译图时传入 checkpointer
app = graph.compile(checkpointer=checkpointer)
```

**Checkpointer 对比**：

| 类型 | 持久化 | 适用场景 | 并发支持 |
|------|--------|---------|---------|
| `MemorySaver` | 否（进程内存） | 开发、测试、演示 | 单进程 |
| `SqliteSaver` | 是（本地文件） | 单机应用、原型验证 | 有限 |
| `PostgresSaver` | 是（远程数据库） | 生产环境、多实例部署 | 完整支持 |

## 2. Checkpoint（检查点）机制详解

### 2.1 Checkpoint 的工作原理

LangGraph 在每次节点执行前后自动创建 Checkpoint：

```
执行流程与 Checkpoint 生成时机：

START
  │
  ├──→ [Checkpoint 0] ←── 初始状态（用户输入）
  │
  ▼
Node A 执行前
  │
  ├──→ [Checkpoint 0.5] ←── Node A 的输入状态（可选）
  │
  ▼
Node A 执行中...
  │
  ▼
Node A 执行后
  │
  ├──→ [Checkpoint 1] ←── Node A 的输出状态
  │
  ▼ (通过 Edge)
Node B 执行前
  │
  ├──→ [Checkpoint 1.5]
  │
  ▼
Node B 执行后
  │
  ├──→ [Checkpoint 2] ←── Node B 的输出状态
  │
  ▼
...以此类推
```

### 2.2 Checkpoint 中保存的内容

每个 Checkpoint 是一个完整的**状态快照**，包含：

```python
@dataclass
class Checkpoint:
    # 元数据
    id: str                          # 唯一标识符
    thread_id: str                  # 所属线程
    parent_checkpoint_id: str | None # 父 checkpoint（形成链表）
    timestamp: datetime             # 创建时间

    # 状态数据
    channel_values: dict            # 各通道（字段）的当前值
    channel_versions: dict          # 版本号（用于冲突检测）

    # 执行元数据
    pending_writes: list            # 待写入的更新
    metadata: dict                  # 自定义元数据（source、writer、step等）

    # 配置
    config: RunnableConfig          # 当前的 config
```

### 2.3 Checkpoint 链结构

Checkpoints 形成一个**有向无环图（DAG）**或**链表**结构：

```
Thread: "conversation-001"

CP0 (初始状态)
  │ values: {messages: [Human], query: "..."}
  │
  ├─→ CP1 (agent 执行后)
  │     │ values: {messages: [Human, AI(with_tools)], ...}
  │     │
  │     ├─→ CP2 (tools 执行后)
  │     │     │ values: {messages: [Human, AI, ToolMsg], ...}
  │     │     │
  │     │     └─→ CP3 (agent 第二次执行后)
  │     │           │ values: {messages: [..., AI(final)], ...}
  │     │           └─→ END
  │     │
  │     └─→ CP2b (从 CP1 回退后的另一条路径)
  │           (时间旅行的分支)
  │
  └─→ CP1b (替代路径的起点)
        ...
```

## 3. 时间旅行的 API

### 3.1 获取历史状态

#### get_state_history()

这是最核心的时间旅行 API，用于获取指定 thread 的所有历史 Checkpoint：

```python
import asyncio
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph.message import add_messages
from typing import TypedDict, Annotated
from langchain_core.messages import HumanMessage, AIMessage

# ============================================================
# 设置：构建一个简单的 ReAct Agent
# ============================================================

class AgentState(TypedDict):
    messages: Annotated[list, add_messages]

def agent_node(state):
    """模拟 Agent 节点"""
    return {"messages": [AIMessage(content=f"Agent 回复第 {len(state['messages'])} 轮")]}

def tool_node(state):
    """模拟工具节点"""
    return {"messages": [AIMessage(content="工具执行结果")]}

graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", tool_node)

graph.add_edge(START, "agent")
graph.add_conditional_edges(
    "agent",
    {"tools": "tools", END: END},
    lambda s: "tools" if len(s["messages"]) < 4 else END
)
graph.add_edge("tools", "agent")

checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)

config = {"configurable": {"thread_id": "demo-time-travel"}}

# ============================================================
# 执行 Agent（产生多个 Checkpoint）
# ============================================================

async def demo_time_travel():
    # 执行 Agent
    result = await app.ainvoke(
        {"messages": [HumanMessage(content="测试查询")]},
        config=config
    )

    print(f"最终消息数: {len(result['messages'])}")

    # ============================================================
    # 核心API：获取完整的历史状态链
    # ============================================================
    print("\n" + "=" * 60)
    print("获取 Checkpoint 历史")
    print("=" * 60)

    state_history = list(app.get_state_history(config))

    print(f"\n总共有 {len(state_history)} 个 Checkpoint:\n")

    for i, state in enumerate(state_history):
        cp = state.config.get("configurable", {})
        checkpoint_id = cp.get("checkpoint_id", "")[:8]

        # 获取元数据
        metadata = state.metadata or {}
        source = metadata.get("source", "unknown")
        step = metadata.get("step", "?")
        writes = metadata.get("writes", {})

        # 显示信息
        print(f"CP[{i}] ID:{checkpoint_id}...")
        print(f"  来源: {source}")
        print(f"  步骤: {step}")
        print(f"  下一步: {state.next}")  # None 表示已结束
        print(f"  消息数: {len(state.values.get('messages', []))}")

        if state.next:
            print(f"  ⏸️  此处可恢复执行")

        print()

# asyncio.run(demo_time_travel())
```

### 3.2 访问特定历史状态

```python
async def inspect_specific_checkpoint():
    config = {"configurable": {"thread_id": "demo-time-travel"}}

    # 获取所有历史
    history = list(app.get_state_history(config))

    # ============================================================
    # 访问特定的 Checkpoint
    # ============================================================

    # 方式1: 通过索引访问（最新的是 [0]，最老的是 [-1]）
    latest_state = history[0]           # 最新的状态
    oldest_state = history[-1]          # 最早的状态（初始输入）

    # 方式2: 找到特定节点的状态
    target_state = None
    for state in history:
        # 检查是否是 agent 节点执行后的状态
        if state.metadata.get("writes", {}).get("agent"):
            target_state = state
            break

    if target_state:
        print("找到目标 Checkpoint:")
        print(f"  ID: {target_state.config['configurable']['checkpoint_id'][:12]}...")
        print(f"  State values:")
        for key, value in target_state.values.items():
            if key == "messages":
                print(f"    {key}: [{len(value)} 条消息]")
            else:
                print(f"    {key}: {value}")
```

### 3.3 从历史 Checkpoint 继续执行

```python
async def resume_from_history():
    """
    从历史的某个 Checkpoint 点继续执行
    """
    config = {"configurable": {"thread_id": "demo-time-travel"}}
    history = list(app.get_state_history(config))

    # ============================================================
    # 选择要回退到的 Checkpoint
    # 例如：回退到第 2 个 Checkpoint（agent 第一次执行后）
    # ============================================================

    target_checkpoint = history[-3]  # 选择一个中间状态
    target_config = target_checkpoint.config

    print(f"回退到 Checkpoint: {target_config['configurable']['checkpoint_id'][:12]}...")
    print(f"当时的状态:")
    print(f"  消息数: {len(target_checkpoint.values['messages'])}")
    print(f"  下一个待执行: {target_checkpoint.next}")

    # ============================================================
    # 从该 Checkpoint 继续（时间旅行！）
    # ============================================================

    print("\n>>> 从此点继续执行...\n")

    # 关键：使用历史 checkpoint 的 config 作为新调用的 config
    new_result = await app.ainvoke(
        None,  # 不需要新的输入，使用已有状态
        config=target_config
    )

    print(f"执行完成!")
    print(f"最终消息数: {len(new_result['messages'])}")

# asyncio.run(resume_from_history())
```

## 4. 更新历史状态（State Editing）

时间旅行不仅是"只读"地查看历史，还可以**修改**历史状态后继续执行。

### 4.1 update_state() 方法

```python
async def edit_and_continue():
    """
    编辑历史状态后继续执行
    """
    config = {"configurable": {"thread_id": "edit-demo"}}

    # 先执行一轮
    initial_result = await app.ainvoke(
        {"messages": [HumanMessage(content="原始问题")]},
        config=config
    )

    print("初始执行完成")
    print(f"Agent 回答: {initial_result['messages'][-1].content}\n")

    # ============================================================
    # 获取历史
    # ============================================================

    history = list(app.get_state_history(config))

    # 找到我们想修改的那个 Checkpoint
    # 比如：在 agent 第一次思考之后、工具执行之前
    target_state = None
    for state in history:
        if state.next and "tools" in state.next:
            target_state = state
            break

    if not target_state:
        print("未找到合适的 Checkpoint")
        return

    target_config = target_state.config

    print(f"选中的 Checkpoint:")
    print(f"  当前消息:")
    for msg in target_state.values["messages"]:
        print(f"    [{msg.type}] {msg.content[:50]}...")

    # ============================================================
    # 编辑状态！
    # ============================================================

    print("\n>>> 编辑状态: 注入额外指令\n")

    # 使用 update_state 修改指定 Checkpoint 处的状态
    await app.aupdate_state(
        target_config,
        {
            # 追加一条新消息（作为系统提示注入）
            "messages": [
                {
                    "role": "system",
                    "content": "[人工干预] 请用更简洁的语言回答，不超过100字。"
                }
            ]
        },
        as_node="human_intervention"  # 标记是谁做的修改
    )

    print("状态已更新!")

    # ============================================================
    # 从修改后的状态继续执行
    # ============================================================

    print("\n>>> 从修改后的状态继续执行\n")

    final_result = await app.ainvoke(None, config=target_config)

    print("最终结果:")
    print(final_result["messages"][-1].content)

# asyncio.run(edit_and_continue())
```

```python
    # ========== 第二阶段：查看历史 ==========

    print("阶段2: 查看 Checkpoint 历史")

    # ========== 第三阶段：定位错误的 Checkpoint ==========
    print("\n" + "=" * 60)
    print("阶段3: 定位并修复错误")
    print("=" * 60)

    # 假设我们在工具执行后的 Checkpoint 进行修复
    # 找到 tools 节点刚执行完的状态
    tools_checkpoint = None
    for state in history:
        metadata = state.metadata or {}
        writes = metadata.get("writes", {})
        if "tools" in writes:
            tools_checkpoint = state
            break

    if tools_checkpoint:
        tools_config = tools_checkpoint.config

        print(f"找到工具执行后的 Checkpoint")
        print(f"当时的工具结果:")

        # 显示工具返回的消息
        for msg in tools_checkpoint.values["messages"]:
            if hasattr(msg, 'name') and msg.name:  # ToolMessage
                print(f"  📦 [{msg.name}] {msg.content[:100]}...")

        # ========== 第四阶段：修改工具结果 ==========
        print("\n>>> 修正工具结果（模拟正确的天气数据）\n")

        # 找到需要修改的 ToolMessage 并替换其内容
        messages = tools_checkpoint.values["messages"]
        corrected_messages = []

        for msg in messages:
            if hasattr(msg, 'name') and msg.name == "weather":
                # 替换为正确的天气数据
                corrected_messages.append({
                    "role": "tool",
                    "name": "weather",
                    "tool_call_id": msg.tool_call_id,
                    "content": "北京今天: 晴转多云, 气温18-26°C, 空气质量优"
                })
            else:
                corrected_messages.append(msg)

        # 应用更新
        await app.aupdate_state(
            tools_config,
            {"messages": corrected_messages},
            as_node="human_correction"
        )

        print("✓ 状态已更新为正确的天气数据")

        # ========== 第五阶段：从修正点继续执行 ==========
        print("\n" + "=" * 60)
        print("阶段4: 从修正点重新执行")
        print("=" * 60)

        corrected_result = await app.ainvoke(None, config=tools_config)

        print("\n修正后的 Agent 回答:")
        print(corrected_result["messages"][-1].content)
```

## 5. 实际应用场景

### 5.1 场景一：Agent 纠错

**问题**：Agent 在某一步理解错了用户意图，导致后续所有步骤都跑偏了。

**解决方案**：回退到出错的那一步，修正理解后重新执行。

```python
async def agent_error_correction():
    """
    Agent 纠错工作流
    """

    # 用户问："帮我订一张去上海的机票"
    # 但 Agent 错误理解为："去北京的机票"
    # 我们需要回退并纠正

    config = {"configurable": {"thread_id": "error-correction"}}

    # 1. 执行（产生错误结果）
    bad_result = await app.ainvoke(
        {"messages": [HumanMessage(content="订去上海的机票")]},
        config=config
    )
    # Agent 可能搜索了北京航班...

    # 2. 检测到错误
    print("检测到: Agent 搜索了北京而非上海")

    # 3. 回退到理解意图的那一步
    history = list(app.get_state_history(config))
    understanding_checkpoint = find_understanding_step(history)

    # 4. 修正用户的原始输入（添加澄清）
    await app.aupdate_state(
        understanding_checkpoint.config,
        {
            "messages": [
                {
                    "role": "user",
                    "content": "订去上海的机票（注意：是上海，不是北京！）"
```

### 5.3 场景三：交互式调试

**问题**：开发时需要逐步检查每个节点的输入输出。

**解决方案**：结合 HITL 断点和时间旅行进行交互式调试。

```python
async def interactive_debug():
    """
    交互式调试模式
    """
    config = {"configurable": {"thread_id": "debug-session"}}

    # 启用断点
    debug_app = graph.compile(
        checkpointer=MemorySaver(),
        interrupt_before=["agent", "tools", "final"]  # 每个节点前都暂停
    )

    try:
        await debug_app.ainvoke(input_data, config=config)
    except Exception:
        pass  # 在第一个断点处暂停

    while True:
        current = await debug_app.aget_state(config)

        if not current.next:
            print("执行完毕")
            break

        # 显示当前状态
        print_debug_info(current)

        # 等待开发者命令
        command = input("\n命令 (continue/step/edit/back/quit): ").strip().lower()

        match command:
            case "continue":
                # 正常继续到下一个断点
                await debug_app.ainvoke(Command(resume=True), config=config)

            case "step":
                # 单步执行
                await debug_app.ainvoke(Command(resume=True), config=config)

            case "edit":
                # 编辑当前状态
                field = input("要编辑的字段: ")
                value = input("新值: ")
                await debug_app.aupdate_state(
                    config, {field: value}, as_node="debugger"
                )

            case "back":
                # 回退 N 步
                steps = int(input("回退几步? "))
                history = list(debug_app.get_state_history(config))
                if steps < len(history):
                    target = history[steps]
                    config = target.config  # 切换到历史 config
                    print(f"已回退到: {target.config['configurable']['checkpoint_id'][:12]}")

            case "quit":
                break
```

## 6. 局限性与注意事项

### 6.1 技术限制

| 限制 | 说明 | 影响 |
|------|------|------|
| **必须配置 Checkpointer** | 没有 Checkpointer 就没有历史记录 | 开发时别忘了配 |
| **内存开销** | 每个 Checkpoint 都保存完整状态副本 | 长对话可能占用大量存储 |
| **版本一致性** | 图的定义修改后，旧 Checkpoint 可能不兼容 | 部署新版本时要考虑迁移 |
| **并发安全** | 同一 thread 的时间旅行可能导致竞争条件 | 需要锁机制或串行化 |

### 6.2 存储开销估算

```python
def estimate_storage(num_threads, avg_steps, avg_state_size_kb):
    """
    估算 Checkpoint 存储需求

    Args:
        num_threads: 并发线程数
        avg_steps: 平均每线程执行步数
        avg_state_size_kb: 平均每个 Checkpoint 大小（KB）
    """
    checkpoints_per_thread = avg_steps * 2  # 每步前后各一个
    total_checkpoints = num_threads * checkpoints_per_thread
    total_size_mb = (total_checkpoints * avg_state_size_kb) / 1024

    print(f"存储估算:")
    print(f"  总 Checkpoint 数: {total_checkpoints:,}")
    print(f"  总存储大小: ~{total_size_mb:.1f} MB")
    print(f"  每日增量（假设1000次会话）: ~{1000 * checkpoints_per_thread * avg_state_size_kb / 1024:.1f} MB/day")

# 示例
estimate_storage(
    num_threads=1000,      # 1000个并发会话
    avg_steps=10,         # 平均每会话10步
    avg_state_size_kb=50   # 每个Checkpoint约50KB
)
# 输出: 约 98 MB / 天
```

#### 6.3.1 Checkpoint 清理策略

```python
from datetime import datetime, timedelta

def cleanup_old_checkpoints(checkpointer, max_age_days=30):
    """
    定期清理过期的 Checkpoint
    """
    cutoff = datetime.now() - timedelta(days=max_age_days)
    count = 0

    for thread_id in checkpointer.list_threads():
        for checkpoint in checkpointer.list_checkpoints(thread_id):
            if checkpoint.timestamp < cutoff:
                checkpointer.delete_checkpoint(thread_id, checkpoint.id)
                count += 1

    print(f"已清理 {count:,} 个过期 Checkpoint")
```

#### 6.3.2 权限控制

```python
class TimeTravelAuthMiddleware:
    """
    时间旅行权限控制中间件
    """

    ALLOWED_ROLES = {"admin", "developer", "auditor"}

    def __init__(self, app, auth_service):
        self.app = app
        self.auth = auth_service

    async def aget_state_history(self, config, user_role):
        """只有授权角色才能查看历史"""
        if user_role not in self.ALLOWED_ROLES:
            raise PermissionError("无权访问执行历史")
        return self.app.get_state_history(config)

    async def aupdate_state(self, config, updates, user_role, reason):
        """记录所有状态修改"""
        if user_role not in self.ALLOWED_ROLES:
            raise PermissionError("无权修改历史状态")

        # 记录审计日志
        audit_log = {
            "timestamp": datetime.now().isoformat(),
            "user_role": user_role,
            "thread_id": config["configurable"]["thread_id"],
            "checkpoint_id": config["configurable"].get("checkpoint_id"),
            "updates": str(updates),
            "reason": reason
        }
        self.auth.log_audit(audit_log)

        # 执行实际更新
        return await self.app.aupdate_state(config, updates)
```

### 6.4 常见问题排查

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| `get_state_history()` 返回空列表 | 未配置 Checkpointer | 编译时传入 checkpointer |
| 找不到目标 Checkpoint | Thread ID 不匹配 | 确保使用相同的 thread_id |
| `update_state()` 无效 | Reducer 行为不符合预期 | 检查字段的 Annotated 定义 |
| 状态更新后执行异常 | 图定义已变更但 Checkpoint 是旧格式 | 清理旧 Checkpoint 或做迁移 |
| 存储爆满 | 未设置清理策略 | 配置 TTL 自动过期 |

## 8. 本章小结

本章深入学习了 LangGraph 的时间旅行与状态编辑功能，核心要点包括：

1. **核心概念**：时间旅行是基于 Checkpoint 机制的强大功能，允许回溯图的执行历史到任意状态快照

2. **前置条件**：必须配置 Checkpointer（MemorySaver/SqliteSaver/PostgresSaver），它负责持久化保存每个节点的执行状态

3. **关键 API**：
   - `get_state_history(config)`：获取完整的 Checkpoint 历史链表
   - `ainvoke(None, config=target_config)`：从指定的历史 Checkpoint 继续执行
   - `aupdate_state(config, updates)`：修改历史 Checkpoint 的状态

4. **State Editing**：不仅可以查看历史，还能修改后重新执行，适用于纠错、分支探索等场景

5. **实战价值**：
   - **纠错**：Agent 理解偏差时回退修正
   - **分支探索**：从同一分岔点尝试不同路径
   - **A/B 测试**：同一输入在不同策略下的效果对比
   - **交互式调试**：结合断点的逐步调试体验

6. **注意事项**：生产环境需关注存储开销、权限控制、Checkpoint 清理策略和并发安全
