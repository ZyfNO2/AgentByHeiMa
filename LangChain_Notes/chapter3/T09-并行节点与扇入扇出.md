## 1. 为什么需要并行执行？

### 1.1 串行执行的痛点

在构建 Agent 系统时，经常会遇到这样的场景：需要对**多个独立任务**分别进行处理。如果采用串行方式逐个执行，总耗时等于所有任务耗时之和：

```
任务A (2s) → 任务B (3s) → 任务C (2s) = 总计 7s
```

而当这些任务之间**没有依赖关系**时，完全可以让它们同时执行：

```
任务A (2s) ─┐
任务B (3s) ─┼→ 汇总 = 总计 max(2, 3, 2) = 3s
任务C (2s) ─┘
```

### 1.2 典型并行场景

| 场景 | 描述 | 并行收益 |
|------|------|----------|
| **多源信息搜索** | 同时查询 Google、Bing、学术数据库 | 耗时取决于最慢的源 |
| **批量文档分析** | 对 N 个文档分别做摘要/分类 | 近似 O(1) 而非 O(N) |
| **多模型对比** | 同时用不同 LLM 回答同一问题 | 并排比较输出质量 |
| **多角度评估** | 从安全性、准确性、流畅度等维度同时评估 | 一次运行获得全面评估 |

### 1.3 LangGraph 的并行能力

LangGraph 作为基于图结构的 Agent 框架，**原生支持节点级并行执行**。其核心机制是：

- 图的拓扑结构天然表达了任务的依赖关系
- 无依赖的节点可以被调度器并发执行
- 通过 `Send` 对象和条件边实现灵活的 Fan-out / Fan-in 控制

## 2. Fan-out（扇出）：并行启动多个节点

### 2.1 核心概念

**Fan-out（扇出）**是指从一个路由节点出发，**同时启动多个目标节点**并行执行的过程。在 LangGraph 中，主要通过 `Send` 对象来实现。

### 2.2 Send 对象详解

`Send` 是 LangGraph 中用于声明"发送到某个节点并携带特定数据"的核心类：

```python
from langgraph.constants import Send

# Send 的基本结构
Send(
    "target_node_name",   # 目标节点名称（字符串）
    {"key": value, ...}   # 传递给该节点的状态数据（字典）
)
```

**关键特性**：
- 每个 `Send` 实例指向**一个**目标节点
- 可以携带**不同的数据**给不同节点
- 路由函数返回 `Send` 列表时，所有 Send 目标**并行启动**

### 2.3 基础 Fan-out 示例

```python
from typing import Annotated, TypedDict, List
from langgraph.graph import StateGraph, START, END, add_messages
from langgraph.constants import Send

# ==================== 定义 State ====================
class OverallState(TypedDict):
    topic: str                    # 研究主题
    results: List[str]            # 各研究者的结果列表
    final_report: str             # 最终汇总报告

class ResearcherState(TypedDict):
    topic: str                    # 当前研究者关注的话题
    # results 由 reducer 自动追加到父级 State

def reduce_results(left: List[str], right: List[str]) -> List[str]:
    """Reducer: 合并结果列表"""
    if not left:
        return right
    if not right:
        return left
    return left + right

# 使用 Annotated 类型声明 reducer
class ResearcherOutputState(TypedDict):
    results: Annotated[List[str], reduce_results]

# ==================== 定义各节点 ====================
def router(state: OverallState):
    """路由节点：Fan-out 到多个并行研究者"""
    topic = state["topic"]
    return [
        Send("researcher_web", {"topic": topic}),
        Send("researcher_academic", {"topic": topic}),
        Send("researcher_code", {"topic": topic}),
    ]

def researcher_web(state: ResearcherState):
    """Web 搜索专家"""
    # 这里实际会调用搜索工具/LLM
    result = f"[Web搜索] 关于'{state['topic']}'的网络资料摘要..."
    return {"results": [result]}

def researcher_academic(state: ResearcherState):
    """学术检索专家"""
    result = f"[学术检索] 关于'{state['topic']}'的论文综述..."
    return {"results": [result]}

def researcher_code(state: ResearcherState):
    """代码库搜索专家"""
    result = f"[代码库] 关于'{state['topic']}'的开源项目分析..."
    return {"results": [result]}

def synthesizer(state: OverallState):
    """汇总节点：Fan-in 点"""
    all_results = "\n".join(state["results"])
    report = f"综合报告（{state['topic']}）:\n{all_results}"
    return {"final_report": report}

# ==================== 构建图 ====================
graph = StateGraph(OverallState)

# 添加节点
graph.add_node("router", router)
graph.add_node("researcher_web", researcher_web)
graph.add_node("researcher_academic", researcher_academic)
graph.add_node("researcher_code", researcher_code)
graph.add_node("synthesizer", synthesizer)

# 添加边
graph.add_edge(START, "router")
# 关键：条件边 + Send 实现 Fan-out
graph.add_conditional_edges(
    "router",
    router,                          # 路由函数返回 [Send, Send, ...]
    ["researcher_web", "researcher_academic", "researcher_code"],  # 允许的目标节点列表
)
# 所有研究者完成后 → 汇总（Fan-in）
graph.add_edge("researcher_web", "synthesizer")
graph.add_edge("researcher_academic", "synthesizer")
graph.add_edge("researcher_code", "synthesizer")
graph.add_edge("synthesizer", END)

# 编译
app = graph.compile()

# ==================== 运行 ====================
result = app.invoke({"topic": "LangGraph 并行执行机制"})
print(result["final_report"])
```

### 2.4 动态 Fan-out：根据输入决定并行数量

有时候并行节点的数量不是固定的，而是由输入动态决定的：

```python
def dynamic_router(state: OverallState):
    """
    动态 Fan-out：根据 sources 列表的长度决定启动多少个并行节点
    """
    sources = state.get("sources", ["default_source"])
    sends = []
    for i, source in enumerate(sources):
        sends.append(Send(
            "search_worker",
            {"source_name": source, "query": state["query"], "worker_id": i}
        ))
    return sends
```

这种模式在以下场景中特别有用：
- 用户提供了 N 个文档，需要分别处理
- 配置了 M 个搜索引擎，需要全部调用
- 数据库分片查询，每个分片独立检索

## 3. Fan-in（扇入）：合并并行结果

### 3.1 核心概念

**Fan-in（扇入）**是指多个并行分支**汇聚到一个共同的后继节点**的过程。在 LangGraph 中：

- 当一个节点有**多个前驱节点**时，它是一个隐式的 Fan-in 点
- LangGraph 的运行时会**自动等待所有前驱分支完成**后，才启动该节点
- 汇总节点接收的是**经过合并后的完整 State**

### 3.2 Fan-in 的自动等待机制

```
        ┌→ researcher_a ─┐
router ─┼→ researcher_b ─┼→ synthesizer (自动等a/b/c都完成)
        └→ researcher_c ─┘
```

上面的图中，`synthesizer` 节点有 3 条入边。LangGraph 保证：

1. **屏障同步（Barrier Synchronization）**：`synthesizer` 在 `researcher_a`、`researcher_b`、`researcher_c` **全部完成后**才会被调度
2. **State 合并**：各分支对 State 的更新会按照 **reducer 规则**合并后传递给 `synthesizer`

### 3.3 Reducer 控制合并策略

Fan-in 时最关键的问题是：**多个分支都更新同一个 State 字段时，如何合并？**

这通过 TypedDict 中字段的 `Annotated` 类型 + **reducer 函数**来控制：

```python
from typing import Annotated

# ====== 策略1：追加合并（适合列表类型）======
def append_reducer(existing, new):
    if existing is None:
        return [new] if not isinstance(new, list) else new
    if isinstance(existing, list) and isinstance(new, list):
        return existing + new
    return existing + [new]

class StateWithList(TypedDict):
    results: Annotated[list, append_reducer]
    # 多个分支各自 append → 最终得到拼接后的完整列表


# ====== 策略2：最后写入获胜（Last-Write-Wins）======
class StateWithLWW(TypedDict):
    answer: str  # 无 reducer → 默认最后一个写入的值覆盖前面的


# ====== 策略3：自定义聚合（如投票、平均等）======
def vote_reducer(existing, new):
    """投票聚合：统计出现次数最多的值"""
    from collections import Counter
    votes = (existing or []) + ([new] if not isinstance(new, list) else new)
    return Counter(votes).most_common(1)[0][0]


# ====== 策略4：求和聚合 ======
def sum_reducer(existing, new):
    return (existing or 0) + (new or 0)

class StateWithSum(TypedDict):
    total_score: Annotated[int, sum_reducer]
```

### 3.4 Reducer 执行顺序保证

LangGraph 对 reducer 的执行有以下保证：

| 特性 | 说明 |
|------|------|
| **确定性** | 同样的输入和图结构，reducer 结果是确定性的 |
| **原子性** | 单个分支的 State 更新是原子的 |
| **有序性** | 分支完成的顺序不影响最终结果（对于可交换的 reducer） |

## 4. 并行的两种实现方式

### 4.1 方式对比

| 特性 | **Send 对象方式** | **map 条件方式** |
|------|-------------------|------------------|
| **语法** | `return [Send("node", data)]` | `{"a": node_a, "b": node_b}` |
| **灵活性** | 高 — 可携带不同数据给不同节点 | 中 — 各分支共享相同输入 |
| **动态性** | 支持动态数量的并行分支 | 通常固定数量的分支 |
| **推荐度** | **推荐用于生产环境** | 适合简单场景快速原型 |
| **底层原理** | 显式创建子线程 | 语法糖，内部转换为 Send |

### 4.2 map 条件方式（语法糖）

当需要将同一个输入分发到**固定的几个节点**时，可以使用更简洁的条件映射语法：

```python
# 方式一：使用 Send（显式）
def router_with_send(state):
    return [
        Send("analyzer_a", {"doc": state["doc"]}),
        Send("analyzer_b", {"doc": state["doc"]}),
        Send("analyzer_c", {"doc": state["doc"]}),
    ]

graph.add_conditional_edges("splitter", ["a", "b", "c"], router_with_send)


# 方式二：使用 map 条件（简洁）
graph.add_conditional_edges(
    "splitter",
    {
        "analyzer_a": analyzer_a_node,
        "analyzer_b": analyzer_b_node,
        "analyzer_c": analyzer_c_node,
    },
    lambda state: ["analyzer_a", "analyzer_b", "analyzer_c"],  # 返回节点名列表
)
```

**注意**：方式二中，lambda 返回的列表中的每个名称必须对应映射字典中的一个 key。LangGraph 会为每个匹配项创建一个隐式的 `Send`。

## 5. 完整实战：并行搜索引擎系统

### 5.1 系统设计

构建一个并行搜索引擎 Agent，能够同时向多个搜索引擎发起查询，汇总排序后返回综合结果。

```
用户查询
    │
    ▼
[router] ──Fan-out──┬── [google_search]
                   ├── [bing_search]
                   ├── [academic_search]
                   └── [wiki_search]
                        │
                        ▼ Fan-in
                  [rank_synthesizer]
                        │
                        ▼
                   最终结果
```

### 5.2 完整代码实现

```python
"""
完整的并行搜索引擎示例
功能：同时查询多个搜索引擎，汇总排序后返回综合结果
"""

from typing import Annotated, TypedDict, List, Any, Dict
from operator import add
from langgraph.graph import StateGraph, START, END
from langgraph.constants import Send
from langchain_core.messages import SystemMessage, HumanMessage

# ============================================================
# 第一部分：State 定义
# ============================================================

class SearchInputState(TypedDict):
    """路由前的输入状态"""
    query: str                      # 用户查询
    engines: List[str]              # 要使用的搜索引擎列表

class WorkerState(TypedDict):
    """单个搜索工作节点的状态"""
    query: str                      # 查询内容
    engine: str                     # 当前使用的引擎名称

class SearchWorkerOutput(TypedDict):
    """搜索工作节点的输出"""
    search_results: Annotated[List[Dict], add]  # 用 add reducer 拼接结果列表

class OverallState(SearchInputState, SearchWorkerOutput):
    """全局状态（继承输入+输出）"""
    ranked_results: List[Dict]      # 排序后的最终结果
    summary: str                    # 结果摘要

# ============================================================
# 第二部分：节点函数定义
# ============================================================

def route_to_engines(state: SearchInputState):
    """
    Fan-out 路由器
    根据 engines 列表动态生成 Send 对象
    """
    query = state["query"]
    engines = state.get("engines", ["google", "bing"])

    print(f"[Router] 将查询 '{query}' 分发到 {len(engines)} 个搜索引擎")

    return [
        Send(
            "search_worker",
            {"query": query, "engine": engine}
        )
        for engine in engines
    ]


async def search_worker(state: WorkerState):
    """
    搜索工作节点（并行执行的单元）
    实际项目中这里会调用真实的搜索 API
    """
    import asyncio
    import random

    query = state["query"]
    engine = state["engine"]

    # 模拟网络延迟（不同引擎速度不同）
    await asyncio.sleep(random.uniform(0.5, 2.0))

    # 模拟搜索结果（实际中替换为真实 API 调用）
    mock_results = [
        {
            "engine": engine,
            "title": f"{engine} 结果 {i+1}: 关于 {query}",
            "url": f"https://example.com/{engine}/{i}",
            "score": round(random.uniform(0.6, 0.99), 2),
            "snippet": f"来自{engine}的相关内容片段..."
        }
        for i in range(random.randint(2, 5))
    ]

    print(f"[{engine}] 返回了 {len(mock_results)} 条结果")

    return {"search_results": mock_results}


def rank_and_synthesize(state: OverallState):
    """
    Fan-in 汇总节点
    1. 收集所有引擎的结果
    2. 按分数排序
    3. 生成摘要
    """
    all_results = state.get("search_results", [])

    # 按分数降序排序
    ranked = sorted(all_results, key=lambda x: x.get("score", 0), reverse=True)

    # 统计各引擎贡献
    engine_stats = {}
    for r in all_results:
        e = r["engine"]
        engine_stats[e] = engine_stats.get(e, 0) + 1

    # 生成摘要
    stats_str = ", ".join([f"{k}:{v}条" for k, v in engine_stats.items()])
    summary = (
        f"共从 {len(engine_stats)} 个引擎获取 {len(all_results)} 条结果 "
        f"({stats_str})，已按相关性排序。"
    )

    print(f"[Synthesizer] {summary}")

    return {
        "ranked_results": ranked,
        "summary": summary,
    }

# ============================================================
# 第三部分：构建图
# ============================================================

def build_parallel_search_graph():
    """构建并行搜索图"""

    graph = StateGraph(OverallState)

    # 添加节点
    graph.add_node("router", route_to_engines)
    graph.add_node("search_worker", search_worker)
    graph.add_node("ranker", rank_and_synthesize)

    # 添加边
    graph.add_edge(START, "router")

    # Fan-out: 条件边 + Send
    graph.add_conditional_edges(
        "router",
        route_to_engines,
        ["search_worker"],  # 所有 Send 都指向 search_worker
    )

    # Fan-in: 所有 worker 完成后进入 ranker
    graph.add_edge("search_worker", "ranker")
    graph.add_edge("ranker", END)

    return graph.compile()


# ============================================================
# 第四部分：运行测试
# ============================================================

async def main():
    app = build_parallel_search_graph()

    # 可视化图结构（需要安装 dev dependencies）
    try:
        import json
        print("\n=== 图结构 ===")
        print(json.dumps(app.get_graph().to_dict(), indent=2, ensure_ascii=False))
    except:
        pass

    # 执行搜索
    print("\n=== 开始并行搜索 ===\n")
    result = await app.ainvoke({
        "query": "LangGraph 并行执行机制",
        "engines": ["google", "bing", "academic", "wikipedia"],
    })

    # 输出结果
    print("\n" + "=" * 60)
    print(result["summary"])
    print("=" * 60)
    for i, r in enumerate(result["ranked_results"][:10], 1):
        print(f"\n[{i}] [{r['engine']}] (评分: {r['score']})")
        print(f"    {r['title']}")
        print(f"    {r['url']}")


if __name__ == "__main__":
    import asyncio
    asyncio.run(main())
```

### 5.3 执行流程说明

```
执行时间线 →

[0.0s]  Router 开始执行
[0.1s]  Router 完成，Fan-out 出 4 个 Send
[0.1s]  ═══════════════════════════════════════
[0.1s]  │ Google Worker  启动 ──────────→ [1.2s] 完成
[0.1s]  │ Bing Worker     启动 ──────────→ [0.8s] 完成
[0.1s]  │ Academic Worker 启动 ──────────→ [1.9s] 完成 ← 最慢
[0.1s]  │ Wikipedia Worker 启动 ────────→ [0.6s] 完成
[0.1s]  ═══════════════════════════════════════
[1.9s]  所有 Worker 完成！触发 Fan-in
[1.9s]  Ranker 开始执行（接收合并后的全部结果）
[2.0s]  Ranker 完成，返回最终排序结果
```

**关键观察**：总耗时约 2 秒，而非串行的 1.2+0.8+1.9+0.6 = 4.5 秒。这就是并行的威力~

## 6. 并行中的状态管理深入

### 6.1 各分支的 State 隔离

LangGraph 为每个通过 `Send` 创建的并行分支提供**独立的 State 视图**：

```
全局 State: { query: "xxx", results: [], status: "running" }

分支 A (google):  { query: "xxx", engine: "google" }   ← 只看到自己需要的字段
分支 B (bing):    { query: "xxx", engine: "bing" }      ← 独立的 State 副本
分支 C (academic):{ query: "xxx", engine: "academic" }  ← 互不干扰
```

**隔离规则**：
- 每个分支只能**读取** Send 时传入的数据
- 每个分支的**写操作**通过 reducer 合并回全局 State
- 分支之间**不能直接通信**（如需通信，通过全局 State 间接实现）

### 6.2 冲突解决策略详解

当多个并行分支同时更新同一个 State 字段时：

```python
# 场景：三个分支都要更新 "best_answer" 字段
# 分支A 写入: best_answer = "答案来自Google"
# 分支B 写入: best_answer = "答案来自Bing"
# 分支C 写入: best_answer = "答案来自Academic"

# ====== 无 reducer（默认 Last-Write-Wins）======
class ConflictState(TypedDict):
    best_answer: str  # 最后完成的分支的值胜出
    # 注意：最后完成的不一定是"最好"的！

# ====== 有 reducer（自定义合并逻辑）======
def pick_best_answer(existing, new):
    """选择更长的答案（简单策略演示）"""
    if existing is None:
        return new
    return new if len(new) > len(len(existing)) else existing

class SmartMergeState(TypedDict):
    best_answer: Annotated[str, pick_best_answer]

# ====== 更复杂的：收集所有答案再决策======
def collect_all_answers(existing, new):
    """收集所有分支的答案到列表"""
    if existing is None:
        return [new]
    if isinstance(existing, list):
        return existing + ([new] if not isinstance(new, list) else new)
    return [existing, new]

class CollectState(TypedDict):
    all_answers: Annotated[list, collect_all_answers]
    # 后续节点可以从 all_answers 中挑选最佳答案
```

### 6.3 实用建议

| 建议 | 说明 |
|------|------|
| **避免共享可变状态** | 各分支尽量只写自己的"命名空间"字段 |
| **使用列表 + 追加 reducer** | 这是最安全且常用的并行合并模式 |
| **在 Fan-in 节点统一决策** | 不要让分支竞争写入，而是各自产出，由汇总节点裁决 |
| **注意幂等性** | reducer 应该是幂等的，同样的输入多次应用结果一致 |
| **考虑容错** | 某个分支失败时的降级策略（见下文错误处理） |

### 6.4 错误处理与容错

并行执行中，单个分支失败不应导致整个流程中断：

```python
import traceback
from typing import Optional

def safe_search_worker(state: WorkerState):
    """带错误处理的搜索工作节点"""
    try:
        # 正常逻辑...
        result = do_actual_search(state["query"], state["engine"])
        return {"search_results": [result]}
    except Exception as e:
        # 记录错误但不阻断整个流程
        error_entry = {
            "engine": state["engine"],
            "error": str(e),
            "status": "failed"
        }
        print(f"[{state['engine']}] 搜索失败: {e}")
        # 返回一个标记失败的条目，让后续节点知道这个源不可用
        return {"search_results": [error_entry]}
```

## 本章小结

本章详细介绍了 LangGraph 中并行节点执行的两大核心机制——**Fan-out（扇出）** 和 **Fan-in（扇入）**：

1. **Fan-out** 通过路由函数返回 `Send` 对象列表，实现从一个节点同时启动多个目标节点并行执行的能力。支持静态或动态数量的分支，每个分支可以携带不同的输入数据。

2. **Fan-in** 利用图的拓扑结构自然形成的汇聚点，配合 **reducer 函数**控制多个并行分支对 State 的更新如何合并回全局状态。支持追加、覆盖、投票等多种合并策略。

3. **两种实现方式**：显式 `Send` 对象（推荐，灵活度高）和 `map` 条件映射（简洁，适合简单场景），后者是前者的语法糖。

4. **状态管理核心原则**：各分支 State 默认隔离，通过 reducer 决定合并策略；推荐使用列表+追加模式收集各分支产出，在 Fan-in 节点做统一决策。

合理运用并行执行可以将 Agent 系统中独立任务的总体耗时从 **O(N)** 降低至 **O(max(N))**，显著提升响应速度和用户体验。
