## 1. 什么是子图（Subgraph）？

### 1.1 核心概念

在 LangGraph 中，**子图（Subgraph）**是指将一个完整的 `StateGraph` 作为节点嵌入到另一个 `StateGraph` 中的能力。这类似于编程语言中的以下概念：

| 编程概念 | LangGraph 对应 | 说明 |
|---------|---------------|------|
| **函数调用** | 子图节点 | 将一段逻辑封装为可复用单元 |
| **模块/包导入** | 子图引用 | 独立定义，按需引入 |
| **类实例化** | compile() 后的子图 | 定义蓝图 → 实例化使用 |
| **微服务调用** | 跨子图通信 | 通过 State 接口交互 |

### 1.2 为什么需要子图？

随着 Agent 系统复杂度的增长，将所有逻辑塞进一张大图会导致：

```
❌ 单体巨石图的问题：

┌─────────────────────────────────────────────────────┐
│                   巨型单体图                          │
│                                                      │
│  [路由] → [搜索] → [分析] → [写稿] → [审核] → [发布] │
│              ↑         ↑        ↑                    │
│         (200行)   (300行)  (250行)                   │
│                                                      │
│  问题：                                               │
│  - 一个节点改动可能影响全局                             │
│  - 无法独立测试和复用                                  │
│  - State 定义臃肿（所有字段混在一起）                   │
│  - 多人协作时冲突频繁                                  │
└─────────────────────────────────────────────────────┘

✅ 子图分解后：

┌──────────┐   ┌──────────┐   ┌──────────┐
│ 主协调图  │   │ 搜索子图  │   │ 写作子图  │
│          │   │ (可复用)  │   │ (可复用)  │
│ [路由]   │→  │[引擎A]   │   │ [起草]   │
│ [汇总]   │←  │[引擎B]   │   │ [润色]   │
│          │   │[融合]    │   │ [排版]   │
└──────────┘   └──────────┘   └──────────┘
     ▲                              ▲
     │    ┌──────────┐              │
     └────┤ 审核子图  │──────────────┘
          │ [合规检查]│
          │ [质量评估]│
          └──────────┘
```

### 1.3 子图的核心价值

| 价值维度 | 具体收益 |
|---------|---------|
| **模块化** | 每个子图关注单一职责，边界清晰 |
| **复用性** | 同一个子图可在多个父图中被引用 |
| **独立性** | 子图可独立开发、测试、迭代 |
| **团队协作** | 不同成员负责不同子图，减少冲突 |
| **State 隔离** | 各子图有独立的 Schema，避免字段污染 |

## 3. 创建和使用子图

### 3.1 基本步骤

创建和使用子图遵循 **"先定义子图 → 编译为 App → 在主图中作为节点添加"** 的三步模式：

```python
from langgraph.graph import StateGraph, START, END

# ==================== 第一步：定义子图 ====================
class ResearchState(TypedDict):
    topic: str
    findings: str
    confidence: float

def research_node(state: ResearchState):
    """研究员节点"""
    return {"findings": f"关于 {state['topic']} 的研究发现...", "confidence": 0.85}

def verify_node(state: ResearchState):
    """验证节点"""
    return {"confidence": state["confidence"] * 0.9}  # 验证后略微降低置信度

# 构建子图
sub_graph = StateGraph(ResearchState)
sub_graph.add_node("researcher", research_node)
sub_graph.add_node("verifier", verify_node)
sub_graph.add_edge(START, "researcher")
sub_graph.add_edge("researcher", "verifier")
sub_graph.add_edge("verifier", END)

# ==================== 第二步：编译子图 ====================
research_app = sub_graph.compile()  # 编译为可运行的应用


# ==================== 第三步：在主图中使用 ====================
class MainState(TypedDict):
    query: str
    research_result: dict
    final_report: str

def coordinator(state: MainState):
    """主图中的协调节点"""
    return {"final_report": f"报告完成: {state['research_result']}"}

main_graph = StateGraph(MainState)
main_graph.add_node("research_team", research_app)  # ★ 关键：整个子图作为一个节点
main_graph.add_node("coordinator", coordinator)
main_graph.add_edge(START, "research_team")
main_graph.add_edge("research_team", "coordinator")
main_graph.add_edge(coordinator, END)

main_app = main_graph.compile()
```

### 3.2 子图的完整生命周期

```
定义阶段:
  StateGraph(SubState)  →  add_node()  →  add_edge()  →  未编译的图对象

编译阶段:
  graph.compile()  →  CompiledGraph (Runnable 对象)

嵌入阶段:
  main_graph.add_node("node_name", compiled_subgraph)

运行阶段:
  main_app.invoke(input_state)
    → 到达 "node_name" 时
    → 自动将父图 State 转换为子图初始 State
    → 执行子图的完整流程
    → 将子图输出 State 转换回父图 State
    → 继续执行主图的后续节点
```

## 4. 主图与子图的状态管理

### 4.1 核心挑战：Schema 不匹配

主图和子图通常有**不同的 State Schema**，这带来了数据映射问题：

```python
# 主图 State
class MainState(TypedDict):
    user_query: str           # 用户原始查询
    search_results: list      # 搜索结果列表
    analysis_report: str      # 分析报告
    timestamp: str            # 时间戳

# 子图 State（不同！）
class AnalysisSubState(TypedDict):
    documents: list           # 待分析文档
    focus_area: str           # 分析重点
    insights: list            # 分析洞察
    summary_text: str         # 摘要文本
    quality_score: float      # 质量评分
```

LangGraph 提供了多种策略来处理这种不匹配。

### 4.2 策略一：共享 State（紧密耦合）

最简单的方式——让主图和子图**使用相同的 State 定义**：

```python
# 共享 State 定义
SharedState = TypedDict('SharedState', {
    "query": str,
    "results": list,
    "report": str,
})

# 子图使用 SharedState
sub = StateGraph(SharedState)
sub.add_node("worker", worker_fn)
sub.add_edge(START, "worker")
sub.add_edge(worker, END)
sub_app = sub.compile()

# 主图也使用 SharedState
main = StateGraph(SharedState)
main.add_node("sub_worker", sub_app)  # 无需转换，直接兼容
```

**优点**：简单直接，无需数据转换
**缺点**：耦合度高，子图无法独立于主图使用；主图 State 会被子图的所有字段污染

### 4.3 策略二：输入/输出转换（推荐）

通过 `input` 和 `output` 参数显式控制 State 映射：

```python
from typing import Annotated, TypedDict

# ====== 主图 State ======
class OrchestratorState(TypedDict):
    user_request: str         # 用户请求
    topic: str                # 提取的主题
    research_data: dict       # 子图的输出（以字典形式存储）
    final_output: str         # 最终输出

# ====== 子图 State ======
class ResearcherState(TypedDict):
    research_topic: str       # 研究主题（来自主图的 topic）
    collected_info: str       # 收集到的信息
    source_count: int         # 来源数量
    reliability_score: float  # 可靠性评分


# ====== 输入转换函数 ======
def map_main_to_sub(main_state: OrchestratorState) -> ResearcherState:
    """
    将主图 State 转换为子图输入 State
    类似函数调用的参数传递
    """
    return {
        "research_topic": main_state.get("topic", ""),
        # 其他字段使用默认值或从主图推导
        "collected_info": "",
        "source_count": 0,
        "reliability_score": 0.0,
    }


# ====== 输出转换函数 ======
def map_sub_to_main(sub_state: ResearcherState, main_state: OrchestratorState):
    """
    将子图输出 State 合并回主图 State
    决定子图的哪些字段写入主图的哪些位置
    """
    return {
        "research_data": {
            "info": sub_state.get("collected_info", ""),
            "sources": sub_state.get("source_count", 0),
            "score": sub_state.get("reliability_score", 0.0),
        }
        }


# ====== 使用转换函数编译子图 ======
sub_graph = StateGraph(ResearcherState)
# ... 添加节点和边 ...

research_app = sub_graph.compile(
    input=map_main_to_sub,    # 进入子图时的转换
    output=map_sub_to_main,   # 离开子图时的转换
)


# ====== 在主图中使用 ======
main_graph = StateGraph(OrchestratorState)
main_graph.add_node("researcher_agent", research_app)
# 当执行流到达 researcher_agent 时：
# 1. 自动调用 map_main_to_sub(current_main_state) 得到子图初始状态
# 2. 执行子图的完整流程
# 3. 子图完成后，自动调用 map_sub_to_main(sub_final_state, current_main_state)
# 4. 将返回值合并到主图 State 中
```

### 4.3 策略三：Store 共享（跨会话持久化）

对于需要在多次调用间共享数据的场景：

```python
from langgraph.store.base import BaseStore
from langgraph.store.memory import InMemoryStore

# 创建共享 Store
store = InMemoryStore()

# 子图可以从 Store 中读写数据
async def researcher_with_store(state: ResearcherState, *, store: BaseStore):
    """子图节点可以访问共享 Store"""
    # 从 Store 读取之前的数据
    namespace = ("research_cache", state["research_topic"])
    cached = store.get(namespace, "previous_results")

    if cached:
        print(f"命中缓存: {cached.value}")
        # 使用缓存结果...

    # 执行研究...
    result = do_research(state["research_topic"])

    # 写入 Store 供其他子图使用
    store.put(namespace, "current_results", result)

    return {"collected_info": result}


# 编译时传入 store
app = main_graph.compile(store=store)
```

### 4.4 三种通信模式对比

| 特性 | 共享 State | 输入/输出转换 | Store 共享 |
|------|-----------|-------------|-----------|
| **耦合度** | 高 | **低（推荐）** | 中 |
| **类型安全** | 是 | 是 | 弱（需要自行管理 key） |
| **复用性** | 差 | **优** | 中 |
| **跨调用持久化** | 否 | 否 | **是** |
| **实现复杂度** | 低 | 中 | 中高 |
| **适用场景** | 原型/简单项目 | 生产环境推荐 | 跨会话缓存/历史 |

## 5. 子图设计最佳实践

### 5.1 单一职责原则

每个子图应该只做一件事，并做好：

```python
# ❌ 差的设计：子图承担了过多职责
class GodObjectSubGraph(StateGraph):
    """搜索 + 分析 + 写作 + 审核 + 发布 全塞在一起"""
    pass

# ✅ 好的设计：每个子图聚焦单一职责
search_graph = build_search_subgraph()      # 只负责搜索
analysis_graph = build_analysis_subgraph()  # 只负责分析
writing_graph = build_writing_subgraph()    # 只负责写作
review_graph = build_review_subgraph()      # 只负责审核
publish_graph = build_publish_subgraph()    # 只负责发布
```

### 5.2 明确的接口契约

子图的输入输出应该清晰定义，像 API 契约一样：

```python
class SearchSubInput(TypedDict):
    """搜索子图的输入接口"""
    query: str                  # 必填 - 查询关键词
    max_results: int            # 可选 - 最大结果数，默认10
    sources: List[str]          # 可选 - 指定来源，默认全部
    recency_filter: str         # 可选 - 时间过滤，默认无

class SearchSubOutput(TypedDict):
    """搜索子图的输出接口"""
    results: List[SearchResult]  # 必填 - 结果列表
    total_found: int             # 必填 - 总找到数量
    search_duration_ms: int      # 必填 - 耗时（毫秒）
    has_more: bool               # 必填 - 是否还有更多结果
    errors: List[str]            # 可选 - 错误信息列表
```

### 5.3 子图的可测试性

好的子图应该能够**独立于主图进行完整测试**：

```python
import pytest

@pytest.mark.asyncio
async def test_search_subgraph_basic():
    """独立测试搜索子图"""

    app = build_search_subgraph().compile()

    result = await app.ainvoke({
        "query": "LangGraph tutorial",
        "max_results": 5,
    })

    assert "results" in result
    assert len(result["results"]) <= 5
    assert result["total_found"] >= 0
    assert isinstance(result["search_duration_ms"], int)


@pytest.mark.asyncio
async def test_search_subgraph_empty_query():
    """边界测试：空查询"""
    app = build_search_subgraph().compile()

    result = await app.ainvoke({
        "query": "",
        "max_results": 3,
    })

    assert result["results"] == []  # 空查询应返回空结果
```

### 5.4 错误隔离

子图的错误不应导致整个主图崩溃：

```python
async def safe_subgraph_wrapper(state, subgraph_app):
    """安全的子图包装器：捕获异常并转换为错误状态"""
    try:
        result = await subgraph_app.ainvoke(state)
        return {**result, "_subgraph_error": None}
    except Exception as e:
        # 返回错误信息而非抛出异常
        return {
            "_subgraph_error": str(e),
            "_subgraph_status": "failed",
            # 提供合理的默认/回退值
            "results": [],
            "total_found": 0,
        }

# 在主图中使用包装后的版本
main_graph.add_node(
    "safe_search",
    lambda state: safe_subgraph_wrapper(state, search_app)
)
```

### 6.2 完整代码实现

```python
"""
多 Agent 研究系统 - 完整实现
功能：主管Agent协调三个专家子图并行研究，汇总生成研究报告
"""

import asyncio
from typing import Annotated, TypedDict, List, Dict, Any, Optional
from operator import add
from langgraph.graph import StateGraph, START, END
from langgraph.constants import Send

# ============================================================
# 第一部分：各子图的 State 与实现
# ============================================================

# ---------- Web 搜索子图 ----------
class WebSearchState(TypedDict):
    query: str
    web_results: List[Dict]
    verification_passed: bool

async def web_search_node(state: WebSearchState):
    """Web 搜索执行"""
    await asyncio.sleep(0.5)  # 模拟网络延迟
    results = [
        {"title": f"Web: 关于{state['query']}", "url": f"https://example.com/{i}", "score": 0.8 + i*0.05}
        for i in range(3)
    ]
    return {"web_results": results}

async def web_verify_node(state: WebSearchState):
    """Web 结果验证"""
    passed = len(state.get("web_results", [])) > 0
    return {"verification_passed": passed}

def build_web_search_subgraph():
    g = StateGraph(WebSearchState)
    g.add_node("search", web_search_node)
    g.add_node("verify", web_verify_node)
    g.add_edge(START, "search")
    g.add_edge("search", "verify")
    g.add_edge("verify", END)
    return g.compile()


# ---------- 学术检索子图 ----------
class AcademicSearchState(TypedDict):
    query: str
    papers: List[Dict]
    top_paper_summary: str

async def academic_query_node(state: AcademicSearchState):
    """学术数据库查询"""
    await asyncio.sleep(0.8)  # 学术检索通常较慢
    papers = [
        {"title": f"论文{i+1}: {state['query']}研究", "citations": 100+i*50, "year": 2024-i}
        for i in range(4)
    ]
    return {"papers": papers}

async def academic_rank_node(state: AcademicSearchState):
    """按引用量排序并提取 top 论文摘要"""
    sorted_papers = sorted(
        state.get("papers", []),
        key=lambda p: p.get("citations", 0),
        reverse=True
    )
    top = sorted_papers[0] if sorted_papers else {}
    summary = f"[Top论文] {top.get('title', 'N/A')} ({top.get('citations', 0)} 引用)"
    return {"top_paper_summary": summary}

def build_academic_search_subgraph():
    g = StateGraph(AcademicSearchState)
    g.add_node("query", academic_query_node)
    g.add_node("rank", academic_rank_node)
    g.add_edge(START, "query")
    g.add_edge("query", "rank")
    g.add_edge("rank", END)
    return g.compile()


# ---------- 代码库搜索子图 ----------
class CodeSearchState(TypedDict):
    query: str
    repo_url: Optional[str]
    code_matches: List[Dict]
    analysis: str

async def code_grep_node(state: CodeSearchState):
    """代码库搜索"""
    await asyncio.sleep(0.3)
    matches = [
        {"file": f"src/module_{i}.py", "lines_matched": 5+i*2, "relevance": 0.7+i*0.08}
        for i in range(3)
    ]
    return {"code_matches": matches}

async def code_analyze_node(state: CodeSearchState):
    """代码匹配分析"""
    matches = state.get("code_matches", [])
    total_lines = sum(m.get("lines_matched", 0) for m in matches)
    analysis = f"在 {len(matches)} 个文件中找到 {total_lines} 行相关代码"
    return {"analysis": analysis}

def build_code_search_subgraph():
    g = StateGraph(CodeSearchState)
    g.add_node("grep", code_grep_node)
    g.add_node("analyze", code_analyze_node)
    g.add_edge(START, "grep")
    g.add_edge("grep", "analyze")
    g.add_edge("analyze", END)
    return g.compile()


# ============================================================
# 第二部分：主图 State 与实现
# ============================================================

class MainOrchestratorState(TypedDict):
    # 输入
    user_request: str
    extracted_topic: str

    # 子图输出（每个子图的结果存入各自的字段）
    web_findings: Dict
    academic_findings: Dict
    code_findings: Dict

    # 最终输出
    combined_results: Dict
    final_report: str


# ---------- 主图节点 ----------

async def intent_parser(state: MainOrchestratorState):
    """解析用户意图，提取研究主题"""
    request = state["user_request"]
    # 简单提取（实际中用 LLM）
    topic = request.replace("研究一下", "").replace("帮我看看", "").strip()
    if not topic:
        topic = request
    print(f"[Intent Parser] 主题提取: '{topic}'")
    return {"extracted_topic": topic}


def route_to_experts(state: MainOrchestratorState):
    """Fan-out 路由器：分发到三个专家子图"""
    topic = state["extracted_topic"]
    return [
        Send("web_researcher", {"query": topic}),
        Send("academic_researcher", {"query": topic}),
        Send("code_researcher", {"query": topic}),
    ]


async def synthesizer(state: MainOrchestratorState):
    """Fan-in 汇总节点：综合三个子图的研究结果"""
    web = state.get("web_findings", {})
    academic = state.get("academic_findings", {})
    code = state.get("code_findings", {})

    combined = {
        "web": {
            "result_count": len(web.get("web_results", [])),
            "verified": web.get("verification_passed", False),
        },
        "academic": {
            "paper_count": len(academic.get("papers", [])),
            "top_paper": academic.get("top_paper_summary", "N/A"),
        },
        "code": {
            "files_found": len(code.get("code_matches", [])),
            "analysis": code.get("analysis", "N/A"),
        },
    }

    report = f"""═══════════════════════════════════════
  研究报告：{state['extracted_topic']}
═══════════════════════════════════════

📄 Web 搜索：
   找到 {combined['web']['result_count']} 条结果
   验证: {'✓ 通过' if combined['web']['verified'] else '✗ 未通过'}

📚 学术文献：
   找到 {combined['academic']['paper_count']} 篇论文
   Top: {combined['academic']['top_paper']}

💻 代码库：
   {combined['code']['analysis']}

═══════════════════════════════════════
"""

    print("\n[Synthesizer] 报告生成完成")
    return {"combined_results": combined, "final_report": report}


async def formatter(state: MainOrchestratorState):
    """格式化输出"""
    return state  # 已经在 synthesizer 中格式化了


# ============================================================
# 第三部分：构建主图
# ============================================================

def build_multi_agent_system():
    """构建完整的多 Agent 研究系统"""

    # 先编译各子图
    web_app = build_web_search_subgraph()
    academic_app = build_academic_search_subgraph()
    code_app = build_code_search_subgraph()

    # 构建主图
    graph = StateGraph(MainOrchestratorState)

    # 添加节点（包括子图节点）
    graph.add_node("intent_parser", intent_parser)
    graph.add_node("web_researcher", web_app)       # 子图作为节点 ★
    graph.add_node("academic_researcher", academic_app)  # 子图作为节点 ★
    graph.add_node("code_researcher", code_app)      # 子图作为节点 ★
    graph.add_node("synthesizer", synthesizer)
    graph.add_node("formatter", formatter)

    # 添加边
    graph.add_edge(START, "intent_parser")

    # Fan-out: 条件边 + Send
    graph.add_conditional_edges(
        "intent_parser",
        route_to_experts,
        ["web_researcher", "academic_researcher", "code_researcher"],
    )

    # Fan-in: 所有子图完成后进入汇总
    graph.add_edge("web_researcher", "synthesizer")
    graph.add_edge("academic_researcher", "synthesizer")
    graph.add_edge("code_researcher", "synthesizer")

    graph.add_edge("synthesizer", "formatter")
    graph.add_edge("formatter", END)

    return graph.compile()


# ============================================================
# 第四部分：运行与可视化
# ============================================================

async def main():
    import time

    app = build_multi_agent_system()

    # 打印图结构
    try:
        import json
        print("=" * 60)
        print("系统结构:")
        print(json.dumps(app.get_graph().to_dict(), indent=2, ensure_ascii=False)[:800])
        print("...")
    except:
        pass

    # 执行
    print("\n" + "=" * 60)
    print("开始多 Agent 研究...")
    print("=" * 60 + "\n")

    start = time.perf_counter()
    result = await app.ainvoke({
        "user_request": "研究一下 LangGraph 的子图设计和并行执行机制"
    })
    elapsed = time.perf_counter() - start

    print(f"\n{'=' * 60}")
    print(f"总耗时: {elapsed:.2f}s")
    print(f"\n{result['final_report']}")
    print(f"{'=' * 60}")


if __name__ == "__main__":
    asyncio.run(main())
```

## 7. 高级话题

### 7.1 嵌套子图（子图的子图）

LangGraph 支持多层嵌套：

```
主图
 └→ 子图A
      └→ 子子图A1
      └→ 子子图A2
 └→ 子图B
 └→ 子图C
      └→ 子子图C1
```

但建议嵌套深度不超过 **2~3 层**，过深会增加调试难度。

### 7.2 动态子图选择

根据运行时条件选择不同的子图：

```python
def dynamic_subgraph_selector(state):
    """根据任务类型动态选择子图"""
    task_type = state.get("task_type", "general")

    subgraphs = {
        "coding": code_expert_app,
        "research": research_app,
        "writing": writer_app,
        "analysis": analyst_app,
    }

    return subgraphs.get(task_type, general_app)

# 注意：这需要在图构建前决定，不能在运行时切换节点的 runnable
```

### 7.3 子图的热更新

由于子图是编译后传入主图的，理论上可以实现**不停机更新子图**：

```python
# 初始部署
main_app = build_main_with(v1_subgraph)

# 更新子图逻辑（无需重启主图）
new_subgraph = build_v2_subgraph().compile()
main_app = build_main_with(new_subgraph)  # 重新编译即可
```

## 本章小结

本章深入讲解了 LangGraph 中**子图（Subgraph）**的设计与封装技术：

1. **核心概念**：子图是将完整 `StateGraph` 作为节点嵌入另一张图的机制，实现了 Agent 系统的**分层解耦**。类似编程中的"函数封装"，支持独立定义、编译后在主图中引用。

2. **三种状态管理模式**：共享 State（简单但耦合）、**输入/输出转换函数（推荐，松耦合）**、Store 共享（支持跨会话持久化）。其中通过 `input`/`output` 参数实现的显式转换是最灵活且生产友好的方式。

3. **实战案例**展示了完整的多 Agent 研究系统：主管 Agent 图协调 Web 搜索、学术检索、代码库搜索三个专家子图**并行工作**，通过 Fan-out/Fan-in 实现任务分发与结果汇总。

4. **设计原则**：单一职责、明确接口契约、独立可测试、错误隔离。子图应像设计 API 一样设计其输入输出接口，确保可复用性和可维护性。

子图是构建**复杂、可扩展、可维护**的多 Agent 系统的核心组织模式，是从小型原型走向企业级应用的必经之路。
