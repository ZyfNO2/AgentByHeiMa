## 1. 工具在 Agent 中的核心地位

### 1.1 为什么工具如此重要？

LLM 本身只是一个"大脑"——它能理解和生成文本，但无法直接与外部世界交互。**工具（Tools）** 就是 Agent 的"手和脚"，让 LLM 能够：

```
┌─────────────────────────────────────────────────────┐
│                    Agent 架构                        │
│                                                      │
│   ┌─────────┐                                        │
│   │   LLM    │ ← 大脑：理解意图、制定计划、生成回复     │
│   │ (推理)   │                                        │
│   └────┬─────┘                                        │
│        │ 决策：调用哪个工具？传入什么参数？             │
│        ▼                                              │
│   ┌──────────────────────────────────────────┐       │
│   │              工具层 (Tools)               │       │
│   │                                          │       │
│   │  ┌──────────┐ ┌──────────┐ ┌──────────┐ │       │
│   │  │ 搜索引擎  │ │ 数据库   │ │ API调用  │ │       │
│   │  │ Calculator│ │ 文件操作 │ │ 代码执行  │ │       │
│   │  └──────────┘ └──────────┘ └──────────┘ │       │
│   └──────────────────────────────────────────┘       │
│                                                      │
│   工具 = Agent 能力的边界扩展                          │
└─────────────────────────────────────────────────────┘
```

### 1.2 工具能力矩阵

| 工具类型 | 典型场景 | 复杂度 | 出错概率 |
|----------|----------|--------|----------|
| **信息检索** | 搜索、查询数据库、RAG | 中 | 低 |
| **计算执行** | 数学运算、代码运行、数据处理 | 高 | **高** |
| **外部API** | 调用第三方服务、发送消息 | 中 | 中 |
| **文件操作** | 读写文件、解析文档 | 低 | 低 |
| **用户交互** | 确认操作、收集输入 | 低 | 极低 |

## 2. ToolNode 深度剖析

### 2.1 ToolNode 是什么？

`ToolNode` 是 LangGraph 预构建的专用节点，专门用于**执行 LLM 决定的工具调用**。它是连接 "LLM 思考" 和 "工具执行" 的桥梁：

```python
from langgraph.prebuilt import ToolNode

# 创建 ToolNode
tool_node = ToolNode(tools=[search_tool, calculator_tool, weather_tool])

# 在图中使用
graph.add_node("tools", tool_node)
graph.add_edge("llm", "tools")      # LLM 决定调用工具 → 执行工具
graph.add_edge("tools", "llm")      # 工具返回结果 → LLM 继续思考
```

### 2.2 ToolNode 的内部工作流程

```
LLM 输出: AIMessage(
    content="",
    tool_calls=[
        {"name": "search", "args": {"query": "LangGraph教程"}, "id": "call_001"},
        {"name": "calculator", "args": {"expr": "2+2"}, "id": "call_002"}
    ]
)
         │
         ▼
┌─────────────────────────────────────────┐
│            ToolNode 内部处理              │
│                                         │
│  1. 解析 tool_calls 列表                 │
│  2. 根据 name 匹配对应的工具函数          │
│  3. 并行执行所有工具调用                  │
│  4. 收集结果并包装为 ToolMessage          │
│  5. 返回更新后的 State                   │
└────────────────┬────────────────────────┘
                 │
                 ▼
State 更新:
{
    "messages": [
        ...原有消息,
        AIMessage(tool_calls=[...]),     # LLM 的决策
        ToolMessage(content="搜索结果...", tool_call_id="call_001"),  # 工具1结果
        ToolMessage(content="4", tool_call_id="call_002"),            # 工具2结果
    ]
}
```

### 2.3 ToolNode 的关键配置参数

```python
from langgraph.prebuilt import ToolNode

tool_node = ToolNode(
    tools=[tool_a, tool_b, tool_c],
    
    # ★ 关键参数：工具执行失败时的行为
    raise_on_error=False,    # 默认 False，失败时返回错误信息而非抛异常
    
    # 其他可选参数
    # tags=["tools"],         # 用于追踪和过滤的标签
    # timeout=30,             # 单个工具的超时时间（秒）
)
```

**`raise_on_error` 的选择指南**：

| 场景 | 推荐值 | 原因 |
|------|--------|------|
| 生产环境 | `False` | 单个工具失败不应中断整个流程 |
| 开发调试 | `True` | 快速发现和定位问题 |
| 关键任务工具 | `True` | 必须成功的操作应该中断 |
| 可选增强工具 | `False` | 失败时降级而非崩溃 |

## 3. 错误处理三层体系

在生产环境中，工具调用可能会因为各种原因失败。建立完善的错误处理机制是 Agent 稳定运行的保障。

### 3.1 错误来源分类

```
工具调用失败的常见原因：

┌─────────────────────────────────────────────────────────┐
│                      错误来源                            │
├──────────────┬──────────────┬──────────────┬─────────────┤
│   LLM 层面   │   参数层面   │   执行层面   │   外部层面   │
├──────────────┼──────────────┼──────────────┼─────────────┤
│ • 选错了工具 │ • 参数类型错误│ • 代码语法错误│ • API 限流  │
│ • 参数遗漏   │ • 参数缺失   │ • 运行时异常  │ • 网络超时  │
│ • 多余调用   │ • 格式不正确 │ • 权限不足    │ • 服务宕机  │
│ • 循环调用   │ • 超出范围   │ • 资源耗尽    │ • 数据变更  │
└──────────────┴──────────────┴──────────────┴─────────────┘
```

### 3.2 第一层：工具内部防御

在工具函数内部进行参数验证和异常捕获：

```python
from langchain_core.tools import tool
from typing import Optional
import re

@tool
def safe_divide(a: float, b: float) -> str:
    """
    安全除法工具：带完整的参数验证和错误处理
    
    Args:
        a: 被除数
        b: 除数（不能为零）
    
    Returns:
        除法结果或错误信息
    """
    # ====== 参数验证 ======
    if not isinstance(a, (int, float)):
        return f"❌ 参数错误: a 应为数字，收到 {type(a).__name__}"
    if not isinstance(b, (int, float)):
        return f"❌ 参数错误: b 应为数字，收到 {type(b).__name__}"
    
    # ====== 业务逻辑验证 ======
    if abs(b) < 1e-10:
        return "❌ 计算错误: 除数不能为零（或接近零）"
    
    # ====== 核心计算（带异常保护）======
    try:
        result = a / b
        return f"✅ 计算结果: {a} ÷ {b} = {result:.4f}"
    except OverflowError:
        return f"❌ 数值溢出: {a} ÷ {b} 结果过大或过小"
    except Exception as e:
        return f"❌ 未知错误: {str(e)}"


@tool
def web_search(query: str, max_results: int = 5) -> str:
    """
    带限流重试的网络搜索工具
    
    Args:
        query: 搜索关键词
        max_results: 最大返回结果数（1-20）
    """
    # 参数清洗
    query = str(query).strip()
    if len(query) < 2:
        return "❌ 搜索词太短，请提供更有意义的关键词"
    
    # 边界检查
    max_results = max(1, min(20, int(max_results)))
    
    # 带重试的执行
    import time
    max_retries = 3
    for attempt in range(max_retries):
        try:
            # 模拟搜索 API 调用
            results = perform_actual_search(query, max_results)
            return format_search_results(results)
        except RateLimitError as e:
            if attempt < max_retries - 1:
                wait_time = 2 ** attempt  # 指数退避
                time.sleep(wait_time)
                continue
            return f"❌ API 限流: 已重试 {max_retries} 次，请稍后再试"
        except ConnectionError:
            return "❌ 网络连接失败，请检查网络设置"
        except TimeoutError:
            return "❌ 请求超时，搜索服务响应太慢"
    
    return "❌ 搜索失败：未知原因"
```

### 3.3 第二层：ToolNode 级别容错

通过 `raise_on_error=False` 让 ToolNode 在单个工具失败时继续执行其他工具：

```python
from langgraph.prebuilt import ToolNode

# 创建容错的 ToolNode
fault_tolerant_tools = ToolNode(
    tools=[
        reliable_search_tool,      # 这个通常成功
        sometimes_fails_tool,      # 这个偶尔失败
        experimental_ai_tool,      # 这个经常失败
    ],
    raise_on_error=False,  # ★ 关键：失败返回错误信息而非崩溃
)


# 自定义 ToolNode 子类实现更精细的错误处理
class RobustToolNode(ToolNode):
    """增强版 ToolNode：带日志、重试、降级"""
    
    def __init__(self, tools, *, max_retries=2, fallback_fn=None):
        super().__init__(tools, raise_on_error=False)
        self.max_retries = max_retries
        self.fallback_fn = fallback_fn
    
    async def _execute_with_retry(self, tool_input, tool, config):
        """带重试的工具执行"""
        last_error = None
        
        for attempt in range(self.max_retries + 1):
            try:
                result = await tool.ainvoke(tool_input, config)
                return result
            except Exception as e:
                last_error = e
                if attempt < self.max_retries:
                    import asyncio
                    await asyncio.sleep(0.5 * (attempt + 1))  # 渐进等待
                    continue
        
        # 所有重试都失败
        if self.fallback_fn:
            try:
                return self.fallback_fn(tool_input, str(last_error))
            except:
                pass
        
        # 返回结构化错误信息
        return f"[TOOL_ERROR] {tool.name}: {str(last_error)}"
```

### 3.4 第三层：图级别恢复策略

当工具失败后，图需要有策略来恢复：

```python
from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated
from operator import add


class AgentState(TypedDict):
    messages: Annotated[list, add]
    error_count: int
    last_error: str
    retry_attempt: int


def should_retry_or_continue(state: AgentState) -> str:
    """
    错误恢复路由器：
    - 少量错误：重试当前步骤
    - 错误过多：跳过该工具，用已有信息继续
    - 严重错误：终止并报告
    """
    messages = state["messages"]
    error_count = state.get("error_count", 0)
    
    # 检查最后一条消息是否是工具错误
    last_msg = messages[-1] if messages else None
    
    if last_msg and hasattr(last_msg, 'content') and '[TOOL_ERROR]' in last_msg.content:
        error_count += 1
        
        if error_count < 3:
            # 还可以重试 → 回到 LLM 让它重新决策
            return "llm"
        elif error_count < 5:
            # 重试次数够了 → 强制结束，使用已有结果
            return "graceful_finish"
        else:
            # 错误太多 → 直接报错退出
            return "error_handler"
    
    # 正常情况 → 继续判断是否有更多工具调用
    if last_msg and getattr(last_msg, 'tool_calls', None):
        return "tools"
    
    return END


def graceful_finish(state: AgentState):
    """优雅降级：基于已有信息给出回答"""
    return {
        "messages": [AIMessage(
            content="⚠️ 部分工具调用遇到问题，但我已根据现有信息尽力回答..."
        )],
        "error_count": state.get("error_count", 0),
    }


def error_handler(state: AgentState):
    """错误处理节点：汇总所有错误"""
    errors = [
        m.content for m in state["messages"]
        if hasattr(m, 'content') and '[TOOL_ERROR]' in m.content
    ]
    return {
        "messages": [AIMessage(
            content=f"❌ 抱歉，遇到了以下问题无法完成请求：\n" + 
                    "\n".join(f"- {e}" for e in errors[-3:])
        )],
    }
```

### 3.5 三层错误处理对比

| 层级 | 位置 | 处理范围 | 典型动作 | 响应时间 |
|------|------|----------|----------|----------|
| **第一层** | 工具函数内部 | 单个工具的参数/逻辑 | 参数校验、try-catch、友好提示 | 即时 |
| **第二层** | ToolNode 配置 | 所有工具的执行阶段 | 容错执行、自动重试、降级 | 秒级 |
| **第三层** | 图路由逻辑 | 整体流程控制 | 重试、跳过、降级、终止 | 流程级 |

## 4. Injected Tool Arguments（注入式参数）

### 4.1 什么是 Injected Args？

LangGraph 支持一种特殊的参数注入机制——**Injected Tool Arguments**，允许将运行时信息（如用户身份、配置）自动传递给工具，而无需 LLM 显式指定：

```python
from langchain_core.tools import InjectedToolArg
from typing import Annotated

@tool
def get_user_preferences(
    topic: str,
    user_id: Annotated[str, InjectedToolArg],  # ← 注入参数！
) -> str:
    """
    获取用户对某主题的偏好设置
    
    Args:
        topic: 查询偏好的主题
        user_id: 当前用户的ID（系统自动注入）
    """
    # user_id 不需要 LLM 提供，由框架自动从 Context 注入
    prefs = load_user_preferences(user_id, topic)
    return format_preferences(prefs)
```

### 4.2 注入参数的工作原理

```
正常工具调用流程：
  LLM 输出: get_user_preferences(topic="AI技术")
  ↓
  工具接收: {"topic": "AI技术"}  ← 只有 LLM 提供的参数

注入参数流程：
  LLM 输出: get_user_preferences(topic="AI技术")  
  ↓
  LangGraph 拦截，检查函数签名中的 InjectedToolArg
  ↓
  从 Context/config 中提取 user_id
  ↓
  工具接收: {"topic": "AI技术", "user_id": "user_12345"}  ← 自动补充！
```

### 4.3 常见注入场景

#### 场景一：用户身份注入

```python
from langchain_core.tools import InjectedToolArg
from typing import Annotated

@tool
def query_personal_data(
    question: str,
    user_id: Annotated[str, InjectedToolArg],
    session_id: Annotated[str, InjectedToolArg],
) -> str:
    """查询用户的个人数据（自动携带身份信息）"""
    data = database.query(
        user_id=user_id,
        session=session_id,
        question=question,
    )
    return sanitize_for_llm(data)

# 在编译时配置注入源
app = graph.compile().with_config({
    "configurable": {
        "user_id": "user_abc123",
        "session_id": "sess_xyz789",
    }
})
```

#### 场景二：配置注入

```python
@tool
def search_database(
    query: str,
    db_connection: Annotated[Connection, InjectedToolArg],  # 注入数据库连接
    max_rows: Annotated[int, InjectedToolArg],             # 注入行数限制
) -> str:
    """搜索数据库（自动获取连接和配置）"""
    cursor = db_connection.cursor()
    cursor.execute(f"SELECT * FROM docs WHERE content LIKE '%{query}%' LIMIT {max_rows}")
    return format_results(cursor.fetchall())
```

#### 场景三：Store 注入

```python
@tool
def save_to_memory(
    key: str,
    value: str,
    store: Annotated[BaseStore, InjectedToolArg],  # 注入 Store 实例
    namespace: tuple = ("default",),                # 默认命名空间
) -> str:
    """保存数据到长期记忆 Store"""
    store.put(namespace, key, value)
    return f"✅ 已保存: {namespace}/{key} = {value[:50]}..."
```

### 4.4 注入参数的最佳实践

| 原则 | 说明 | 示例 |
|------|------|------|
| **安全敏感数据必须注入** | 不要让 LLM 看到/决定用户ID、密钥等 | `user_id`, `api_key` |
| **复杂对象适合注入** | 数据库连接、HTTP客户端等不适合序列化 | `db_conn`, `http_client` |
| **运行时常量适合注入** | 每次调用都相同的配置 | `max_tokens`, `timeout` |
| **业务参数交给 LLM** | 与用户意图直接相关的参数 | `query`, `topic`, `format` |

## 5. 多字段状态更新模式

### 5.1 工具如何更新多个 State 字段

默认情况下，ToolNode 只会向 `messages` 字段追加 ToolMessage。但如果需要同时更新多个字段呢？

```python
from langchain_core.tools import tool
from typing import Dict, Any

@tool
def complex_analysis(text: str) -> Dict[str, Any]:
    """
    同时返回多个状态更新的工具
    
    Returns:
        包含多个字段更新的字典
    """
    # 执行分析...
    word_count = len(text.split())
    sentiment = analyze_sentiment(text)
    keywords = extract_keywords(text)
    
    # 返回多字段更新
    return {
        "__all__": {
            "analysis_result": f"字数:{word_count}, 情感:{sentiment}",
            "word_count": word_count,
            "sentiment": sentiment,
            "keywords": keywords,
            "metadata": {
                "processed_at": datetime.now().isoformat(),
                "source": "complex_analysis_tool",
            }
        },
        "_message": f"分析完成：共{word_count}个词，情感倾向{sentiment}"
    }
```

### 5.2 使用 Command 进行精确控制

对于更复杂的场景，可以使用 `Command` 对象精确控制状态更新：

```python
from langgraph.types import Command

@tool
def multi_update_tool(data: str) -> Command:
    """使用 Command 进行多字段更新"""
    
    processed = process_data(data)
    
    return Command(
        update={
            "raw_data": data,
            "processed_data": processed["result"],
            "confidence": processed["score"],
            "processing_time": processed["duration"],
            "status": "completed",
        },
        # 同时也可以添加消息
    )
```

### 5.3 结构化工具输出模式

推荐使用 Pydantic Model 来定义工具的输出结构：

```python
from pydantic import BaseModel, Field
from langchain_core.tools import tool

class SearchResult(BaseModel):
    """搜索结果的标准化结构"""
    url: str = Field(description="结果链接")
    title: str = Field(description="结果标题")
    snippet: str = Field(description="内容摘要")
    relevance_score: float = Field(description="相关性评分 0-1")

class SearchResponse(BaseModel):
    """搜索工具的完整响应"""
    query: str
    results: list[SearchResult]
    total_found: int
    search_duration_ms: int
    has_more: bool

@tool
def structured_search(query: str, top_k: int = 5) -> SearchResponse:
    """
    执行结构化搜索，返回标准化的结果
    
    Args:
        query: 搜索关键词
        top_k: 返回前 K 个结果
    
    Returns:
        标准化的搜索响应对象
    """
    import time
    start = time.perf_counter()
    
    # 执行实际搜索...
    raw_results = do_search(query, top_k)
    
    # 构建标准化响应
    results = [
        SearchResult(
            url=r["url"],
            title=r["title"],
            snippet=r["snippet"][:200],
            relevance_score=r.get("score", 0.8),
        )
        for r in raw_results
    ]
    
    duration_ms = int((time.perf_counter() - start) * 1000)
    
    return SearchResponse(
        query=query,
        results=results,
        total_found=len(raw_results),
        search_duration_ms=duration_ms,
        has_more=len(raw_results) >= top_k,
    )
```

**结构化输出的优势**：

| 优势 | 说明 |
|------|------|
| **类型安全** | 编译期就能发现字段错误 |
| **自文档化** | Field description 就是工具说明 |
| **可验证** | 可以轻松做输出校验 |
| **易解析** | LLM 更容易理解预期输出格式 |

## 6. 大规模工具管理策略

### 6.1 当工具有几十个甚至上百个时...

随着 Agent 功能的增长，工具数量可能迅速膨胀。管理大量工具需要系统化的策略：

```
工具数量增长曲线：

Phase 1 (1-5): 手动定义
    @tool def foo(): ...
    @tool def bar(): ...
    tools = [foo, bar]

Phase 2 (5-20): 分类组织
    tools_by_category = {
        "search": [...],
        "calculation": [...],
        "file_ops": [...],
    }

Phase 3 (20-100): 动态注册 + 权限控制
    class ToolRegistry:
        def register(self, tool): ...
```

```python
"""
工具注册表：集中管理所有可用工具
"""

from typing import Dict, List, Type, Callable, Optional
from langchain_core.tools import BaseTool
from enum import Enum


class ToolCategory(str, Enum):
    """工具分类枚举"""
    SEARCH = "search"
    CALCULATION = "calculation"
    DATA_ACCESS = "data_access"
    COMMUNICATION = "communication"
    FILE_OPERATIONS = "file_operations"
    AI_ASSISTED = "ai_assisted"


class ToolPermission(str, Enum):
    """权限等级"""
    PUBLIC = "public"           # 所有用户可用
    AUTHENTICATED = "auth"      # 登录用户可用
    PREMIUM = "premium"         # 付费用户可用
    ADMIN = "admin"             # 仅管理员


class ToolRegistry:
    """全局工具注册表"""
    
    def __init__(self):
        self._tools: Dict[str, BaseTool] = {}
        self._categories: Dict[str, ToolCategory] = {}
        self._permissions: Dict[str, ToolPermission] = {}
        self._tags: Dict[str, List[str]] = {}
    
    def register(
        self,
        tool: BaseTool,
        category: ToolCategory = ToolCategory.SEARCH,
        permission: ToolPermission = ToolPermission.PUBLIC,
        tags: Optional[List[str]] = None,
    ):
        """注册一个工具"""
        self._tools[tool.name] = tool
        self._categories[tool.name] = category
        self._permissions[tool.name] = permission
        self._tags[tool.name] = tags or []
        
        print(f"[Registry] 注册工具: {tool.name} ({category.value})")
    
    def get_all_tools(self) -> List[BaseTool]:
        """获取所有工具"""
        return list(self._tools.values())
    
    def get_tools_by_category(self, category: ToolCategory) -> List[BaseTool]:
        """按类别获取工具"""
        return [
            self._tools[name] for name, cat in self._categories.items()
            if cat == category
        ]
    
    def get_allowed_tools(self, user_roles: List[str]) -> List[BaseTool]:
        """根据用户角色获取允许使用的工具"""
        allowed = []
        for name, tool in self._tools.items():
            perm = self._permissions[name]
            
            # 权限检查逻辑
            if perm == ToolPermission.PUBLIC:
                allowed.append(tool)
            elif perm == ToolPermission.AUTHENTICATED and "authenticated" in user_roles:
                allowed.append(tool)
            elif perm == ToolPermission.PREMIUM and "premium" in user_roles:
                allowed.append(tool)
            elif perm == ToolPermission.ADMIN and "admin" in user_roles:
                allowed.append(tool)
        
        return allowed
    
    def get_tool_info(self) -> Dict:
        """获取所有工具的元信息（用于展示和管理）"""
        return {
            name: {
                "category": self._categories[name].value,
                "permission": self._permissions[name].value,
                "tags": self._tags[name],
                "description": self._tools[name].description[:100],
            }
            for name in self._tools
        }


# ========== 使用示例 ==========

# 创建全局注册表
registry = ToolRegistry()

# 注册各种工具
registry.register(web_search_tool, category=ToolCategory.SEARCH, permission=ToolPermission.PUBLIC)
registry.register(calculator_tool, category=ToolCategory.CALCULATION, permission=ToolPermission.PUBLIC)
registry.register(database_query_tool, category=ToolCategory.DATA_ACCESS, permission=ToolPermission.AUTHENTICATED)
registry.register(send_email_tool, category=ToolCategory.COMMUNICATION, permission=ToolPermission.PREMIUM)
registry.register(admin_panel_tool, category=ToolCategory.AI_ASSISTED, permission=ToolPermission.ADMIN)

# 根据用户角色获取工具集
user_tools = registry.get_allowed_tools(["authenticated"])  # 普通登录用户
premium_tools = registry.get_allowed_tools(["authenticated", "premium"])  # 付费用户
admin_tools = registry.get_allowed_tools(["authenticated", "admin"])  # 管理员

# 在图中使用
app = graph.compile().with_config({
    "configurable": {
        "tools": premium_tools,  # 动态注入可用工具
    }
})
```

```python
class VersionedToolRegistry(ToolRegistry):
    """支持版本管理的工具注册表"""
    
    def __init__(self):
        super().__init__()
        self._versions: Dict[str, int] = {}  # name → version
        self._history: Dict[str, List[BaseTool]] = {}  # name → [old_versions]
    
    def register_v2(self, tool: BaseTool, version: int = 1, **kwargs):
        """注册带版本号的工具"""
        name = tool.name
        
        if name in self._tools:
            # 保存旧版本
            if name not in self._history:
                self._history[name] = []
            self._history[name].append(self._tools[name])
            
            print(f"[Registry] 工具 {name} v{self._versions[name]} → v{version}")
        
        self._versions[name] = version
        self.register(tool, **kwargs)
    
    def rollback(self, tool_name: str) -> bool:
        """回滚到上一个版本"""
        if tool_name not in self._history or not self._history[tool_name]:
            return False
        
        old_version = self._history[tool_name].pop()
        self._tools[tool_name] = old_version
        self._versions[tool_name] -= 1
        
        print(f"[Registry] {tool_name} 已回滚到 v{self._versions[tool_name]}")
        return True


# 热更新示例
registry = VersionedToolRegistry()

# 初始版本
registry.register_v2(search_tool_v1, version=1)

# ... 运行一段时间后发布新版本 ...
registry.register_v2(search_tool_v2, version=2)  # 自动替换

# 发现问题，快速回滚
if detect_regression():
    registry.rollback("search_web")  # 立即回滚到 v1
```

```python
class ToolMetadata(BaseModel):

    name: str
    category: str
    min_role: UserRole
    description: str
    version: int = 1
    call_count: int = 0
    avg_latency_ms: float = 0.0
    error_rate: float = 0.0


class EnterpriseToolRegistry:
    """企业级工具注册表"""
    
    def __init__(self):
        self._tools: Dict[str, Any] = {}
        self._metadata: Dict[str, ToolMetadata] = {}
    
    def register(self, tool, category: str, min_role: UserRole = UserRole.USER):
        """注册工具"""
        meta = ToolMetadata(
            name=tool.name,
            category=category,
            min_role=min_role,
            description=tool.description or "",

        role_level = role_order.index(role)
        
        allowed = []
        for name, meta in self._metadata.items():
            tool_level = role_order.index(meta.min_role)
            if role_level >= tool_level:
                allowed.append(self._tools[name])
        
        return allowed
    
    def get_metadata(self) -> Dict[str, dict]:
        """获取所有工具元信息"""

class EnterpriseAgentState(TypedDict):
    messages: Annotated[List[BaseMessage], add]
    user_role: str
    available_tools: List[str]
    error_log: List[str]
    execution_stats: Dict[str, Any]


async def llm_node(state: EnterpriseAgentState):
    """LLM 决策节点"""
    from langchain_openai import ChatOpenAI
    
    model = ChatOpenAI(model="gpt-4o-mini")
    
    system_prompt = f"""你是一个智能助手。

请根据用户需求选择合适的工具来帮助解决问题。"""

    return {"messages": [response]}


def route_after_llm(state: EnterpriseAgentState) -> str:
    """LLM 后的路由决策"""
    last_message = state["messages"][-1]
    
    if hasattr(last_message, 'tool_calls') and last_message.tool_calls:
        return "tools"
    return END


def log_error(state: EnterpriseAgentState, error_msg: str):
    """记录错误日志"""
    errors = state.get("error_log", [])
    errors.append(f"[{time.strftime('%H:%M:%S')}] {error_msg}")
    return {"error_log": errors}

    graph.add_edge("tools", "llm")  # 工具执行完回到 LLM
    
    return graph.compile()
```

## 本章小结

本章深入讲解了 LangGraph 中的**工具集成进阶**技术，这是构建生产级 Agent 的核心技能之一：

1. **ToolNode 深度剖析**：理解其内部工作流程（解析 tool_calls → 匹配工具 → 并行执行 → 包装结果），以及 `raise_on_error` 参数的选择策略。

2. **三层错误处理体系**：工具内部防御（参数验证 + try-catch）、ToolNode 级别容错（`raise_on_error=False` + 自定义重试）、图级别恢复策略（重试/降级/终止路由）。每层各司其职，共同保障稳定性。

3. **Injected Tool Arguments**：通过 `Annotated[T, InjectedToolArg]` 实现运行时参数自动注入，适用于用户身份、数据库连接、Store 实例等安全敏感或复杂对象的传递。

4. **大规模工具管理**：采用注册表模式（`ToolRegistry`）集中管理工具的注册、分类、权限控制和版本管理；优化工具描述以提升 LLM 的选择准确率。

5. **完整实战案例**展示了企业级工具集成系统：支持 4 种用户角色（Guest/User/Premium/Admin）、5 类工具、权限隔离、注入参数、结构化输出和调用统计。

掌握这些进阶技能后，你就能够构建出**稳定、安全、可扩展**的生产级 Agent 工具体系。
