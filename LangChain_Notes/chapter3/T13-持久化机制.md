# T13 - 持久化机制 (Persistence Mechanism)

## 1. 为什么 Agent 需要持久化？

在构建生产级 Agent 应用时，**状态持久化（State Persistence）** 是一个不可回避的核心问题。理解其必要性，需要从以下几个实际场景出发：

### 1.1 对话中断后恢复

用户在使用 Agent 时，可能会遇到以下情况导致对话中断：

- **浏览器意外刷新或关闭**：用户误操作或浏览器崩溃
- **网络波动**：移动端网络不稳定，WebSocket 连接断开
- **服务端重启**：部署更新或异常恢复

如果没有持久化机制，这些中断将导致：
- 所有上下文历史丢失
- 用户需要从头开始描述问题
- 体验严重下降，尤其是长对话场景

### 1.2 长时间运行的任务不能丢失进度

某些 Agent 任务可能涉及多轮工具调用和长时间执行：

```python
# 示例：一个复杂的数据分析任务可能运行数分钟
def long_running_analysis(query):
    # 第1步：搜索相关数据 (30s)
    # 第2步：下载并解析文件 (60s)
    # 第3步：执行多轮分析 (120s)
    # 第4步：生成报告 (30s)
    # 总耗时约4分钟
    pass
```

如果任务进行到第3步时服务重启，没有持久化意味着前两步的工作全部白费。

### 1.3 调试时需要回溯历史

开发和调试 Agent 时，能够回溯历史状态至关重要：

- **复现 Bug**：查看出错时的完整 State 快照
- **分析决策路径**：理解 LLM 在每一步为什么做出某个选择
- **性能优化**：识别哪些节点消耗最多时间
- **A/B 测试**：对比不同配置下的执行轨迹

### 1.4 多用户并发需要隔离各自的状态

在生产环境中，Agent 服务通常同时服务于多个用户：

```
User A ──→ Thread A (State A) ──→ 独立会话状态
User B ──→ Thread B (State B) ──→ 独立会话状态
User C ──→ Thread C (State C) ──→ 独立会话状态
```

持久化系统必须保证：
- **状态隔离**：用户 A 无法看到用户 B 的对话历史
- **并发安全**：同一用户的多次请求不会互相覆盖
- **资源可控**：每个 Thread 的存储开销可预测

## 2. LangGraph 持久化架构

LangGraph 提供了一套层次化的持久化架构，理解这个架构是正确使用持久化功能的前提：

### 2.1 架构总览

```
App (compiled graph)
 │
 ├── Checkpointer: 负责 State 快照的保存与加载
 │     ├── MemorySaver      (内存检查点)
 │     ├── SqliteSaver      (SQLite 检查点)
 │     └── PostgresSaver    (PostgreSQL 检查点)
 │
 ├── Store: 负责长期记忆的存取（跨会话）
 │     └── Namespace / Key-Value 存储
 │
 └── Thread: 一次对话执行的唯一标识符
       ├── thread_id: 标识一次完整对话
       └── checkpoint_id: 标识对话中的某个时间点
```

### 2.2 各组件职责

| 组件 | 职责 | 生命周期 | 存储内容 |
|------|------|----------|----------|
| **Checkpointer** | 管理 State 快照 | 由 App 持有 | 图中每个节点的完整 State |
| **Store** | 管理跨会话数据 | 由 App 持有 | 用户偏好、文档索引等长期数据 |
| **Thread** | 标识一次对话 | 由调用方指定 | 仅是一个标识符，不存储数据 |

### 2.3 数据流向

```
用户请求 (invoke/stream)
        │
        ▼
   ┌─────────┐
   │  App    │ ←── 从 Checkpointer 加载当前 State
   │  执行   │
   └────┬────┘
        │
        ▼
   节点执行完毕 → 新 State 生成
        │
        ▼
   Checkpointer 保存新 State 快照 (与 thread_id 关联)
        │
        ▼
   返回结果给用户
```

## 3. Thread（线程/会话）的概念

Thread 是 LangGraph 持久化体系中的核心概念之一，它代表了一次完整的对话会话。

### 3.1 Thread 的本质

Thread 是一个**逻辑上的会话标识符**，用于将同一次对话的所有状态变更关联起来：

```python
config = {"configurable": {"thread_id": "user_123_session_456"}}
```

关键特性：

| 特性 | 说明 |
|------|------|
| **唯一性** | 每个 thread_id 对应一组独立的状态历史 |
| **持久性** | 同一 thread_id 的调用可以跨越多次 invoke/stream |
| **隔离性** | 不同 thread_id 之间完全隔离，互不影响 |
| **可追溯** | 可以通过 thread_id 回溯该会话的任意历史快照 |

### 3.2 Thread ID 的生成策略

实际项目中，thread_id 的生成需要考虑以下策略：

**方案一：用户ID + 会话UUID**
```python
import uuid

def get_thread_id(user_id: str) -> str:
    """为每个用户每次新对话生成唯一 thread_id"""
    return f"{user_id}_{uuid.uuid4().hex[:8]}"
```

**方案二：基于业务实体的固定ID**
```python
def get_thread_id(order_id: str) -> str:
    """针对某个订单的持续跟进，使用订单ID作为 thread_id"""
    return f"order_{order_id}"
```

**方案三：匿名用户的临时ID**
```python
from datetime import datetime

def get_anonymous_thread_id() -> str:
    """匿名用户使用时间戳+随机数"""
    ts = datetime.now().strftime("%Y%m%d%H%M%S")
    rand = uuid.uuid4().hex[:6]
    return f"anon_{ts}_{rand}"
```

### 3.3 Thread 与 Checkpoint 的关系

一个 Thread 内部包含多个 Checkpoint（检查点），每个 Checkpoint 代表图执行过程中的一个时间点：

```
Thread: "t1"
│
├── Checkpoint 1: 初始 State (messages=[])
│   └── timestamp: T0
│
├── Checkpoint 2: 用户发送第一条消息后
│   └── timestamp: T1, messages=[user_msg, ai_response]
│
├── Checkpoint 3: 用户追问后
│   └── timestamp: T2, messages=[user_msg, ai_response, followup, ai_response2]
│
└── Checkpoint N: 最新状态
    └── timestamp: TN
```

这种设计支持**时间旅行（Time Travel）**功能——可以回到任意历史 Checkpoint 继续执行。

## 4. MemorySaver（内存检查点）

MemorySaver 是最简单的 Checkpoint 实现，适合开发测试阶段使用。

### 4.1 基础用法

```python
from langgraph.checkpoint.memory import MemorySaver
from langgraph.graph import StateGraph, MessagesState
from langchain_openai import ChatOpenAI

# 1. 创建 Checkpointer
checkpointer = MemorySaver()

# 2. 定义图结构
def chatbot(state: MessagesState):
    model = ChatOpenAI(model="gpt-4o-mini")
    return {"messages": [model.invoke(state["messages"])]}

graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.set_entry_point("chatbot")
graph.set_finish_point("chatbot")

# 3. 编译时传入 checkpointer
app = graph.compile(checkpointer=checkpointer)

# 4. 第一次调用 - 使用 thread_id "t1"
from langchain_core.messages import HumanMessage

msg1 = HumanMessage(content="你好，我叫小明")
res1 = app.invoke(
    {"messages": [msg1]},
    config={"configurable": {"thread_id": "t1"}}
)
print(res1["messages"][-1].content)
# 输出: 你好小明！很高兴认识你。

# 5. 第二次调用 - 相同 thread_id，可以看到历史
msg2 = HumanMessage(content="我叫什么名字？")
res2 = app.invoke(
    {"messages": [msg2]},
    config={"configurable": {"thread_id": "t1"}}
)
print(res2["messages"][-1].content)
# 输出: 你叫小明。（因为能看到第一次的对话历史！）
```

### 4.2 不同 Thread 完全隔离

```python
# 使用不同的 thread_id - 完全独立的会话
msg3 = HumanMessage(content="我叫什么名字？")
res3 = app.invoke(
    {"messages": [msg3]},
    config={"configurable": {"thread_id": "t2"}}  # 新的 thread_id
)
print(res3["messages"][-1].content)
# 输出: 我不知道你的名字，因为我们还没有聊过。
# （"t2" 是全新会话，看不到 "t1" 的任何历史）
```

### 4.3 查看历史状态

```python
# 获取某 Thread 的所有 Checkpoint
from langgraph.pregel import RetryPolicy

# 查看当前 Thread 的状态
state = app.get_state(config={"configurable": {"thread_id": "t1"}})
print(state.values)  # 当前的完整 State
print(state.next)    # 下一步要执行的节点（如果有）

# 获取历史 Checkpoint 列表
checkpoints = list(app.get_state_history(config={"configurable": {"thread_id": "t1"}}))
for cp in checkpoints:
    print(f"Checkpoint ID: {cp.config['configurable']['checkpoint_id']}")
    print(f"Messages count: {len(cp.values['messages'])}")
    print("---")
```

### 4.4 MemorySaver 的限制

| 限制项 | 影响 |
|--------|------|
| **进程内存储** | 服务重启后所有状态丢失 |
| **无持久化能力** | 不适合生产环境 |
| **内存占用随会话增长** | 大量并发时会消耗大量内存 |
| **单进程可用** | 无法在多个进程/机器间共享 |

## 5. SqliteSaver（SQLite 检查点）

SqliteSaver 将状态持久化到 SQLite 数据库文件，适合单机生产环境。

### 5.1 基础用法

```python
from langgraph.checkpoint.sqlite.aio import AsyncSqliteSaver
import asyncio

async def main():
    # 1. 创建 SQLite 检查点器
    checkpointer = AsyncSqliteSaver.from_conn_string("./checkpoints.db")

    # 2. 编译图（与之前相同）
    app = graph.compile(checkpointer=checkpointer)

    # 3. 异步调用
    config = {"configurable": {"thread_id": "sqlite_test"}}
    res = await app.ainvoke(
        {"messages": [HumanMessage(content="你好")]},
        config=config
    )
    print(res["messages"][-1].content)

asyncio.run(main())
```

### 5.2 同步版本

```python
from langgraph.checkpoint.sqlite import SqliteSaver

# 同步版本的 SqliteSaver
checkpointer = SqliteSaver.from_conn_string("./checkpoints.db")
app = graph.compile(checkpointer=checkpointer)

# 正常同步调用即可
res = app.invoke(
    {"messages": [HumanMessage(content="你好")]},
    config={"configurable": {"thread_id": "sync_test"}}
)
```

### 5.3 SQLite 文件结构

运行后会在当前目录生成 `checkpoints.db` 文件，内部表结构大致如下：

```sql
-- 主要存储 checkpoints 表
CREATE TABLE checkpoints (
    thread_id TEXT,
    checkpoint_id TEXT,
    parent_checkpoint_id TEXT,
    channel_values BLOB,      -- 序列化的 State 数据
    channel_versions BLOB,    -- 版本信息
    metadata BLOB,            -- 时间戳等元数据
    PRIMARY KEY (thread_id, checkpoint_id)
);

-- 存储 writes（增量更新记录）
CREATE TABLE checkpoint_writes (
    thread_id TEXT,
    checkpoint_id TEXT,
    task_id TEXT,
    channel TEXT,
    type TEXT,
    value BLOB,
    PRIMARY KEY (thread_id, checkpoint_id, task_id, channel)
);
```

### 5.4 适用场景

| 场景 | 是否适用 | 原因 |
|------|----------|------|
| 本地开发调试 | ✅ 推荐 | 无需外部依赖，零配置 |
| 单服务器生产环境 | ✅ 可用 | 轻量级持久化，足够可靠 |
| 低并发应用 | ✅ 可用 | SQLite 并发性能有限但够用 |
| 高并发生产环境 | ❌ 不推荐 | SQLite 写锁机制不适合高并发 |
| 分布式多实例 | ❌ 不支持 | SQLite 是文件级数据库，无法跨机器共享 |

## 6. PostgresSaver（PostgreSQL 检查点）

PostgresSaver 是企业级的持久化方案，适用于大规模生产部署。

### 6.1 基础用法

```python
from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver

# DATABASE_URL 格式:
# postgresql://user:password@host:port/database
DATABASE_URL = "postgresql://postgres:password@localhost:5432/langgraph_db"

async def setup():
    # 1. 创建检查点器
    checkpointer = AsyncPostgresSaver.from_conn_string(DATABASE_URL)

    # 2. 初始化数据库表（首次使用需要）
    await checkpointer.setup()

    # 3. 编译图
    app = graph.compile(checkpointer=checkpointer)

    # 4. 使用
    config = {"configurable": {"thread_id": "pg_test_001"}}
    res = await app.ainvoke(
        {"messages": [HumanMessage(content="你好")]},
        config=config
    )
    return res
```

### 6.2 Docker 快速部署 PostgreSQL

```yaml
# docker-compose.yml
version: '3.8'
services:
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: langgraph
      POSTGRES_PASSWORD: your_secure_password
      POSTGRES_DB: langgraph_checkpoints
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U langgraph"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  pgdata:
```

启动命令：
```bash
docker-compose up -d
```

### 6.3 连接池配置

对于高并发场景，建议配置连接池：

```python
from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver
import asyncpg

async def create_pooled_checkpointer():
    pool = await asyncpg.create_pool(
        DATABASE_URL,
        min_size=5,           # 最小连接数
        max_size=20,          # 最大连接数
        command_timeout=60,   # 命令超时时间(秒)
    )

    checkpointer = AsyncPostgresSaver.from_conn_string(DATABASE_URL)
    # 或者直接使用 pool 进行更精细的控制
    await checkpointer.setup()
    return checkpointer
```

### 6.4 PostgreSQL vs SQLite 对比

| 维度 | SQLite | PostgreSQL |
|------|--------|------------|
| **部署复杂度** | 零配置，单文件 | 需要 DB 服务 |
| **并发模型** | 文件级写锁 | MVCC，读写不阻塞 |
| **横向扩展** | 不支持 | 支持读写分离、分片 |
| **数据量上限** | TB 级（但不推荐高并发） | PB 级 |
| **备份恢复** | 复制文件即可 | WAL 归档、流复制 |
| **监控生态** | 基础 | 丰富（pg_stat 等） |
| **适用规模** | 单机、低并发 | 企业级、高并发 |

## 7. 持久化方案选型指南

### 7.1 选型决策表

| 方案 | 优点 | 缺点 | 适用场景 | 推荐指数 |
|------|------|------|----------|----------|
| **MemorySaver** | 零依赖、最快速度、最简配置 | 重启丢失、内存占用大 | 开发/测试/原型验证 | ★★★★★ (开发期) |
| **SqliteSaver** | 轻量持久化、无需外部服务、单文件备份 | 单机限制、写入并发受限 | 单机生产/中小型项目 | ★★★★☆ |
| **PostgresSaver** | 企业级可靠性、高并发支持、可扩展 | 需要额外基础设施、运维成本 | 大规模生产/分布式系统 | ★★★★★ (生产期) |

### 7.2 选型流程图

```
开始选择持久化方案
        │
        ▼
   当前是什么环境？
        │
   ┌────┴────┐
   │         │
 开发/测试  生产环境
   │         │
   ▼         ▼
MemorySaver  是否需要多实例？
              │
         ┌────┴────┐
         │         │
       单实例    多实例/高并发
         │         │
         ▼         ▼
    SqliteSaver  PostgresSaver
```

### 7.3 生产环境推荐配置

```python
# production_config.py
import os
from langgraph.checkpoint.postgres.aio import AsyncPostgresSaver

def get_checkpointer():
    """
    生产环境 Checkpointer 工厂函数
    根据环境变量自动选择合适的实现
    """
    env = os.getenv("ENVIRONMENT", "development")

    if env == "development":
        from langgraph.checkpoint.memory import MemorySaver
        return MemorySaver()

    elif env == "staging":
        from langgraph.checkpoint.sqlite.aio import AsyncSqliteSaver
        return AsyncSqliteSaver.from_conn_string("./checkpoints.db")

    elif env == "production":
        db_url = os.getenv("DATABASE_URL")
        if not db_url:
            raise ValueError("DATABASE_URL environment variable is required in production")
        return AsyncPostgresSaver.from_conn_string(db_url)

    else:
        raise ValueError(f"Unknown environment: {env}")
```

## 8. 高级主题

### 8.1 时间旅行（Time Travel）

LangGraph 的持久化机制不仅支持状态恢复，还支持**时间旅行**——回到任意历史节点继续执行：

```python
# 获取历史 checkpoint 列表
checkpoints = list(app.get_state_history(
    config={"configurable": {"thread_id": "t1"}}
))

# 假设我们想回到第2个 checkpoint（用户发完第一条消息后）
target_checkpoint = checkpoints[2]  # 从最新的往前数

# 用该 checkpoint 的 config 作为起点重新执行
new_result = app.invoke(
    {"messages": [HumanMessage(content="换个方式回答"))},
    config=target_checkpoint.config  # 使用历史 checkpoint 的配置
)
# 这会从那个时间点的状态开始，而不是最新状态！
```

### 8.2 状态分支与 Fork

可以基于某个历史 Checkpoint 创建新的分支：

```python
# 从历史 checkpoint fork 出一个新的 thread
historical_config = checkpoints[3].config

# 修改 thread_id 创建新分支
forked_config = {
    "configurable": {
        "thread_id": "t1_branch_v2",  # 新的 thread_id
        "parent_checkpoint_id": historical_config["configurable"]["checkpoint_id"]
    }
}

# 这个调用会从历史状态开始，但写入新的 thread
result = app.invoke(
    {"messages": [HumanMessage(content="探索另一种解决方案")]},
    config=forked_config
)
```

### 8.3 自定义 Checkpointer 接口

如果内置方案不能满足需求，可以实现自定义 Checkpointer：

```python
from langgraph.checkpoint.base import BaseCheckpointSaver, Checkpoint, CheckpointMetadata
from typing import Optional, Iterator

class CustomCheckpointer(BaseCheckpointSaver):
    """自定义 Checkpointer 示例（如对接 Redis）"""

    def __init__(self, redis_client):
        self.redis = redis_client

    async def aget(self, config, ...) -> Optional[Checkpoint]:
        # 从 Redis 读取 checkpoint
        key = f"checkpoint:{config['configurable']['thread_id']}"
        data = await self.redis.get(key)
        if data:
            return Checkpoint.parse_raw(data)
        return None

    async def aput(self, config, checkpoint, metadata, ...) -> dict:
        # 写入 Redis
        key = f"checkpoint:{config['configurable']['thread_id']}"
        await self.redis.set(key, checkpoint.json(), ex=86400)  # 24小时过期
        return {"configurable": {"checkpoint_id": checkpoint.id}}

    # ... 其他必需方法
```

## 本章小结

本章深入讲解了 LangGraph 的持久化机制，这是构建生产级 Agent 应用的基石。核心要点包括：

1. **持久化的必要性**：应对中断恢复、长任务保护、调试追溯、多用户隔离四大需求
2. **架构三要素**：Checkpointer（状态快照）、Store（长期记忆）、Thread（会话标识）各司其职
3. **三种 Checkpoint 方案**：MemorySaver（开发）、SqliteSaver（单机生产）、PostgresSaver（分布式生产）按需选型
4. **Thread 概念**：通过 thread_id 实现会话隔离与状态关联，支持时间旅行与状态分支等高级功能

掌握持久化机制后，Agent 应用才能从原型走向真正的生产级系统。
