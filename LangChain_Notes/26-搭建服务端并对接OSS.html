1 FastAPI 后端项目初始化

FastAPI 是 Python 生态中最现代化的异步 Web 框架，原生支持 OpenAPI 文档自动生成、类型校验、异步请求处理。我们用它来包装 AI 私厨 Agent：

Python — app/main.py 
# ============================================
# AI 私厨 — FastAPI 主入口
# ============================================

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from contextlib import asynccontextmanager

# === 生命周期管理 ===
@asynccontextmanager
async def lifespan(app: FastAPI):
    """应用启动/关闭时的生命周期钩子"""
    # 启动时：加载 Agent、预热模型、连接数据库
    print("⚡ AI Personal Chef starting up...")
    yield
    # 关闭时：释放资源、保存状态
    print("🚮 AI Personal Chef shutting down...")

# === 创建 FastAPI 实例 ===
app = FastAPI(
    title="AI Personal Chef",
    description="基于 LangChain 的智能菜谱推荐助手 API",
    version="1.0.0",
    lifespan=lifespan,
)

# === CORS 跨域配置 ===
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000", "http://127.0.0.1:5173"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

# === 健康检查端点 ===
@app.get("/health")
async def health_check():
    return {"status": "healthy", "service": "ai-personal-chef"}

# === 注册路由 ===
from app.api.v1 import chat, oss
app.include_router(chat.router, prefix="/api/v1")
app.include_router(oss.router, prefix="/api/v1")
💡

为什么选择 FastAPI？

性能：基于 Starlette + Pydantic，异步性能接近 Go/Nginx。
开发效率：自动生成 Swagger UI（/docs），前端联调零成本。
类型安全：Pydantic v2 自动请求验证，减少 80% 的参数校验代码。

2 RESTful API 接口设计

AI 私厨的核心 API 设计遵循 RESTful 规范。以下是完整的端点清单：

POST /api/v1/chat 发送消息给 Agent，获取流式响应
POST /api/v1/upload 上传食材图片到 OSS，返回 URL
GET /api/v1/history/{session_id} 获取指定会话的历史记录
GET /api/v1/recipes/{query} 直接搜索菜谱（无需 Agent）
Python — app/api/v1/chat.py 
# ============================================
# Chat 接口 — Agent 核心交互入口

from pydantic import BaseModel
from typing import Optional

3 阿里云 OSS 对象存储对接

用户上传的食材图片需要持久化存储。OSS（Object Storage Service）是阿里云提供的海量、安全、低成本的对象存储方案：

Python — app/api/v1/oss.py 
# ============================================
# OSS 图片上传服务
# ============================================

import os
import uuid
import base64
from datetime import datetime
from fastapi import APIRouter, UploadFile, File, HTTPException
import oss2

router = APIRouter()

# === OSS 配置（从环境变量读取）===
OSS_CONFIG = {
    'endpoint': os.getenv('OSS_ENDPOINT'),
    'access_key_id': os.getenv('OSS_ACCESS_KEY_ID'),
    'access_key_secret': os.getenv('OSS_ACCESS_KEY_SECRET'),
    'bucket_name': os.getenv('OSS_BUCKET_NAME', 'ai-chef-images'),
}

def get_oss_client() -> oss2.Bucket:
    """获取 OSS Bucket 客户端实例"""
    auth = oss2.Auth(OSS_CONFIG['access_key_id'], 
                       OSS_CONFIG['access_key_secret'])
    return oss2.Bucket(auth, OSS_CONFIG['endpoint'], 
                       OSS_CONFIG['bucket_name'])

# === 允许的文件类型 ===
ALLOWED_EXTENSIONS = {'.jpg', '.jpeg', '.png', '.webp'}
MAX_FILE_SIZE = 10 * 1024 * 1024  # 10MB

@router.post("/upload")
async def upload_image(file: UploadFile = File(...)):
    """
    上传食材图片到 OSS。
    
    流程：校验格式 -> 读取文件 -> 生成唯一路径 -> 上传 OSS -> 返回公开访问 URL
    """
    # 1. 校验文件扩展名
    ext = os.path.splitext(file.filename)[1].lower()
    if ext not in ALLOWED_EXTENSIONS:
        raise HTTPException(
            status_code=400,
            detail=f"不支持的文件格式: {ext}。仅支持 jpg/png/webp"
        )
    
    # 2. 校验文件大小
    content = await file.read()
    if len(content) > MAX_FILE_SIZE:
        raise HTTPException(
            status_code=400,
            detail=f"文件过大: {len(content)/1024/1024:.1f}MB，上限 10MB"
        )
    
    # 3. 生成唯一文件路径
    date_path = datetime.now().strftime("%Y/%m/%d")
    file_name = f"{uuid.uuid4().hex[:12]}{ext}"
    object_key = f"uploads/{date_path}/{file_name}"
    
    # 4. 上传到 OSS
    bucket = get_oss_client()
    bucket.put_object(object_key, content)
    
    # 5. 构建公开访问 URL
    url = f"https://{OSS_CONFIG['bucket_name']}.{OSS_CONFIG['endpoint'].replace('https://','')}/{object_key}"
    
    return {
        "url": url,
        "key": object_key,
        "size": f"{len(content)/1024:.1f}KB",
        "filename": file_name,
    }

⚠️

安全注意事项

1. AccessKey 绝对不能硬编码 —— 必须通过环境变量或 KMS 管理
2. 开启 Bucket 策略限制 —— 仅允许特定来源上传
3. 生产环境建议使用 STS 临时凭证 而非长期 AccessKey
4. 设置合理的 文件大小和类型白名单防止恶意上传

4 前后端联调与 SSE 流式输出

AI Agent 的推理过程可能耗时较长（2~5秒）。为了提升用户体验，我们采用 SSE（Server-Sent Events） 实现流式输出，让用户能实时看到 Agent 的思考过程：

Python — SSE 流式响应实现 
# ============================================
# SSE 流式输出 — 让用户实时看到 Agent 思考过程
# ============================================

from fastapi.responses import StreamingResponse
import json

@router.post("/chat/stream")
async def chat_stream(req: ChatRequest):
    """
    SSE 流式聊天接口。
    返回 text/event-stream 格式的数据，
    前端可逐块接收并渲染。
    """
    
    async def generate():
        # 发送连接建立事件
        yield f"data: {json.dumps({'type': 'connected'})}\n\n"
        
        # 模拟 Agent 的逐步输出（实际替换为真实 Agent 调用）
        steps = [
            {"type": "thinking", "content": "正在识别食材..."},
            {"type": "tool_call", "content": "调用 Tavily 搜索菜谱..."},
            {"type": "thinking", "content": "分析营养价值和难度..."},
            {"type": "result", "content": "推荐：番茄炒蛋 🍽"},
        ]
        
        for step in steps:
            import asyncio
            await asyncio.sleep(0.8)  # 模拟延迟
            yield f"data: {json.dumps(step)}\n\n"
        
        # 发送结束事件
        yield f"data: {json.dumps({'type': 'done'})}\n\n"
    
    return StreamingResponse(
        generate(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no",
        },
    )
事件类型 触发时机 前端行为
connected SSE 连接建立时 显示加载动画
thinking Agent 推理过程中 展示「正在思考...」提示
tool_call 调用外部工具时 展示工具名称和进度
result 最终结果返回 渲染回复内容和推荐卡片
done 全部输出完毕 隐藏加载状态，启用输入框

5 Docker 容器化部署

将 FastAPI 应用打包为 Docker 镜像，实现「一次构建，到处运行」的一致性部署体验：

Dockerfile 
# ============================================
# AI Personal Chef — Docker 多阶段构建
# ============================================

# Stage 1: 构建阶段 — 安装依赖
FROM python:3.11-slim AS builder

WORKDIR /app
COPY pyproject.toml .
RUN pip install --no-cache-dir -e .

# Stage 2: 运行阶段 — 最小化镜像
FROM python:3.11-slim

WORKDIR /app

# 从构建阶段复制已安装的包
COPY --from=builder /usr/local/lib/python3.11/site-packages \
     /usr/local/lib/python3.11/site-packages

# 复制应用代码
COPY app/ ./app/
COPY .env.example .env

# 创建非 root 用户运行（安全最佳实践）
RUN useradd -m -u 1000 appuser && chown -R appuser:appuser /app
USER appuser

# 暴露端口
EXPOSE 8000

# 健康检查
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')" || exit 1

# 启动命令（uvicorn ASGI 服务器）
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "2"]

  1. 构建镜像

    docker build -t ai-personal-chef:v1.0 .

  2. 本地测试运行

    docker run -p 8000:8000 --env-file .env ai-personal-chef:v1.0

  3. 访问文档

    浏览器打开 http://localhost:8000/docs 查看 Swagger UI

  4. 推送到仓库

    docker tag && docker push registry.cn-hangzhou.aliyuncs.com/xxx/chef:v1.0

✅

Docker 最佳实践总结

多阶段构建：最终镜像不包含 pip/build 工具，体积缩小约 60%。
非 root 用户：避免容器逃逸带来的宿主机权限风险。
Healthcheck：让编排系统（K8s/Docker Compose）能自动重启异常容器。
