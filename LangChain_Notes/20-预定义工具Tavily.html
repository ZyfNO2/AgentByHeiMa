Tavily 搜索引擎介绍

专为 AI Agent 设计的搜索 API

Tavily 是一款专门为 AI 应用程序和 LLM Agent 设计的搜索引擎 API。与传统搜索引擎不同，Tavily 的核心设计理念是：返回结构化、高质量、可直接被 LLM 理解的搜索结果。

*
为什么选择 Tavily 而非传统搜索？
传统搜索引擎返回的是 HTML 页面，包含大量噪声（广告、导航栏、脚本等）。Tavily 返回经过清洗的结构化数据：标题 + 摘要 + URL + 内容片段，这正是 LLM 所需的理想输入格式。此外，Tavily 针对 AI 场景优化了结果排序逻辑。

Tavily 核心特性

  • AI 原生结果格式 — 返回 JSON 格式的结构化数据，无需额外解析 HTML
  • 内容提取与摘要 — 自动提取页面核心内容并生成摘要
  • 实时网络搜索 — 覆盖全网最新信息，非静态知识库
  • 免费额度充足 — 注册即获每月 1000 次免费 API 调用
  • LangChain 官方集成 — 一行代码即可接入 Agent 工具链
  • 支持高级查询 — 可指定搜索深度、结果数量、主题过滤等

TavilySearchResults 工具使用

安装、初始化与参数配置详解

LangChain 提供了 TavilySearchResults 作为预定义工具类，封装了所有 Tavily API 调用细节，让开发者只需关注业务逻辑而非底层 HTTP 交互。

Step 1: 安装依赖

Bash 
# 安装 Tavily Python SDK 和 LangChain 社区集成包
pip install tavily-python langchain-community

# 验证安装成功
python -c "from langchain_community.tools.tavily_search import TavilySearchResults; print('OK')"

Step 2: 初始化工具

Python 
import os
from langchain_community.tools.tavily_search import TavilySearchResults

# 配置 API Key（也可通过环境变量自动读取）
os.environ["TAVILY_API_KEY"] = "tvly-your-key-here"

# 创建搜索工具实例
search = TavilySearchResults(
    max_results=5,          # 返回最大结果数量
    search_depth="basic",     # 搜索深度: "basic" 或 "advanced"
    include_answer=True,       # 是否在结果中包含 AI 生成的答案摘要
    include_raw_content=False, # 是否包含原始页面内容（Token 消耗大）
    include_images=False      # 是否返回图片链接
)

# 直接调用测试
results = search.invoke("Python LangChain 最新版本")
print(results)

关键参数详解

参数 类型 默认值 说明
max_results int 5 返回的最大搜索结果条数，建议 3-10 之间以控制 Token 消耗
search_depth str "basic" "basic" 快速搜索（推荐）；"advanced" 深度搜索，更全面但更慢
include_answer bool True 是否让 Tavily AI 直接生成问题答案摘要，对简单事实查询非常有效
include_raw_content bool False 是否包含页面原始文本内容，开启后 Token 消耗显著增加
include_images bool False 是否在结果中返回相关图片 URL
name str "tavily_search_results_json" 工具名称，Agent 通过此名称识别和调用该工具
description str 默认描述 工具功能描述，决定 Agent 何时选择调用此工具

工具组合策略

多工具 Agent 编排实战

单个工具的能力有限，真正的强大来自多工具协同工作。LangChain 的 Agent 架构天然支持将多个工具绑定到一个 Agent 上，由 LLM 自主决定何时调用哪个工具。

多工具 Agent 执行流程
User Query
→
LLM Reasoning
→
Tool Selection
→
Execute Tool
→
Synthesize Answer

完整示例：搜索 + 计算组合 Agent

Python 
from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_community.tools.tavily_search import TavilySearchResults
from langchain_core.tools import tool
import os

# ========== 1. 初始化 LLM ==========-
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# ========== 2. 定义工具集 ==========-

# 工具 A: Tavily 搜索
search = TavilySearchResults(max_results=3)

# 工具 B: 自定义计算器（使用 @tool 装饰器）
@tool
def calculator(expression: str) -> str:
    """计算数学表达式的值。仅用于基础算术运算。"""
    try:
        result = eval(expression)
        return f"计算结果: {result}"
    except Exception as e:
        return f"计算错误: {e}"

# ========== 3. 组装 Agent ==========-
tools = [search, calculator]

agent = create_tool_calling_agent(llm, tools, prompt=None)
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,
    handle_parsing_errors=True
)

# ========== 4. 测试运行 ==========-

# 场景1: 需要搜索信息
response1 = agent_executor.invoke({
    "input": "2024年巴黎奥运会中国代表团获得了多少枚金牌？"
})

# 场景2: 需要计算
response2 = agent_executor.invoke({
    "input": "如果每枚金牌奖励50万元，总奖金是多少？"
})

# 场景3: 搜索 + 计算 组合
response3 = agent_executor.invoke({
    "input": "帮我查一下当前比特币价格，然后计算如果我有0.5个BTC值多少美元"
})

Agent 如何选择工具？
Agent 的工具选择完全依赖 LLM 的推理能力。每个工具的 description 参数是关键 — 它相当于给 LLM 写了一份"工具说明书"。描述写得越准确，LLM 选择正确工具的概率越高。这就是为什么自定义工具时 description 的撰写质量直接决定 Agent 表现。

工具编排的核心原则

职责单一
每个工具只做一件事，避免"万能工具"导致 LLM 选择困难
描述精准
description 要明确说明适用场景和不适用的边界条件
数量适度
同一 Agent 绑定 3-7 个工具为宜，过多会降低选择准确性
互补覆盖
工具之间能力应互补而非重叠，形成完整的技能矩阵

实际搜索场景演示

从零构建一个智能研究助手

下面我们用一个完整的实际案例来展示 Tavily 搜索工具在真实项目中的运用方式——构建一个技术调研助手，能够自主搜索、汇总并输出研究报告。

Python 
from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain_community.tools.tavily_search import TavilySearchResults
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
import json

# === 初始化 ===
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# === 定义搜索工具（带自定义描述）===
tech_search = TavilySearchResults(
    max_results=5,
    name="tech_research_search",
    description=(
        "用于搜索最新的技术资讯、框架更新、编程语言特性、"
        "开源项目动态等信息。当用户询问技术趋势、版本发布、"
        "框架对比或需要最新资料时使用此工具。"
    )
)

news_search = TavilySearchResults(
    max_results=5,
    name="news_search",
    description=(
        "用于搜索时事新闻、行业动态、政策变化等新闻类信息。"
        "当用户询问最近发生的新闻事件、市场动态时使用此工具。"
    )
)

# === 构建 Prompt 模板 ===
prompt = ChatPromptTemplate.from_messages([
    ("system", """
你是一位专业的技术研究助手。你的任务是：
1. 根据用户的问题，主动使用搜索工具获取最新信息
2. 对搜索结果进行分析和整理
3. 输出结构清晰、有据可查的研究报告

报告要求：
- 使用 Markdown 格式
- 包含信息来源引用
- 区分事实陈述和个人分析
- 如信息不足，明确指出
"""),
    MessagesPlaceholder(variable_name="chat_history"),
    ("human", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])

# === 创建 Agent ===
tools = [tech_search, news_search]
agent = create_tool_calling_agent(llm, tools, prompt)
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,
    max_iterations=5,         # 最大迭代次数防止死循环
    handle_parsing_errors=True
)

# === 运行测试 ===
result = agent_executor.invoke({
    "input": (
        "请帮我调研一下 2024 年大模型领域的重要进展，"
        "重点关注开源模型和 Agent 框架的发展"
    ),
    "chat_history": []
})

print(result["output"])
+
为什么用两个搜索实例而非一个？
虽然底层都是 Tavily API，但通过不同的 name 和 description，可以让 Agent 更精准地判断该用哪个入口。技术搜索可以指定 topic 过滤为 tech，新闻搜索可以用 news topic。这种"同源异构"的工具设计模式在实际项目中非常常见。

自定义工具 vs 预定义工具

选择标准与决策指南

上一集学习了如何用 @tool 装饰器创建自定义工具，本集又介绍了丰富的预定义工具生态。那么在实际项目中该如何选择？以下决策框架帮助你做出最优判断。

维度 预定义工具 自定义工具 (@tool)
开发速度 极快，导入即用 需编写函数体和文档字符串
灵活性 受限于官方提供的参数 完全可控，任意定制逻辑
维护成本 社区维护，跟随版本升级 自行负责 Bug 修复和迭代
依赖风险 引入第三方包依赖 无额外依赖
适用场景 通用能力（搜索、计算、知识库） 业务特有逻辑（内部 API、私有数据）
API Key 通常需要第三方服务密钥 取决于具体实现
错误处理 已内置标准异常处理 需自行实现 try-except
典型代表 Tavily、Wikipedia、Calculator 企业内部 CRM 查询、自有算法服务

混合策略（推荐）
在实际项目中，最佳实践是混合使用：用预定义工具覆盖通用能力（搜索、计算），用自定义工具封装业务逻辑（数据库查询、内部 API）。这种组合既保证了开发效率，又不失灵活性。
