大模型应用全景

系统梳理 LLM 应用的五大范式，理解 RAG 与 Agent 的核心概念，掌握从 Prompt Engineering 到 Orchestration 的完整技术选型体系。

时长 12:33 基础篇 应用范式

1 LLM 应用的五大范式

大语言模型（LLM）的应用场景极为广泛，但归根结底可以归纳为五种核心范式。每种范式代表了人与 AI 交互的一种基本模式，从最简单的对话到最复杂的自主推理，构成了 LLM 应用的完整能力光谱。

01
💬
对话聊天
Chatbot / Conversational AI
最基础也最常见的 LLM 应用形式。用户发送消息，模型生成回复，形成多轮对话交互。是所有高级应用的地基。
典型产品：ChatGPT、Claude、智能客服、虚拟助手、陪伴型聊天机器人
02
📝
文本处理
Text Processing & Transformation
将输入文本按照指定规则进行转换。包括摘要提取、语言翻译、风格改写、语法润色等「输入→输出」的文本变换任务。
典型产品：DeepL 翻译、Grammarly、Notion AI 摘要、Jasper 写作助手
03
📊
信息提取
Information Extraction (IE)
从非结构化或半结构化文本中抽取出结构化数据。将自由文本转化为 JSON/表格/数据库记录等机器可读格式。
典型产品：简历解析器、发票 OCR 提取、合同关键条款抽取、医疗病历结构化
04
✏️
内容生成
Content Generation
基于指令或上下文从头创建新内容。涵盖文章写作、代码生成、创意文案、营销素材、甚至音乐/图像的多模态创作。
典型产品：GitHub Copilot、Midjourney 文案、Sora 视频脚本、AI 小说创作
05
🧠
复杂推理
Complex Reasoning & Decision Support
LLM 最具挑战性的应用范式。需要多步逻辑推理、数学运算、因果分析、方案评估与决策建议，通常结合 Chain-of-Thought 技术。
典型产品：AlphaGeometry（数学证明）、法律文书分析、科研假设验证、战略咨询顾问
🌟
范式演进规律：这五种范式并非彼此孤立——实际产品往往是多种范式的组合叠加。例如一个智能客服系统 = 对话聊天 + 信息提取 + 复杂推理；一个代码辅助工具 = 内容生成 + 复杂推理 + 对话聊天。LangChain 的核心价值正是为这种跨范式的组合提供了统一的编排框架。

2 RAG：检索增强生成

在深入 Agent 之前，我们必须先理解 RAG（Retrieval-Augmented Generation，检索增强生成）这一关键技术概念。它是连接「纯 LLM」与「实用 AI 应用」之间的桥梁。

为什么纯 LLM 不够？

问题表现影响
知识过时模型的训练数据有截止日期（如 GPT-4 训练至 2023 年 4 月），无法知晓之后发生的事件回答关于最新事件的问题时产生错误或拒绝回答
私有数据缺失企业内部文档、个人笔记、私有数据库等内容从未进入训练集无法回答「我们公司上季度的销售额是多少？」这类问题
幻觉问题（Hallucination）模型会以极高的自信编造看似合理但完全虚假的信息在医疗、法律、金融等领域可能导致严重后果
可解释性差用户无法知道模型回答的依据来源是什么难以建立信任，尤其在专业领域应用中

RAG = 检索 + 生成的组合拳

🔍
RAG 核心流程：
• User Query（用户提问） → 用户提出问题
• Retrieval（检索阶段） → 从外部知识库（向量数据库/文档索引）中检索出与问题最相关的文档片段
• Augmentation（增强阶段） → 将检索到的文档片段作为上下文（Context）注入到 Prompt 中
• Generation（生成阶段） → LLM 基于增强后的 Prompt 生成准确、有据可查的回答
User Query
Input
用户提出自然语言问题
Retriever
Vector DB
语义检索相关文档片段
Context
Prompt
拼接检索结果到 Prompt
LLM Output
Answer
生成带引用依据的回答
✅
RAG 的核心优势：相比微调（Fine-tuning），RAG 具有部署成本低、知识更新快、可追溯来源、无需重新训练四大优势。对于大多数企业级问答和知识库场景，RAG 是首选方案。

3 Agent：智能体概念

如果说 RAG 解决的是「知道更多」的问题，那么 Agent 解决的就是「做得更多」的问题。Agent（智能体）是 LLM 应用领域最令人兴奋的前沿方向。

🤖
Agent 核心公式：
Agent = LLM + Tools + Memory + Planning

• LLM（大脑）：负责理解任务、制定计划、推理决策
• Tools（手脚）：搜索引擎、API 调用、数据库查询、代码执行等外部能力
• Memory（记忆）：短期记忆（当前对话上下文）+ 长期记忆（历史经验积累）
• Planning（规划）：将复杂目标拆解为子任务、动态调整执行策略

Agent vs 传统程序的核心区别

维度传统程序Agent
执行方式硬编码的 if-else 流程，每条路径预先确定自主规划步骤，根据中间结果动态调整策略
能力边界仅限于开发者预设的功能通过组合 Tools 可以应对未预见的任务类型
容错性遇到异常即崩溃或返回固定错误可以尝试替代方案、重试、换一种思路解决问题
交互模式命令式：用户告诉系统做什么声明式：用户描述目标，Agent 自主决定怎么做
🚀
ReAct 循环 —— Agent 的思考方式：
Thought（思考）→ Action（行动）→ Observation（观察）→ Thought（再思考）...

Agent 不是一次性给出答案，而是像人类一样：先想一下该用什么工具 → 调用工具获取结果 → 分析结果 → 决定下一步 → 直到完成任务。这个循环就是 LangChain 中 ReAct Agent 的核心机制。

4 实际应用场景案例

理论落地实践，以下是目前市场上最具代表性的五类 LLM 应用场景，每种都对应着不同的技术架构选择：

🔔
智能客服系统 多轮对话 + 知识库检索 + 意图识别，7×24 小时自动应答，降低人工客服 60% 以上工作量
📚
文档问答助手 上传 PDF/Word/Markdown，基于 RAG 实现精准文档检索与问答，支持引用溯源
💻
代码辅助编程 Copilot 类工具，理解代码上下文自动补全、生成函数、重构优化、Bug 修复建议
📈
数据分析助手 自然语言转 SQL/Python，自动生成图表，支持数据探索与洞察发现
🎨
创意内容生产 营销文案、社交媒体帖子、SEO 文章批量生成，配合人工审核提升效率 10 倍+
💡
场景与技术映射：智能客服 ≈ 对话 + RAG；文档问答 ≈ 纯 RAG；代码辅助 ≈ 内容生成 + 复杂推理；数据分析 ≈ 信息提取 + 复杂推理；创意生产 ≈ 内容生成 + 文本处理。理解你的场景属于哪种范式组合，是技术选型的第一步。

5 LLM App 开发技术栈概览

构建一个完整的 LLM 应用，需要在多个层次上进行技术选型。下图展示了从底层基础设施到上层应用的四层技术栈：

Orchestration 层
LangGraph / Dify
工作流编排、状态管理、多 Agent 协作、人机交互循环
Framework 层
LangChain / LlamaIndex
组件抽象、链式调用、RAG 管道、Agent 构建
Prompt Engineering 层
Templates / CoT
提示词模板设计、Few-shot 示例、输出格式约束
Infrastructure 层
Vector DB / Rerank
向量数据库、Embedding 模型、重排序、缓存层
层级核心职责主流选项
Prompt Engineering 设计高质量提示词，引导 LLM 输出符合期望的结果 ChatPromptTemplate、System Prompt 设计、Few-shot Learning、Chain-of-Thought
Framework 提供统一的组件抽象和应用构建框架 LangChain（生态最全）、LlamaIndex（RAG 专精）、CrewAI（多 Agent）
Orchestration 复杂工作流的状态管理与步骤编排 LangGraph（图状态机）、Dify（低代码平台）、AutoGen（多 Agent 对话）
Infrastructure 支撑上层应用的底层数据与服务设施 向量库（Pinecone/Milvus/FAISS）、Embedding（OpenAI/BGE）、Rerank（Cohere/bge-reranker）、缓存（Redis）
💪
本课程的技术路线：我们将自顶向下地覆盖这四个层次——从 Prompt Engineering 入手，逐步深入 LangChain Framework，最终用 LangGraph 编排完整的 Agent 工作流。每一层都会提供动手实践的代码示例。
